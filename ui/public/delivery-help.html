返回条目交付 · 帮助中心

交付导航与条目详情

左侧“需求条目”按同一项目、来源及条目展示最新采集版本，支持项目、编号或标题、来源差异筛选。详情提供交付概览、工单与执行、需求分析、交付物与核验，来源与历史单独收纳。来源业务状态、平台任务与运行状态、正式核验状态分别展示。分析与接入 Jira 工单入口保留项目和返回条目；创建分析时预填条目号，创建不等于授权执行。

左侧“我的工作台”处理日常待办，“工单管理”接入与派发具体任务，“交付报表”汇总任务和效果；项目、席位与执行记录归入资源。正式验收仍在轻舟或 Jira 的正式流程中进行。

适用场景

组长以轻舟条目统筹多个 Jira 主需求及研发、测试子工单，核对排期与实际工单范围。当前版本支持管理员在线读取或手工导入快照、成员查看，不会创建或启动 Agent 执行任务。

在线读取场景

管理员配置轻舟账号、项目 Jira 服务地址和 PAT，读取并选择排期组织。项目来源连接不绑定执行席位，派单时另选席位。PAT 加密保存，不回显；旧配置保存一次后复制为项目独立凭据，不修改原席位配置。

  1. 点击“保存并查看组织条目”，自动进入月度列表，切换月份自动读取。月份以轻舟排期为准，不按创建日期；列表只展示月度排期，不包含完整未排期需求。
  2. 账号、密码及 PAT 留空可保留已有凭据；变更 Jira 服务地址时需重新填写 PAT。
  3. 补录已知条目或核对跨月计划时，打开“来源与历史 → 更多操作 → 补录指定条目”，填写条目号和涉及的月份。
  4. 单条补录中的“读取并核对”不保存快照，“同步只读版本”保存来源版本。来源查询及同步均不会自动派单。
  5. 读取失败时按提示核对认证与网络；配置或凭据读取期间发生变化时须重新查询。

手工导入操作步骤

  1. 进入“左侧“需求条目” → 接入／同步条目”或“Jira 工单执行 → 返回需求条目”，选择平台项目。
  2. 管理员选择“导入条目快照”，上传 JSON 文件。应从已获授权的只读来源导出，不要上传 Cookie、Token 或密码。
  3. 点击“预览并核对”，核对条目、主子工单、经办人和差异；跨月份相同排期步骤只计算一次。
  4. 确认后“保存只读纳管”。相同来源内容重复导入不产生重复版本。来源变化请导入新版本；历史版本仍保留。

快照封装格式

所有原始响应必须保持原文字符串，不能先解析再序列化长整数。采集时间为实际导出时间（ISO 8601）。平台保存标准化结果和来源内容摘要，不保存原始正文、浏览器会话或附件内容。

{
  "format": "zhiyan-delivery-snapshot-v1",
  "sourceOrigin": "https://proj.fingard.com:1888",
  "demandNo": "ATS3-00156",
  "collectedAt": "实际采集时间，如 2026-10-25T08:00:00Z",
  "demandJson": "轻舟条目查询完整响应原文",
  "analysisJson": "轻舟条目分析及主工单清单响应原文",
  "scheduleJsons": ["轻舟排期树响应原文，可提供多月份"],
  "jiraJson": "Jira 完整查询响应原文，含 startAt=0、total 和 issues"
}

轻舟响应必须 success=true、code=0；条目查询 rows 和 total 必须一致。Jira 必须完整包含条目主单和所有真实子单，不得混入其他需求。文件上限 1.5 MB，超出时请联系管理员，不要删减数据来绕过完整性检查。

如何理解差异

  • 排期有、Jira 无：可能是快照缺失，不等于工单已删除。
  • Jira 有、排期无：需核对新增、作废或替代关系，平台不自动推定。
  • 作废 / 取消：保留真实工单身份，不作为可执行任务。
  • 多月份数据冲突、父子编号不匹配：拒绝导入，请核对来源后重试。

比较版本与记录核对说明

场景：排期或 Jira 工单发生变化，需要确认新增、移出、经办人、来源状态、父子关系及排期变化。先在“快照版本比较”选择基准版本，再选择同一项目、来源和条目的对比版本，点击“比较版本”。当前选择范围为快照列表所在页；可切换列表页查找历史版本。

表格按“基准 → 对比”显示变化。移出只表示不在该版本中，不代表工单被取消；没有规范化变化也不代表原始正文相同或正式交付已验收。手工与在线版本的采集方式变化会单独提示。

管理员可以填写“核对说明”并点击“记录核对说明”，记录对差异的解释与后续安排。审计包含两个版本及其指纹、记录人和说明，不覆盖快照，不代替正式评审、差异解决状态或执行授权。其他成员可比较版本。

运行治理与 Harness 路由

在“席位 → 设备与诊断 → 本机 Harness 能力”登记并选择分析、研发、测试套件。同领域一个套件自动选择，多个套件需由席位负责人或管理员指定。选择路由不代表授权派单，旧任务不会自动迁移目录。

在“执行记录”选择运行，可查看执行治理与用量对账。新版客户端展示许可监督、进程树停止证明、部分用量或最终对账。部分用量不是完整汇总；用量未知不等于零消耗。实际中转/订阅价格未提供时显示未计价，不保证零超支。

交付工作台与统计报表

入口：协同工作台 → “交付工作台与报表”，或席位统计 → “按项目、领域与负责人查看交付报表”。默认查看自己的席位和历史执行；管理员可切换组织范围及执行时负责人。项目、席位、领域和周期保存在网址中，便于返回和分享同一筛选。

  • 任务与过程：场景：检查手头任务、Agent 是否正在执行、等待人工或状态未知。业务状态与运行状态分别显示；阶段来自 Harness 上报，不推算完成百分比。“查看任务、对话与决策”进入原任务详情，仍按原会话权限查看正文。无会话、已知缺口、已收尾和正文过期分别展示。
  • 统计报表：场景：组长按日、周、月、季度、年查看交付量、运行用量和等待时间。上海时区，周一开周；当前在手是当前叶子任务数，首次开始/交付/取消来自本期已采集的不可变事实。历史运行按当时负责人及固定项目归属；旧运行缺少归属时不猜测。CSV 导出当前筛选的全部席位汇总，不包含对话正文或凭据。
  • 时间与用量：并行运行时间按同席位、负责人取并集，执行优先于等待。会话未知时间仅指受管会话内无有效证据的区间；席位离线和工作时段在线另见席位统计。项目/领域筛选下无法分配席位空闲。Token 来自所选期间的账本差额，最终回执、部分计量、未计价分别显示；已知费用单位为美元，未知不当作零。
  • 质量：展示交付后14天内 Jira 显式关联缺陷；发生率为出现关联缺陷的完整观测成熟工单数除以完整观测成熟工单数，同时展示全部成熟工单及覆盖率。它不是确认归因的编码 Bug 率。未成熟、缺少观测和确认归因未接入均明确提示。
  • 验收材料清单：场景：主需求负责人按项目核对某个来源版本的材料缺口。展开版本可查看范围、来源新鲜度、分析/设计/代码评审/构建环境/用例/测试/风险/Tracker/正式验收项目。当前只记录来源范围和缺口；正式证据未接入的项目保持待核验，不会自动判定可验收或关闭上游工单。

只有固定的运行路由可确定需求分析、研发、测试领域；没有固定路由的旧运行归为未分类。Tracker 领域工时和确认归因 Bug 率仍待接入。数据超过查询上限时整份报表报错，请缩小周期；不会返回静默截断的总数。

工单状态筛选

子工单安排区和主子工单树提供来源状态下拉筛选，选项来自来源实际数据，如已完成、已发版、待受理。可与关键词组合，保留匹配子单的主工单作为上下文。在待安排范围选择结束状态会自动切换全部子单。来源状态取自保存版本，可通过整月同步更新。

安排子工单执行

条目详情 → 工单与执行按主工单分组，默认只显示未接入平台、来源未结束的设计与编码子单。可切换已接入、来源已结束、全部子单并搜索。每行分别展示来源状态、排期、来源负责人及平台任务与运行状态。已接入的工单通过原任务处理对话、决策和恢复，不重复派发；来源已结束的工单不提供新派发按钮。测试及评审等其他类型可查看，不开放尚未实现的派发能力。来源状态是保存版本，必要时重新同步；来源未结束不代表通过开发准入，派发前仍核验最新状态及席位授权。

一键同步本月全部条目

月度排期点击“一键同步本月全部条目”，先读取当前项目所选月份的完整清单，再逐条同步轻舟与 Jira 的主子工单及来源版本。覆盖已纳管条目，不受搜索、筛选、分页或勾选 20 条限制。无变化复用已有版本，不派单、不启动 Agent、不修改上游工单。

查看成功、失败、未处理及逐条回执，可停止后续同步，并仅重试失败和未完成项。请保持页面打开；离开页面停止未发送的请求，当前请求可能仍保存，已保存结果保留。这是手动整月同步，不是后台自动同步。

月度条目筛选

需求条目 → 月度排期可组合筛选关键词、来源负责人（支持搜索）、来源状态、同步情况、开发准入和工单情况。筛选整月数据后再分页，显示匹配数量与总数量。查看详情后返回或刷新页面会保留条件；清除筛选保留项目和月份，切换项目会清除原项目的筛选。修改条件会清空批量选择，避免同步隐藏条目。来源未提供的信息可单独筛选；待核验不代表不允许开发，已登记核验也不代替派发前检查。

独立需求分析闭环

场景：需求还没有拆成 Jira 开发子单，需先由分析 Harness 澄清范围、整理证据并形成可交接的需求。入口：左侧“需求分析”，或“需求条目 → 条目详情 → 需求分析”。管理员选择项目、分析席位，填写诉求后创建记录；创建不会启动模型，再点击“授权并派发分析”。

  1. 席位负责人在本机登记分析套件：harness capability register --kind analysis --profile dsp --path 分析Harness目录。同领域多个套件时指定路由；旧客户端需先更新，并保持席位在线、桌面已登录。
  2. 平台沿用真实运行、执行许可和预算控制，本机在登记的分析 Harness 根目录打开可见 Claude；不需要虚构 Jira 工单或手动 start。原生任务目录按平台任务 ID 和修订固定，恢复不重新初始化。
  3. 网页展示 P0 接收、P1 证据、P2 分析、P3 质量评审、P4 交接的实际状态及门禁错误。业务问题在“待决定问题”答复，同一 Claude 会话领取后继续，无须 /exit。批准质量评审前，负责人必须在本机核对当前指纹对应的材料；输入变化后旧决定失效。本机工具权限确认仍在终端处理。
  4. 通过原生门禁后采集七项文件的名称和 SHA-256，单独记录输入与交接文档指纹。原始材料保留在本机，索引不等于可共享的交接包。网页对话只展示已采集内容，并继续受原任务的会话权限控制。
  5. 正式发布：先在 Jira 或轻舟按正式流程发布交接包并核验权限，再在网页登记正式链接、核验说明和精确版本。该登记明确为人工核验，平台尚不自动上传或回读正式发布，也不会自动派发研发单。
  6. 中断时先停止并核验旧进程，再“核验并恢复分析”；原任务与修订保持不变。交付冻结后修改需求须“建立新修订”，历史评审与发布记录不被覆盖。

网页普通答复、质量评审、正式发布是不同决定。质量评审不代替轻舟正式业务审签。离线、能力未登记、旧客户端、费用硬预算或旧进程未核验停止时会明确阻止启动；不要重复手工启动第二个 Claude。

免填路径登记分析或测试 Harness

席位详情 → 设备与诊断 → 本机 Harness 能力，选择套件用途并生成选目录命令。分析任务创建表单也提供入口。先更新对应电脑的客户端，再执行网页命令；系统弹出文件夹选择框，选择包含 CLAUDE.md 和技能的 Harness Git 根目录，检查通过后保存到该席位。路径无需手工填写，取消不修改登记；网页命令绑定席位，不可在另一台电脑误用。

同一席位可以同时登记研发、分析和测试；仅承接测试时才需要 QA Harness。登记测试能力不代表 QA 自动执行已经开放。无图形桌面电脑可继续使用 --path。登记成功后点击分析表单的“刷新席位登记”，保留已填写内容。

当前边界

手工快照不代表实时状态。持续定时同步、独立代码评审、条目自动交付已支持单主单下的串行分析、研发和 QA 衔接；正式评审和验收由真人核验，并行协调与自动关闭主单尚未开放。来源“已完成 / 已验收”不等于平台已核验交付证据。

条目自动交付最小闭环

进入“需求条目 → 条目详情 → 一键交付条目 → 配置并启动”。选择分析、研发、测试席位，指定已存在且未结束的设计、编码、测试用例编写、功能测试四张 Jira 子工单，提供测试环境和待测构建的正式准入说明链接，点击“启动条目自动交付”。这是本条目后续自动执行的初始授权。

设计和编码共用研发席位；用例和执行共用测试席位。同一台电脑可以登记多个领域 Harness，无需给席位增加固定职责类型。分析使用登记的 analysis 路由，设计／编码使用 development 路由，用例／执行使用 qa 路由，禁止跨领域替代。编码继续包含研发 Harness 内的代码评审。

人工问题在条目流程中答复，平台绑定问题指纹并续传同一 Claude 会话；普通答复不改写原生 Jira 审批，不替代正式审签。分析问题、P3 评审和正式发布沿用独立需求分析页面。设计和用例评审需先在正式流程完成，再在条目中登记结论链接和核验说明；此处明确标注为人工核验，未声称自动回读轻舟审签。
