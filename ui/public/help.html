快速入门

流程总览：从 Jira 指派到交付验收

用四条泳道看清谁负责、在哪里执行、遇到阻塞由谁处理，以及最终如何验收。

什么时候使用
  • 首次了解智研协同平台的工作流程
  • 组长希望 Jira 指派后自动执行
  • 研发人员确认阻塞处理与交付渠道
  • 向团队介绍平台、本机 Harness 与 Tracker 的分工

先完成一次性接入

  1. 管理员配置组织权限、共享 Project、仓库 URL 和基线分支。
  2. 研发人员登记自己的电脑席位，绑定本机源码仓库，配置 Claude 与 Harness。
  3. 在席位的接单设置中配置 Jira 地址、PAT、经办人、项目、允许状态和工单类型，启用自动执行规则。
  4. 配置阻塞提醒的接收人和发送机器人。外部提醒需要实际凭据、配置与授权。
  5. 保持本机接入桥在线。只有在线且空闲、满足校验的席位才能开工；不会绕过其他执行者的锁。

⑬⑭⑮ 结果与验收平台 + 研发 / 负责人展示运行结果与用量，人员按正式流程验收并更新 Jira 状态网页运行记录、Tracker 和 Jira

自动模式与人工模式

  • 推荐日常模式：组长在 Jira 指派，已授权规则发现符合条件的工单，在线空闲席位自动执行；不需要每天重新配置，也不需要逐单确认开工。
  • 人工接入模式：在项目页登记工单，研发在本机执行 harness start ATSES-XXXXX --confirm-no-other-executor。适合手动启动或未启用自动接单的场景；校验仍然生效。
  • 离线或忙碌：平台保留队列，等待目标席位满足执行条件；不会默认让其他电脑接管。

三个容易误解的边界

  1. 智研协同平台管理和协调执行，Claude 与业务源码在研发电脑上运行。
  2. 运行结束、网页显示完成，都不能替代正式交付验收。
  3. 工作台的“待执行任务”是待办 / 待排期工单，真实自动执行队列要到席位页核对。

快速入门

日常导航与管理员入口

研发日常围绕 Jira、工单和席位；通用平台能力归入管理中心。

什么时候使用
  • 找不到以前的连接器、技能或例行任务入口
  • 研发人员希望接入 Jira 工单
  • 管理员配置项目仓库、权限或高级能力

日常入口

侧栏保留协同工作台、工单、待处理中心、项目、席位管理、执行记录、搜索和帮助中心。顶部“接入 Jira 工单”用于登记已有 Jira 子工单；手机底栏同步保留工作台、工单、接入、席位和待处理。

普通成员使用新建任务按钮或 C 快捷键时进入 Jira 接入。任务来源保持在 Jira，正式确认仍走 Jira/Harness。席位自动接单、Claude 执行、公共技能加载、提醒和运行记录不因菜单调整而停用。

待处理中心

统一展示席位阻塞提醒与原有待处理列表、失败和审批入口。提醒会说明应去 Jira/Harness、网页审批或本机权限提示处理；普通评论不是正式确认。

管理中心

实例管理员及当前组织的 owner/admin 可进入管理中心。组织管理员仅能管理自己所属组织，实例级配置仍需实例管理员。普通成员直接访问管理页面会看到权限说明；个人设置和修改密码始终可用。

  • 人员与权限：成员、邀请、人员联邦（联邦需实例管理员）。
  • 项目与执行配置：共享项目仓库、执行智能体、环境。
  • 用量与审计：组织费用、预算、操作记录和诊断。
  • 高级管理：公共协作技能、连接器、例行任务、目标、产物及原有实验能力；仍受原有开关控制。

当前 Harness 通过 GitLab 维护和分发技能、领域知识及 MCP 配置。平台连接器为可选治理能力，不是席位接入的前提。平台公共技能管理仅用于确有需要的公共协作技能。

原有能力没有删除

调整的是入口与权限。管理员仍可使用高级功能；运行数据、审批、领域回执和技能分配保留。试点诊断卡片已从首页移至管理中心。

组织费用与智能体配置接口按管理权限控制；普通成员的 Agent 展示响应不再提供完整执行配置。正式交付证据仍在工单和 Tracker 中查看。

开始使用与一张工单的完整流程

先了解三套系统的分工，再按工单生命周期使用网站。

什么时候使用
  • 研发人员第一次接入
  • 负责人安排编码或设计任务
  • 复盘一次 Agent 执行

协同工作台与全站导航

点击左上角“智研协同平台”返回工作台。组织切换位于品牌名称下方；各页面仍有独立标题和面包屑。右上角可进入在线帮助、待处理中心、个人设置和退出登录；手机端单独显示品牌栏。

  • 我的工作：显示直接指派给当前用户的工单，以及其负责席位智能体的工单。
  • 组织概览：显示当前组织内有权限查看的工单和席位，不扩大接口权限。
  • 需要你处理：优先展示席位提醒、阻塞工单与组织待审批入口。个人工单数量与组织审批数量分开显示。
  • 正在执行：按工单的执行中状态展示；真实进程、实时心跳和席位在线状态应到席位页核对。
  • 待执行任务：包含待办和待排期工单，不代表已领取的自动执行队列。
  • 组织运行概况：展示组织当前状态和本月费用；图表保留其实际统计周期，不当成今日统计。

浅色与深色模式共用靛蓝主色。绿色、橙色、红色分别提示完成、待处理与异常；状态仍需结合文字理解。

网站解决什么问题

智研协同平台 是智能体的管理台。它集中展示任务、运行记录、阻塞、决策和资源用量，让研发人员及负责人能了解“谁在做什么、什么时候做的、为什么停下来”。当前业务接入使用 Jira + 本地 Harness + 本地 Claude Code + Harness Tracker。

系统职责你主要在这里做什么
Jira需求、子工单、经办人和正式工程确认建需求、拆编码／设计子工单、维护状态、正式确认
智研协同平台 网页协调、可见性和任务管理选择项目和席位、登记工单、查看运行、处理待决策事项
本地 Claude + Harness执行和领域流程在终端观察 Claude，按技能开发、设计、校验和续传
Harness Tracker流程效果和交付数据查看 Harness 上报的结果、阶段和效果数据

Jira 自动执行与人工接入

日常研发推荐在席位页面配置“Jira 指派后自动执行”：组长指派 → 自动发现并排队 → 本机 Claude 执行 → 阻塞通知负责人 → 有效决策后继续。详情见“席位”。以下流程保留为人工接入方式。

人工接入流程

  1. 在 Jira 创建需求，并拆出编码、Bug 或设计子工单，指定研发经办人。
  2. 管理员配置共享 Project 的仓库 URL、基线分支，配置组织接入权限；研发人员通过“席位 → 接入我的电脑”登记独立执行席位。
  3. 研发人员在自己的电脑绑定本地业务源码仓库；同一项目的映射通常只需配置一次。
  4. 在 Project 详情页点击 接入工单，填写 Jira 子工单号、共享工作区、执行席位和允许开工的 Jira 状态。
  5. 等待网页显示“接入已完成”。登记完成不代表已经开工。
  6. 在选中的电脑打开终端，运行 harness start ATSES-XXXXX --confirm-no-other-executor。未启用 Jira 自动执行规则时，使用这一人工启动方式。
  7. 用网页查看任务、阶段、评论和运行，用终端观察 Claude 的具体执行和权限请求。
  8. 遇到业务歧义或需要人工决定时，先看阻塞说明和确认编号；按对应确认渠道处理。
  9. 完成后按 Harness 门禁提供交付证据和 Tracker 回执，再结束本地会话。网页任务状态不能替代领域验收。

各角色从哪里开始

  • 研发人员：先读“项目与共享仓库”“Jira 网页接入”“本地终端”“阻塞与人工决策”。
  • 研发负责人／项目经理：先读“概览”“任务”“运行与用量”“费用”“审计”。
  • 管理员：先读“席位”“组织与权限”“设置”“能力边界”。

某些功能由实验开关、插件或账号权限控制，菜单未出现时应先核对配置。没有菜单并不意味着网页故障。

认识组织、项目、任务、智能体和席位

用同一套概念理解网站各页面的关系。

什么时候使用
  • 多个项目共用管理台

概念含义示例
组织管理任务、智能体、权限和预算的范围一个研发团队
项目（Project）对同一业务目标和源码仓库的长期归类DSP7 银企直联
工作区（Workspace）项目的仓库及执行环境配置DSP7 仓库 URL 和基线分支
任务（Task / Issue）一项具体工作，有执行者、状态、讨论和交付证据一张 Jira 编码子工单对应的网页任务
智能体（Agent）智研协同平台 中登记的执行身份及其运行配置某研发电脑上的 Claude 执行身份
执行席位当前集成为一台研发电脑定义的独立身份张三的 Mac
运行（Run）某个智能体的一次实际执行记录一次 harness start 创建的运行
会话（Session）Claude 的交互上下文同一次本地会话内的开发与确认续传

容易混淆的地方

  • 网站账号是人的登录身份；Agent 是执行身份。这里的“席位”是本地执行电脑标识，并非 智研协同平台 的计费许可证数量。
  • 一个项目可以有很多任务，不需要为每张 Jira 工单新建项目。
  • 任务可以经历多次运行；一次运行结束不一定代表任务已经完成。
  • Project 的共享仓库配置不应依赖某位研发的 /Users/... 路径。每台电脑维护自己的路径映射。
  • 编码源码工作树与 Harness 的 tickets/... 工单目录职责不同：前者隔离源码修改，后者保存领域状态、方案和证据。

日常管理

概览：发现正在运行和需要处理的工作

从团队全局快速进入活动任务、失败运行和待审批事项。

什么时候使用
  • 负责人每日查看研发进度
  • 排查某个 Agent 是否还在工作

主要看什么

概览汇总当前组织的智能体、任务、费用以及近期活动。实时运行区域用于查看活动运行和最近完成的运行；待审批或预算提示用于发现需要人工处理的事项。

使用步骤

  1. 在侧栏顶部选择组织，进入“概览”。
  2. 先看活动运行和待处理事项，再看任务状态分布及近期活动。
  3. 点击任务进入任务详情；点击智能体或运行进入执行记录。
  4. 结合任务评论、阶段和阻塞原因判断进度，而不是只凭“运行中”判断有效产出。

如何读状态

“智能体空闲”表示当前没有活动运行，不证明研发电脑在线。“任务进行中”也不保证本地 Claude 仍在执行；需要同时看运行状态和本地会话。预算暂停、运行失败、业务阻塞是不同问题，应进入详情查看原因。

日常管理

任务：安排、拆分、跟踪与交付

用任务列表和详情页管理工作的状态、参与者及上下文。

什么时候使用
  • 负责人分派工作
  • 研发更新进度
  • 拆出评审或补充设计工作

列表和筛选

“任务”页用于查看组织内任务。可按状态、优先级、执行者、项目等条件筛选；列表、分组或看板视图是否可用，以当前页面为准。项目任务应关联到对应 Project，方便统一查看。

状态常见含义建议操作
待安排已登记，尚未准备开工核对执行者、条件和排期
待执行已准备好，等待执行检查所选席位及本地环境
进行中工作已开始查看运行、阶段和评论
评审中等待评审或验收查看证据和评审意见
已阻塞暂时无法推进读取阻塞原因及需要谁做什么
已完成网页任务结束正式工单还需核对领域验收和交付回执
已取消不再推进核对本地进程是否也已结束

详情页怎么用

  • 说明：保存工作目标、范围、约束和验收条件。
  • 执行者／负责人：谁执行、谁对任务负责；不要用反复换执行者来绕过独占登记。
  • 评论／会话：补充信息、提出调整、处理已明确的人工决策。
  • 运行／活动：查看执行记录和状态变化。
  • 子任务／关联工作：拆分评审、补充设计或依赖工作，并保留父子关系。
  • 文件／产物：核对交付文件和可追溯证据。

新建网页任务与登记 Jira 的区别

“新建任务”可创建 智研协同平台 普通任务，但不会自动成为正式 Harness 工单。正式编码、Bug 或设计子工单，请使用 Project 的“接入 Jira 工单”入口。不要仅在标题写一个 Jira 编号就开始执行。

修改网页状态、点击“已完成”，不等于已经执行 Harness 的完成门禁，也不会因此自动完成 Jira。当前集成没有把普通网页任务创建替换成 Jira 工单创建。

研发接入

项目与共享仓库：配置一次，供多张工单使用

按业务仓库建立长期项目，每台电脑自行绑定本地路径。

什么时候使用
  • 多个工单属于同一仓库
  • 多人在不同目录开发同一产品

Project 有什么用

Project 把任务、仓库工作区、项目说明、状态概况、成员及预算归在一起。适用于同一个产品、源码仓库或长期研发目标。项目摘要可帮助负责人了解当前状态、下一步和待人工处理的事项，具体更新取决于摘要智能体是否启用。

共享配置建议

  1. 创建项目，填写清晰的项目名称和说明。
  2. 添加共享工作区，设置 仓库 URL 和 基线分支。
  3. 共享工作区不要把某位研发电脑的本地 cwd 当成所有人的工作路径。
  4. 为各执行电脑登记席位，并在本机配置工作区到仓库路径的映射。

本机绑定示例

以下 UUID 和路径是占位符，需换成自己的 Project、工作区和业务源码路径：

harness seat info
harness repo bind --project <Project-UUID>   --workspace <Workspace-UUID>   --path /Users/yourname/work/dsp7.1_git
harness repo list

绑定时会核对仓库根目录、本机路径白名单、Git origin 与共享 URL，以及本机是否存在基线引用；不会自动拉取或覆盖源码。绑定对象是业务仓库，不是 Harness 知识库目录。

工作树怎么生成

编码和 Bug 工单通常准备独立工作树，分支使用 harness/<Jira编号>，目录位于该席位自己的工作树根目录。设计工单通常使用本机登记的源仓库，不额外创建源码工作树。

具体路径以接入结果或 harness status 为准，不要凭其他电脑的目录推断自己的路径。改动共享 URL、基线或本机映射可能导致执行校验停止，应先核对已有工单，避免在执行期间随意更换配置。

网页接入 Jira 工单：从申请到准备完成

通过项目页面把真实 Jira 子工单登记到所选电脑。

什么时候使用
  • 正式编码子工单开工
  • Bug 修复接入
  • 设计子工单登记

接入前准备

  • Jira 已指定研发经办人，工单类型属于当前支持的编码、Bug 或设计工作流。
  • 真实工单尚未完成，当前 Jira 状态允许开工。
  • Project 已配置共享仓库 URL 和基线。
  • 所选执行席位已登记，本机已绑定该工作区的业务仓库。
  • 申请账号在该席位允许接入的用户范围内。

网页操作步骤

  1. 进入目标 Project 的详情页，打开“接入工单”。
  2. 输入 Jira 子工单号，例如 ATSES-XXXXX。
  3. 选择项目的共享工作区。
  4. 选择实际执行的电脑／席位。
  5. 填写 允许执行的 Jira 状态，应与 Jira 当前可开工状态一致。
  6. 提交后，网页创建接入申请。所选本地桥在线时会核验并准备工作目录。
  7. 等待结果为“接入已完成”，然后在该电脑运行启动命令。

提交申请时网页会留下真实创建者的授权评论。不要手工编辑申请中的隐藏标记来换工单、换项目或换席位；它们与中央归属校验关联。

各种结果如何处理

显示结果含义下一步
等待接入桥处理申请已保存，所选桥尚未完成核验确认选对席位，检查该电脑的桥是否运行
接入已完成已登记并准备目录，但尚未开工在所选电脑打开终端启动
接入未完成／已阻塞Jira、仓库、账号或本机条件不满足按错误说明修复，在同一任务重试
已由另一任务或席位登记同一 Jira 的中央归属冲突找到已有任务并核对，不能重复抢占

接入过程中不会自动完成 Jira，也不会自动启动真实编码。已完成的 Jira 工单不能通过此入口重新开发；模拟演练使用独立流程。

研发接入

多席位：多人、多电脑如何协作

每台执行电脑使用独立身份、路径映射和连接通道。

什么时候使用
  • 同一项目由多位研发并行开发
  • 更换电脑
  • 申请落在离线席位

运行在哪里

  • 智研协同平台 管理台与服务端：部署在团队服务器。
  • 本地接入桥、Claude Code 和 Harness：运行在所选研发电脑。
  • 业务源码和工作树：保存在该电脑自己的目录中。

网页选择席位后，只有那个席位的桥处理申请。其他电脑不会因为同属一个 Project 就代领工单。

新电脑接入步骤

  1. 管理员为该电脑创建独立 智研协同平台 Agent，并配置指向该电脑的运行通道。
  2. 在电脑安装 Harness、Claude 和接入桥，准备业务仓库及基线。
  3. 用 harness seat init --name "研发电脑名称" 生成本机席位配置。
  4. 管理员合并输出的席位信息，签发此 Agent 独立凭证；本机按管理员说明安装凭证。
  5. 用 harness seat register 登记本机 Claude 运行配置，然后 harness repo bind 绑定项目工作区到本机路径。
  6. 在网页选中此席位提交工单。

管理员配置不是仅填一个显示名称；每台电脑必须使用自己的 Agent、机器身份、凭证和连接通道，不能复制另一台电脑的配置来充当第二席位。

同一工单的执行归属

准备工作树前，服务端会为组织内的 Jira 工单建立独占登记。相同申请可以重试，另一任务或席位不能重复登记。实际运行还有原生运行锁和本机租约。

席位离线、运行超时、任务取消或完成，不会自动转移 Jira 归属。 当前没有网页换席位或自动接管功能。需要交接时，请先让管理员确认旧执行者和本地进程都已停止，再安排迁移。

当前每台桥仍只允许一张启用工单。不同席位可以各自执行不同工单；旧人工 Claude 会话不在中央登记覆盖范围内，启动时仍需人工核对。

第一期：自动关联已登记席位

适用于已经在本机配置 Claude 和 Harness，希望网页直接复用本机执行者的研发人员。

  1. 管理员先为这台电脑绑定独立 Agent、SSH 环境、机器身份和授权用户，安装本席位的 0600 Agent 凭证。登记不能替代初始通道授权。
  2. 在自己的 Harness 目录执行登记，例如：
harness seat register --claude /usr/local/bin/claude --settings /Users/leo/work/fingard/base-harness-infrastructure-dsp7/.claude/settings.local.json
harness seat info

以上路径是当前 Leo Mac 的示例，其他电脑换成自己的路径。默认自动查找 Claude，并使用上次登记的配置或 Harness 的 settings.local.json；用 --use-default-settings 显式选择 Claude 默认配置。

  1. 新建 Claude 的连接步骤上方选择 关联已登记的本机席位。页面会展示执行环境、Claude 版本与路径、设置文件、Harness 根目录和最近检查时间。
  2. 点击 使用此席位，打开已有智能体。网页重新核对登记并打开原 Agent；这条入口不会为同一电脑再创建一个执行者。Project 接入 Jira 工单时也选择同一个席位。
  3. 本机执行 harness seat check 可核验并刷新；配置、路径或 Claude 版本变更后执行 harness seat register 重新登记，再点网页 刷新席位。

登记检查有效期为 24 小时，并不表示电脑当前在线。网页核对服务端登记；本机启动和交互包装器在调用 Claude 前再次检查机器、文件摘要、版本、环境和登记版本。登记不验证密钥或模型可用性。文件内容和 API 密钥不会上传。

已登记的包装器使用登记的 Claude 路径，通过 --settings 读取本机设置；原有同会话审批续传继续保留。管理员改变执行通道或参数后，需要重新核对登记。存在活动任务时不得更新执行配置。

若网页显示需刷新、配置不存在、登记版本不一致，请先在所属电脑处理，不要复制其他席位配置或重复创建 Agent。登记入口不自动发现电脑、不安装 SSH、不提供持续在线检测；下方手动配置向导用于创建独立智能体。

后续功能已接入

本地 Claude 终端：启动、观察与续传

在可见终端里执行，同时让网站记录运行与状态。

什么时候使用
  • 研发希望观察 Claude 执行
  • 终端断开后重新连接
  • 执行中改进 Harness 知识

启动正式登记工单

确认网页已显示接入完成，在所选电脑的终端执行：

harness start ATSES-XXXXX --confirm-no-other-executor

ATSES-XXXXX 是已登记的工单号。--confirm-no-other-executor 表示你已核对没有旧人工会话或其他未纳入系统的执行者同时处理该工单；它不能绕过服务端独占登记、Jira 状态和 Harness 门禁。

终端会请求 智研协同平台 创建实际运行，再连接可见的 Claude 会话。正式工单的 Claude 会切换到登记的业务源码目录；Harness 知识和领域状态仍从配置的 Harness 工程加载，不是凭你启动命令时的目录推测仓库。

观察和重新连接

harness status
harness attach ATSES-XXXXX

终端意外断开时，先查看状态，再尝试 attach。已有活动运行时不要反复 start，否则可能产生冲突或无效唤醒。

人如何参与

  • 在终端观察 Claude 的推理输出、工具调用和权限请求。
  • 使用 Claude 自身的权限机制确认操作；网页审批不替代本地工具权限。
  • 修订 Harness 知识、约束或说明后，让当前任务按需要重新核验，不要假设所有修改会自动注入当前上下文。
  • 可用 harness knowledge ATSES-XXXXX --summary "知识改进说明" 记录与工单相关的知识改进。

会话什么时候退出

当前已接入的确认等待可在同一会话内恢复，不要求为了接收有效的模拟同意消息而先输入 /exit。任务完成且不再需要交互后再退出。运行超时、手工取消、连接失败等情况仍需看网页与终端的实际状态。

这里不承诺网站能自动控制任意已经打开的普通 Claude 终端；可见性和续传适用于通过 harness start 接入的会话。

席位管理：运行概览、自动接单与通知

默认使用 Jira 指派驱动自动执行；电脑接入和旧手工模式按需使用。

什么时候使用
  • 组长 Jira 指派后自动执行
  • 优先处理阻塞与业务决策
  • 暂停新工单但继续当前任务
  • 连接研发电脑并检查配置

页面如何使用

  • 顶部待处理事项：优先呈现阻塞与超时提醒，点击“处理决策”进入对应工单。
  • 席位列表：搜索电脑名称，切换我的/全部席位，按需要处理、在线、忙碌或离线筛选。连接、执行、接单分别展示，离线时不把旧执行状态当作实时状态。
  • 运行概览：查看当前工单、已登记队列与最近心跳；操作记录默认收起，展开查看请求进度与取消尚未领取的请求。
  • 接单设置：推荐一次配置 Jira 自动接单。只有一个项目仓库时自动选择；多个时自行选定；没有仓库时先配置项目。手工模式放在高级区。
  • 通知：设置阻塞提醒与超时升级，按姓名选人。选择管理员登记的企业机器人，接收人需来自同企业的有效通讯录。
  • 设备与诊断：检查本机配置或更新登记，失败与警告直接展开，通过项收起。
  • 已有席位时接入向导默认隐藏，需要新电脑时点击“接入新电脑”。切换标签与刷新心跳不会覆盖未保存的表单；切换到其他席位前请保存配置。
  • HTTP IP 地址通常不支持浏览器系统通知，页面会显示不可用原因；钉钉与网页内提醒仍可使用。

推荐：Jira 指派后自动执行

场景：组长在 Jira 指派编码、Bug 或设计子工单，研发电脑在线后自动接单，遇到业务决策再通知负责人。

一次性配置

  1. 进入“席位”，选择自己的电脑，进入 接单设置 → Jira 指派后自动执行。
  2. 填写 Jira 网站地址及 PAT。PAT 加密保存在 智研协同平台 密钥存储中，页面只显示已配置；后续留空表示保留，输入新值可更新。本机通过自己的席位凭证获取这个席位的 PAT，值仅在内存中使用，不写入普通配置或日志。首次启用需配置 PAT。
  3. 填写 Jira 经办人登录名（不是中文显示姓名）、Jira 项目代号，选择 智研协同平台 项目和共享仓库。该仓库须已在本机通过 harness repo connect 关联。
  4. 点击 验证 Jira 连接并预览接单范围 读取真实 Jira 状态，再选择团队允许执行的状态和工单类型。补齐范围后再次预览，可查看匹配的未完成工单数量与前 10 个样例；预览只查询、不执行。状态需涵盖本次执行期间允许的状态；未完成但不在允许状态范围的工单不会开工。
  5. 进入 通知 标签，按人员联邦通讯录的姓名选择钉钉接收人及管理员登记的发送机器人，以及提醒和升级间隔。这部分通常只配置一次；自动工单不需要填写下面旧模式的逐单授权列表。
  6. 勾选自动执行授权并保存。启用后会发现当前已有的符合条件未完成工单，也会发现后续指派的工单。组长负责指派，你无需逐单登记或在本地输入 yes。

系统如何执行

本机后台接入桥默认每分钟查询一页 Jira（最多 50 张，并分页继续），按经办人、Jira 项目、工单类型和允许状态发现工作。它不依赖 Jira Webhook；离线期间没有执行，上线后查询补齐。智研协同平台 为发现的工单建立持久队列，同一组织同一 Jira 工单不重复建自动任务。

席位空闲、配置正常时，接入桥核验 Jira 归属、领域门禁、源码映射、独占登记和本机执行者，准备独立 worktree，在可见终端直接启动真实 Claude Run。macOS 使用 Terminal；Linux 自动打开终端需要图形登录和已安装的桌面终端。只有网站授权的调度任务能免去逐单启动确认，旧人工工单的模式保持独立。

需要业务决策时，网页出现待决策事项，并按配置发送通知。正式工程确认仍遵循 Jira 门禁；适用网页确认的事项在网页处理，有效决策交给同一 Claude 会话续传。

Agent 完成 Harness 交付门禁、回写任务并生成完成证据后，自动会话发送 /exit 收尾。真实运行结束、进程及租约核验通过后释放席位，再接下一单，不需要人工每天结束每个已完成会话。

改派、暂停和异常

  • 暂停接单：在运行概览点击暂停接单，只阻止新工单发现、准备与启动，已经运行的工单继续执行、决策续传与通知。恢复接单后继续查询和调度，不需要逐单重配。暂停状态保存在服务器，离线也可以设置；旧版桥以服务器启动门禁为准，升级桥后本机也会在发现和准备阶段等待。

  • 停用规则与暂停不同：停用会撤销自动工单授权，影响当前自动任务；界面保存前会再次说明。

  • 停用自动执行规则、经办人变化、需求或附件变化、工单移出允许状态时，当前自动任务停止并保留领域状态与证据，通知原负责人处理。

  • 忙碌时保留队列，不把等待标为接入失败；网络失败会保留执行状态，避免因不确定结果重复启动。

  • 旧版登记或其他席位已取得该 Jira 执行权时，不自动抢占。跨席位改派后需管理员核对旧进程停止并处理交接，当前版本没有自动转移既有独占登记。

  • 本机在线还需 Claude 已完成登录、模型配置可用及操作系统允许打开终端。这些本机环境问题会回报检查或请求失败记录。

推荐：接入我的电脑

场景：组织研发人员希望连接自己的电脑，沿用本机 Claude 和 Harness 配置，不配置 SSH、不输入智能体或项目 UUID。

  1. 使用本人网站账号登录，进入 席位 → 接入新电脑 → 接入我的电脑。
  2. 填写席位名称，点击 生成接入命令，复制到这台电脑的终端执行。命令中的一次性接入码有效期 15 分钟，请勿转发。
  3. 安装器检测本机 Claude、Harness 工程和 Jira 配置。检查目录后输入 yes。多个候选目录会让你选择；没有配置时会提示准备，安装器不会代替你安装 Claude 或克隆业务仓库。
  4. 从列表选择组织项目及本机 Git 仓库。安装器核对 origin 和基线分支，不需要输入 UUID。回车可以暂时跳过，之后执行 harness repo connect。
  5. 返回席位页面确认电脑在线。默认保持人工启动策略。后续在 Project 的“接入工单”登记 Jira 子工单，然后在本机运行 harness start ATSES-XXXXX --confirm-no-other-executor；macOS 也可以通过网页请求启动，由本机 Terminal 确认。

准备与权限

  • macOS / Linux，Python 3.9+、Git、可运行的 Claude Code、当前版本 Harness 工程，以及本机可访问网站的网络。Linux 后台服务使用当前用户 systemd；没有用户 systemd 时使用 --no-service 并手动启动安装器输出的 watcher 命令。Windows 原生安装尚未提供，可在 WSL 使用 Linux 路径。
  • 账号需要 agents:create 权限。组织要求新智能体审批时，快捷接入会停止，并要求管理员按原审批流程处理；它不会自动批准智能体。
  • 模型密钥和 Jira 凭证保留在电脑上。网站只登记配置来源、摘要及路径等信息。本机 Agent 使用其已经配置好的模型服务，包括第三方中转站。
  • 一台电脑在同一组织只保留一个席位。已经安装的电脑复用原席位，不会自动把旧 SSH 席位改成主动连接。
  • 项目共有仓库 URL 和基线分支；每台电脑分别选择自己的源码目录。Harness 根目录不是业务源码映射。

断线、取消和重新接入

本机监督器定期检查租约。网站取消运行或连接长期失败时停止对应 Claude；网络请求超时会延长实际停止时间。服务器重启后不会恢复派发旧执行包，本机收到旧租约失效后停止。网页运行结束不等于电脑进程已确认停止，重新启动前仍需核对本机状态。不要因为等待而在另一台电脑同时执行同一工单。

安装过程中已写入本机配置但尚未完成登记时，可以重跑安装命令，复用配置并完成后续登记。已有配置不完整或后台服务指向其他版本时，请按提示核对。不要删除凭证后重复创建新席位。

高级接入与日常管理

使用场景

  • 研发负责人确认电脑是否在线、Claude 配置是否发生变化。
  • 从网页请求本机启动，研发人员在可见终端核对后执行。
  • 新电脑安装接入桥、获得独立凭证，并登记自己的本机路径。
  • 为指定工单开启主动推进，发现阻塞并按间隔提醒、超时升级。

席位管理

侧栏打开 席位管理。本机接入桥约每 20 秒向服务器发送心跳，90 秒无心跳显示离线。显示状态包括在线空闲、正在执行、等待人工决策、等待本机确认、配置异常。

在线仅证明接入桥通信正常。 网页不会根据 Agent 的 idle 状态猜测电脑在线。模型密钥可用性和 SSH 启动能力以实际运行为准。

点击 检查本机配置，接入桥检查 Claude 可执行文件、版本、JSON 配置、Harness 和服务端登记。网页“操作记录”显示接收和结果，最近检查区域展示检查项。仅检查版本和文件，不调用模型，不上传密钥或文件内容。

配置变化后先核对，再点 更新设备登记。存在活动运行时，不允许更新执行配置。后台每分钟检查配置，每小时在配置一致时续期登记；出现变化时提醒，不自动接受新配置。

网页请求本机启动

  1. 从 Project 接入 Jira，或在本机登记模拟任务。工单需要出现在席位管理的“工单队列”中。
  2. 核对没有其他执行者，勾选确认，再点击 请求本机启动。
  3. 请求发送到服务器，接入桥通过出站轮询获取；不需要给研发电脑开放入站端口。
  4. 本机自动打开独立 Terminal 终端，输入 yes 同意；其他输入拒绝。也可执行 harness seat pending 查看请求，再运行 harness seat accept <请求UUID>。
  5. 同意后沿用原有 Harness 启动、Jira 校验和 智研协同平台 SSH 调度，连接真实 Claude 会话。网页记录运行 ID，终端显示执行过程。

请求等待有效期为 15 分钟。等待本机确认时网页可以取消；领取之后使用任务／运行页面处理，不把取消启动请求当作停止运行。重复请求不会启动第二个执行者。现阶段自动打开终端支持 macOS。

主动推进

在 接单设置 → 高级：手工登记工单的推进方式 中选择模式并填写明确的工单号，保存策略：

模式行为
手动启动仅处理人的启动请求
主动发现并请求确认在本机已登记且就绪的授权工单中发现待执行工作，主动打开终端请求确认
限时授权后自动执行在网站工单范围与本机有效授权同时满足时，自动打开可见终端并执行

自动执行需要在本机终端明确登记授权，例如：

harness seat allow-auto-start --jira ATSES-XXXXX --minutes 60 --confirm-no-other-executor
harness seat revoke-auto-start

授权最长 480 分钟，只覆盖明确登记的工单。本机授权过期、网站取消策略、Jira 状态不符、已有执行者或领域门禁不满足时不能自动启动。没有有效本机授权时改为终端人工确认。

只推进已经登记的工单，不自动创建 Jira 需求、不擅自领取其他研发的工单、不自动同意业务方案。一次主动请求不会在失败或结果不明确时无限重试，需要核对后手动恢复。

阻塞与多渠道提醒

待决策事项显示在席位管理；侧栏显示待处理数量。macOS 提交系统通知，按保存的间隔重复提醒，超过升级时间显示“超时升级”。通知是否实际弹出取决于系统通知权限和专注模式，窗口打开和网页提醒仍可查看。

浏览器支持系统通知且满足权限条件时，可点击 启用浏览器提醒；在普通 HTTP IP 地址上浏览器可能不提供该能力。网页内提醒始终可用。

钉钉使用网站保存的席位通知配置，旧 Harness 工单通知配置作为已授权的兼容路径。新接收人或群需要单独指定，系统不从席位登记中猜测收件人。真实工程确认仍通过 Jira；模拟确认只影响模拟 state。

新电脑接入向导

管理员点击 接入新电脑 → 高级 SSH 接入：先选择尚未绑定席位的独立 Agent 和已配置的 SSH 环境，填写那台电脑的 Harness、接入桥、Claude 与设置路径；可指定获授权的网站用户 ID，留空为当前管理员。

生成邀请并下载接入桥。邀请有效 15 分钟、只能使用一次，不会复制现有席位的凭证。新电脑准备 Harness、Claude 和 Jira 凭证，然后运行：

chmod 600 /绝对路径/paperclip-seat-invitation.json
/usr/bin/python3 onboard.py --invitation /绝对路径/paperclip-seat-invitation.json --jira-credential-file /绝对路径/jira-access.json --repository-root /本机业务源码根目录 --install-watcher

邀请中的桥安装位置必须与实际解压位置一致。成功后保存 0600 本机凭证，登记 Claude，配置 Harness 的桥路径并安装当前用户的后台监督进程。Jira 凭证不会从网站下发，需由研发电脑独立配置；本机仓库仍通过 harness repo bind 绑定。

同一组织内一台机器不能重复绑定两个执行 Agent。已有本机接入配置时安装器拒绝覆盖，应复用原席位或由管理员核对迁移。SSH 通道本身仍在“执行环境”中配置。

钉钉机器人通知

管理员在席位管理页展开“钉钉通知机器人”，添加企业内部应用机器人的名称、CorpId、AppKey、AppSecret 和 RobotCode。应用需启用机器人、开通单聊消息发送权限，并发布到负责人的可见范围。AppSecret 加密保存于平台服务器，不下发研发电脑。

席位负责人进入“通知”，先选择管理员登记的发送机器人，再打开接收人下拉框，输入姓名、部门、组织或钉钉 ID 关键词检索同企业人员。支持空格分隔多个关键词、上下键选择与回车确认；搜索无结果时检查关键词和人员联邦同步。设置提醒间隔和超时升级时间后，点击“保存通知设置”生效。由本机接入桥上报阻塞状态，平台服务器以机器人身份发送消息，本机无需登录个人 DWS。

“最近机器人投递”区分发送中、钉钉已受理、发送失败和结果未知。已受理不代表已读；未知结果不自动重发同一条消息，后续提醒周期会产生新的提醒。停用机器人会停止所有引用它的席位的钉钉提醒，网站和本机系统提醒仍可使用。旧个人账号配置不会自动转换，需要选择机器人并保存。

接单范围：工单状态与工单类型

工单状态决定什么时候允许接收及继续执行，例如“待编码”“编码中”；工单类型决定 Agent 接收哪类工作，例如“编码”“线上问题”“系统设计”。这两组条件与经办人、项目一起生效，必须全部满足。

  1. 先验证 Jira 连接，获取真实状态。
  2. 在“工单状态”中搜索关键词、勾选状态。列表可滚动，最多选择 20 个；上方展示全部已选状态，点击 × 可移除。搜索不会清除已选项。Jira 状态可能来自其他项目流程，请按团队实际工作流选取。
  3. 在“工单类型”区域选择工作类别。状态和类型分别至少选择一项。
  4. 查看“当前接单范围”摘要，补齐条件后重新预览匹配工单，再保存规则。预览只查询、不执行。

例如经办人为 liw2386，类型为“编码”，状态为“待编码、编码中”：只接收该经办人的编码工单，且当前状态必须是待编码或编码中。工单未完成但不在所选状态内仍不会开工。高级手工填写状态名称与复选框同步，不用重复配置。仅保存配置不等于启用自动执行，还需勾选自动执行授权。

什么时候使用
  • 研发过程需要透明化

进入运行记录

从任务详情中的运行记录、智能体详情或概览实时运行区域进入。通常可以查看运行状态、开始和结束时间、会话输出、工具调用、错误及关联任务，具体字段随适配器而异。

建议查看顺序

  1. 确认关联任务和智能体，避免把其他工单的运行当成当前执行。
  2. 看开始时间、结束时间、耗时和结果。
  3. 看错误摘要及最后阶段，区分业务阻塞、权限等待、连接故障和运行失败。
  4. 结合任务评论、领域状态及交付证据判断是否真正完成。

Token 和费用有什么限制

当前交互式 Claude 接入可从 Claude 持久化记录中提取可用的用量，并按消息编号去重。没有来源时应该显示未知，而不是当作零。

CLI／适配器报告或估算的费用不等同于服务提供方真实订阅账单。交互记录缺少权威费用账本时，美元费用可能未知。模型、缓存、订阅额度、请求费用是不同概念，不宜直接互相换算。

停止、取消与重试

停止和取消是执行控制操作，不是常规审批按钮。先查看任务和本地会话状态；服务端运行结束不总能证明本地进程已经消失。重试前确认旧执行者停止，并采用现有工单的正规续传入口。不要通过新建同一 Jira 的任务来规避锁。

费用与预算：管理上限、分析用量

从运行用量到组织、项目和智能体预算管理。

什么时候使用
  • 控制智能体费用

费用页面怎么读

选择时间范围和统计维度，查看智能体、项目、模型或计费方的费用与用量。推理账本面向请求和运行；财务账本面向账号层面的收费、抵扣或账单记录。没有数据可能是未发生事件，也可能是适配器未报告，需结合运行详情判断。

预算怎么用

预算用于限制智能体、项目或组织的支出。触发硬上限时可能暂停执行。管理员应核对用量和业务优先级，再决定提高预算、调整范围或保持暂停。

使用场景示例

  • 负责人比较同类任务的 Token 消耗和执行耗时，寻找 Harness 知识不足或重复尝试。

第一期：自动关联已登记席位

适用于已经在本机配置 Claude 和 Harness，希望网页直接复用本机执行者的研发人员。

  2. 在自己的 Harness 目录执行登记，例如：
harness seat register --claude /usr/local/bin/claude --settings /Users/leo/work/fingard/base-harness-infrastructure-dsp7/.claude/settings.local.json
harness seat info

以上路径是当前 Leo Mac 的示例，其他电脑换成自己的路径。默认自动查找 Claude，并使用上次登记的配置或 Harness 的 settings.local.json；用 --use-default-settings 显式选择 Claude 默认配置。

  1. 新建 Claude 的连接步骤上方选择 关联已登记的本机席位。页面会展示执行环境、Claude 版本与路径、设置文件、Harness 根目录和最近检查时间。

登记检查有效期为 24 小时，并不表示电脑当前在线。网页核对服务端登记；本机启动和交互包装器在调用 Claude 前再次检查机器、文件摘要、版本、环境和登记版本。登记不验证密钥或模型可用性。文件内容和 API 密钥不会上传。

已登记的包装器使用登记的 Claude 路径，通过 --settings 读取本机设置；原有同会话审批续传继续保留。管理员改变执行通道或参数后，需要重新核对登记。存在活动任务时不得更新执行配置。

若网页显示需刷新、配置不存在、登记版本不一致，请先在所属电脑处理，不要复制其他席位配置或重复创建 Agent。登记入口不自动发现电脑、不安装 SSH、不提供持续在线检测；下方手动配置向导用于创建独立智能体。

  • 概览和运行：查看任务、活动运行及历史结果。

适用于已有中转站地址和密钥，希望由 智研协同平台 驱动本地 Claude Code 的场景。

  1. 在“智能体”中新建 Claude 智能体，进入“连接模型”。
  2. 点击 使用网站密钥或登录，切换到 API 密钥，勾选 使用第三方中转站。
  3. 填写中转站提供的地址。按站点说明填写完整基础路径，系统不会自动追加 /v1；地址不能包含密码或密钥查询参数。

中转站必须兼容 Anthropic Messages API；仅提供 OpenAI Chat Completions 接口的站点不能直接用于 Claude。使用其他供应商模型时需确认站点兼容 Claude 的消息、工具调用和流式输出。认证失败应核对认证方式、密钥和基础地址，模型不存在应核对站点提供的模型名。

此入口位于“新建智能体”的连接步骤；组织首次引导和通用官方“连接”管理面板仍使用原有官方连接方式。已有智能体可通过配置中的环境变量和秘密引用维护中转站设置。

哪些变化会生效

  • 智研协同平台 新增或启用技能：通常在下一次运行准备技能提示包时生效。当前会话不会自动热更新；技能或指令版本变化可能影响旧会话复用。

什么时候使用
  • 评审设计文档
  • 验收源码和执行记录
  • 团队需要在线查看成果

应保存哪些证据

根据工作流保存设计说明、实现摘要、变更清单、检查结果、交付文件及 Tracker 回执。文件或附件应有清楚名称，并能关联到任务、执行者和相关运行。

在线查看与本地路径

上传到 智研协同平台 的附件或产物可以在网页中查看或下载。任务说明中出现一个本地路径，不等于文件已上传，也不保证其他电脑能访问；本机工作树不是共享下载链接。

当前 Harness 工单目录中的材料是否自动上传到网页，应以实际附件和产物列表为准。不要把终端“文件已生成”视为团队已经能在线查看。

完成时的核对

网页“已完成”状态之外，还应按 Harness 检查工单领域状态、交付证据和 Tracker 回执或允许的降级记录。缺少领域门禁时，不应仅靠修改网页状态结束真实工单。

管理外部工具、凭证及执行环境。

什么时候使用
  • Agent 需要访问外部系统
  • 多个成员管理不同连接

连接器

连接器用于配置外部应用、工具或消息系统。连接后是否能供某个 Agent 使用，取决于连接的权限、账号状态和分配方式。插件提供的连接能力以实际安装内容为准。

密钥与变量

密钥保存敏感凭证，变量用于一般运行配置。应明确允许哪些成员或智能体使用，核对凭证有效性、轮换和来源。不要把密钥粘贴在任务评论或帮助反馈中。

运行环境

运行环境描述任务在哪里执行以及如何连接。网站服务器、远程环境和研发电脑不是同一位置。当前本地 Claude 接入需要管理员配置对应电脑的运行通道；仅在网页填写本机路径不会自动建立连接。

连接成功不等于权限和业务流程已经打通。正式 Jira／Harness 接入还需独立核验工单、仓库、经办人和席位归属。

管理与配置

人员联邦与自动启用账号

同步人员默认启用，使用初始密码登录后自行改密。

什么时候使用
  • 从钉钉／企业微信同步人员
  • 首次登录并修改初始密码
  • 保留原网站账号与席位关系

无需管理员激活

人员联邦从钉钉或企业微信同步的新账号默认启用，初始密码为 12345。现有已设置密码的账号保留原密码。

  1. 打开登录页，输入企业邮箱与初始密码 12345；使用用户名时勾选“企业人员账号”。
  2. 首次登录自动进入修改初始密码页面，旧密码填写 12345，新密码为 8–128 个字符。
  3. 设置个人密码后进入工作台。未修改前，业务接口不可访问。

管理员不再需要逐人生成激活链接。同步仅为尚未设置本地密码的联邦托管账号初始化密码，不覆盖已有密码，不改变管理员权限或席位关联。

同步与账号关联

管理员在人员联邦配置身份源、应用凭证和部门范围，可立即同步或开启定时同步。目录账号与原网站账号发生冲突时，仍需核对并明确关联，不根据邮箱自动授予原账号权限。目录缺失的人员标记待核对，不自动删除网站账号和席位。

初始化密码只属于 智研协同平台，与钉钉、企业微信和企业邮箱密码独立。角色默认是普通成员，席位创建等权限仍由管理员授权。

账号与权限

修改个人登录密码

在个人设置中验证旧密码并设置新密码。

什么时候使用
  • 更换管理员初始密码
  • 更换个人登录密码
  • 退出其他设备的登录会话

操作步骤

  1. 使用需要修改密码的账号登录。
  2. 点击左下角头像，选择 编辑个人资料（个人设置）。
  3. 找到 修改密码，填写旧密码、新密码、确认新密码。
  4. 新密码为 8–128 个字符，与旧密码不同，两次输入必须一致。
  5. 默认勾选 退出其他设备的登录会话，当前登录保留；需要保留其他设备登录时可以取消。
  6. 点击 保存新密码，看到成功提示后，下次使用新密码登录。

适用范围

此功能只修改当前账号的本地登录密码，管理员不能通过此表单修改他人的密码。人员联邦导入后设置的 智研协同平台 密码也属于本地密码，与钉钉或企业微信密码独立。Cloud 外部管理账号请到其登录服务修改密码。

旧密码错误时不会修改。登录失效时请退出并重新登录。忘记旧密码不属于本表单的自助修改流程。

快速入门

Windows 原生席位接入

使用 Windows 本机 Claude 和 Harness，通过 PowerShell 接入，无需 WSL。

什么时候使用
  • 研发使用 Windows 电脑接入席位
  • 了解 Windows 环境准备、后台任务和终端操作

适用于研发已有 Windows Claude 环境，希望通过网页接收指派、查看执行与用量、处理阻塞决策的场景。

  1. 准备 Windows 10 1809+ 或 Windows 11、Python 3.10+（含 pip）、Git for Windows（含 Git Bash）。支持原生 claude.exe；官方 npm 安装的 claude.cmd 会解析为 Node 与 CLI JS 入口，避免将任务提示交给 cmd.exe 解释。Node 版本遵循 Claude 自身要求。
  2. 在 PowerShell 验证 claude --version 与 Git 可用，准备 Harness 和业务仓库。本机 .claude/settings.local.json 存在时沿用；否则使用 Claude 默认配置，不需要在网站重新填写模型 Key。
  3. 网站“席位 → 接入我的电脑”选择 Windows（原生 PowerShell），生成并执行接入命令。接入码有效期有限且仅能消费一次，不要转发。
  4. PowerShell 入口检测 Python，并在缺少时通过 pip 安装 pywinpty>=2.0.15,<4 的预编译 wheel；虚拟环境安装到当前环境，普通 Python 使用当前用户安装。企业网络需允许所配置 pip 源，或事先安装批准的 wheel。
  5. 根据提示确认 Harness／Claude 路径与项目仓库。成功后在用户级 PATH 加入 %LOCALAPPDATA%\ZhiyanSeat\bin，重新打开 PowerShell 使用 harness。
  6. 回网站确认心跳。可以先使用已授权的模拟工单验证，再启用正式 Jira 自动接单。

harness start、attach、seat、repo、status 和 knowledge 通过桥执行；其他子命令委托给登记的 Harness CLI。安装不修改 Harness 源码，不保证所有领域技能里的 Shell、Maven、MCP 都已适配 Windows；这些工具仍须在研发电脑准备好。

后台运行

安装当前用户的 Zhiyan-Seat-Bridge-<用户SID> 计划任务，使用交互登录身份、普通权限，登录时启动并立即启动本次接入，不保存 Windows 密码、不安装 SYSTEM 服务。使用 pythonw 启动监督进程并保存本机日志。

  • 必须保持该 Windows 用户已登录。退出登录、休眠和断网时会离线。
  • 网页请求或授权自动接单时可打开本机可见窗口。Ctrl+] 暂离后使用 harness attach 工单号 重连；/exit 结束 Claude 会话。
  • 使用 -NoService 时不创建任务，按安装器打印的命令手动运行 pilot.py ... watch。
  • 本机日志位于 ~/.config/paperclip-dsp7-bridge/watcher.log，超过 5 MB 后在下一次启动保留一份 previous 日志。
  • 本机 Windows 气泡提醒为尽力投递，受系统通知设置影响；网页与管理员配置的钉钉机器人仍是独立通知通道。

当前验证范围

已完成本机静态检查。Windows 原生接入尚待实机验收，首次使用请先确认心跳并运行模拟工单，再启用正式自动执行。
