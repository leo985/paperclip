快速入门

流程总览：从平台派单到交付验收

用四条泳道看清谁负责、在哪里执行、遇到阻塞由谁处理，以及最终如何验收。

什么时候使用
  • 首次了解智研协同平台的工作流程
  • 组长希望 在智研平台派单后自动执行
  • 研发人员确认阻塞处理与交付渠道
  • 向团队介绍平台、本机 Harness 与 Tracker 的分工

先完成一次性接入

  1. 管理员配置组织权限、共享 Project、仓库 URL 和基线分支。
  2. 研发人员登记自己的电脑席位，绑定本机源码仓库，配置 Claude 与 Harness。
  3. 在席位的接单设置中配置 Jira 地址、PAT、经办人、项目、允许状态和工单类型，启用自动执行规则。
  4. 配置阻塞提醒的接收人和发送机器人。外部提醒需要实际凭据、配置与授权。
  5. 保持本机接入桥在线。只有在线且空闲、满足校验的席位才能开工；不会绕过其他执行者的锁。

自动模式与人工模式

  • 推荐日常模式：组长在智研平台点击“派单并执行”，在线空闲席位自动准备并打开可见 Claude 终端；Jira 指派不会触发执行；不需要每天重新配置，也不需要逐单确认开工。
  • 人工接入模式：在项目页高级选项中选择“仅登记”，研发在本机执行 harness start ATSES-XXXXX --confirm-no-other-executor。适合手动启动或未启用自动接单的场景；校验仍然生效。
  • 离线或忙碌：平台保留队列，等待目标席位满足执行条件；不会默认让其他电脑接管。

三个容易误解的边界

  1. 智研协同平台管理和协调执行，Claude 与业务源码在研发电脑上运行。
  2. 运行结束、网页显示完成，都不能替代正式交付验收。
  3. 工作台的“待执行任务”是待办 / 待排期工单，真实自动执行队列要到席位页核对。

快速入门

条目自动交付最小闭环

启动一次后按交付证据自动衔接分析、研发与测试，人工处理问题、评审和验收。

什么时候使用
  • 已有主子工单，希望自动衔接需求分析、研发和 QA
  • 需要在网页查看阶段、回复阻塞问题并登记正式评审结论

使用方式

进入“需求条目 → 条目详情 → 一键交付条目 → 配置并启动”。选择分析、研发、测试席位，指定已存在且未结束的设计、编码、测试用例编写、功能测试四张 Jira 子工单，提供测试环境和待测构建的正式准入说明链接，点击“启动条目自动交付”。这是本条目后续自动执行的初始授权。

设计和编码共用研发席位；用例和执行共用测试席位。同一台电脑可以登记多个领域 Harness，无需给席位增加固定职责类型。分析使用登记的 analysis 路由，设计／编码使用 development 路由，用例／执行使用 qa 路由，禁止跨领域替代。编码继续包含研发 Harness 内的代码评审。

需求分析 → 真人评审和正式发布 → 研发设计 → 真人设计评审 → 编码与代码评审 → 测试用例 → 真人用例评审 → 功能测试 → 正式验收。

人工问题在条目流程中答复，平台绑定问题指纹并续传同一 Claude 会话；普通答复不改写原生 Jira 审批，不替代正式审签。分析问题、P3 评审和正式发布沿用独立需求分析页面。设计和用例评审需先在正式流程完成，再在条目中登记结论链接和核验说明；此处明确标注为人工核验，未声称自动回读轻舟审签。

中断和安全边界

  • 席位离线、忙碌或暂停接单：等待原席位，不换机、不重复启动。
  • 所有人、能力路由或授权人的管理权限变化：拒绝领取／续租，停止推进；保持已有原生数据。
  • 费用硬预算无法对新领域实际计价：拒绝自动启动；保留既有预算硬停规则。
  • 运行退出但没有有效交付：中断，不能推定阶段完成。显式恢复需核验旧进程树停止，建立新的派发身份，沿用原生任务目录。
  • 问题、评审和回执绑定版本，旧指纹提交拒绝；正式交付冻结后不能被另一版本覆盖。
  • 来源指纹变化或评审退回：阻塞后续派发。第一期不自动重规划或无限重试。
  • 管理员可停止当前执行及后续派发；是否真正停止以本机进程树回执为准。
  • 阻塞问题、设计／用例评审沿用席位配置的企业机器人接收人。原生问题还显示本机提醒；未配置机器人不虚构通知送达。DING 仍受现有在线等待核验约束。
  • 平台保存验收登记，不自动关闭 Jira 主单，也不修改轻舟正式业务状态。

本期未扩展的范围

并行研发分支、自动拆单、缺陷修复回环、退回后的自动重规划、跨组织派发、多主单同时编排、正式审签系统自动回读及自动关闭主需求。本期以已有真实四张子单和三个领域的已登记能力完成串行成功路径。

研发接入

月度排期条目与开发准入

按项目与月份浏览轻舟计划，批量同步来源，核验分析和设计条件后安排子工单执行。

什么时候使用
  • 组长从月度计划安排研发工作
  • 批量接入本月轻舟条目
  • 复用已有正式需求分析结论
  • 需求或分析版本变化后重新核验开发条件

从月度计划进入

“需求条目”默认打开“月度排期”。选择项目后自动读取当前月份的组织排期，切换月份自动加载，也可点击“刷新条目”。月份按来源归集口径查询，不按创建日期。来源配置填写子产品归属代码（例如 DSP）后，列表合并本组织排期和该产品期望本月交付的条目，跨研发、测试组补齐期望交付条目。使用“条目归属分类”筛选全部、本组织已排期、本月期望交付；两类可重叠，列表按编号去重。期望交付不等于实际完成。未配置子产品归属时沿用单组织排期。只有一个项目时自动选中。管理员先通过“组织来源配置”配置轻舟账号、项目 Jira 服务地址和 PAT（加密保存），点击“读取组织”，按名称或编码筛选并选择排期组织，点击“保存并查看组织条目”进入月度列表，无需填写条目号。Jira 来源连接不绑定席位，派单时另选执行席位。旧席位来源保存一次后复制为项目独立凭据，不修改原席位配置；地址未变时无需重填 PAT，地址变更时必须重填。已有配置自动复用保存的凭据读取组织；读取失败会保留原组织，不会自动切换。

列表展示轻舟返回的条目、负责人、计划时间和工单数量；来源未提供的信息明确标注。月份只是只读查询范围，不改变轻舟排期，也不设置 Agent 开工时间。

按编号精确查询

选择项目后，管理员可在月度排期或已纳管列表使用“按条目编号精确查询”，输入完整编号（例如 TWGF-00919）。系统直接查询轻舟基本信息，不受当前月份、列表筛选或是否已纳管限制，显示名称、来源状态、来源负责人和条目分析负责人。轻舟账号权限决定来源可见范围。已纳管条目可打开保存版本；未纳管条目可进入“补录来源与工单”，补录时选择月份用于核对排期；配置子产品归属后尚未排期也可保存来源版本。查询本身不保存快照、不派单。

一键同步本月全部条目

月度排期点击“一键同步本月全部条目”，先重新读取当前项目所选月份的完整合并清单（本组织排期及已配置产品的本月期望交付条目），再逐条同步轻舟和 Jira 的主子工单及来源版本。已纳管条目也会重新核对，来源无变化时复用已有版本。不受搜索、筛选、分页或勾选最多 20 条限制。不派单、不启动 Agent、不修改上游工单。

页面显示进度及逐条回执，并统计新增来源版本和来源未变化的条目数；新增来源版本包含首次导入和已有条目的来源更新，不代表全部为新条目。可停止后续同步，并仅重试失败和未完成项。单条失败继续其他条目，成功结果保留；账号权限或来源版本冲突会停止后续请求。同步期间请保持当前页面打开，离开页面将停止未发送的请求，当前请求可能仍保存，已保存结果不会撤销。此功能是网页手动整月同步，不是后台自动同步。

月度条目筛选

可组合使用关键词、来源负责人、条目分析负责人、来源状态、同步情况、开发准入和工单情况。两类负责人均支持搜索：来源负责人是研发拆分人员，条目分析负责人是轻舟需求分析人员；列表同时展示两者，关键词也支持搜索分析人员。筛选覆盖当前项目整月数据，再按每页 20 条展示，并显示筛选数量与总数量。打开条目后返回、刷新页面均保留条件；清除筛选保留项目和月份，切换项目会清除原项目的筛选。修改条件会清空批量选择，避免同步隐藏条目。未提供的负责人和来源状态可单独筛选；“待核验”不表示不允许开发，已登记核验也不能代替派发前的正式检查。

工单状态筛选

工单与执行中的子工单安排区、主子工单树均可按“来源状态”下拉筛选，包括来源实际返回的已发版、已完成、待受理等状态。支持与关键词组合，子单匹配后保留所属主单作为上下文。子工单安排区的来源状态与查看范围同时生效；在默认待安排范围选择结束状态时自动切换全部子单。状态来自当前保存版本，需要最新数据时可一键同步本月全部条目。

安排子工单执行

条目详情 → 工单与执行按主工单分组展示子单。默认“待安排”仅包含未接入平台、来源未结束的系统设计、系统设计补充、编码和前端编码子单。可切换“已接入”“来源已结束”“全部子单”，并按编号、标题、类型、状态或负责人搜索。每行分别展示保存版本中的来源状态、排期、来源负责人，以及实时查询到的平台任务和运行状态；来源状态可能滞后，需要时重新同步来源。主单结束不推定子单结束。

已接入的子单链接原平台任务处理对话、决策和恢复，不重复创建任务；同一子单关联多个任务时全部保留。来源已完成、取消、作废等明确结束状态的未接入子单不提供派发按钮。编码仍需先核验开发准入；设计不因编码准入未通过而隐藏。评审与测试等其他类型可在全部子单中查看，但不开放尚未实现的派发能力。按钮只进入席位选择，派发前服务端仍核验最新 Jira 状态、席位授权与执行条件。

主子工单树

同步后的核对表以主工单分组，子工单缩进展示，保留来源状态、经办人和排期。主行展示子单完成数；仍有待办的分支默认展开，全部完成的分支默认收起，可逐个或全部展开／收起。筛选编号、标题、类型、状态或经办人时自动展开匹配分支并保留主工单；清空搜索恢复原展开状态。完成数只依据来源状态，不代表正式验收。

同步与批量处理

点击单行“同步并查看”，读取该条目的轻舟分析清单、排期树及 Jira 主子工单，保存后进入条目详情。查询计划、同步来源都不授予执行权限。

也可勾选最多 20 个条目，点击“预览批量同步”核对编号和月份，再点击“开始只读同步”。逐条显示成功或失败，已成功的版本保留；失败项可单独重试。相同内容复用已有版本。

“已纳管条目”继续提供历史聚合、搜索和差异筛选。“来源与历史”的“更多操作 → 补录指定条目”用于补充已知条目；也保留手工快照导入。月度列表只展示组织的排期条目，未排期条目的完整查询尚未接通，可按已知条目号补录。跨月条目可补充完整排期查询范围，不能把本月局部排期当成全部交付计划。

已排期与可开发分别判断

已排期表示纳入计划，不代表分析或设计评审通过。条目详情的“开发准入”独立展示待核验原因。

  • 没有有效正式分析结论：创建需求分析任务，暂不派发编码。
  • 轻舟或 Jira 已有有效结论：管理员核对正式产物版本和通过结论后登记引用，不必重复运行分析 Harness。
  • 需要设计评审：同时登记正式设计评审通过结论链接。
  • 不需要设计评审：取消对应选项，并明确填写理由。
  • 最新平台分析修订未正式发布、来源有结构差异或尚无编码子单：先处理对应条件，不能仅登记链接就开工。

核验登记只记录管理员已核对正式流程的事实，不替代正式审批，系统不会凭状态文字或链接自动认定通过。登记绑定来源版本及分析修订；来源更新或出现新的分析修订时需要重新核对。

选择工单并派发

工单与项目

工单管理：筛选、执行状态与批量管理

用管理表格筛选项目和负责人，区分任务状态与执行证据，快速查看对话并维护个人视图。

什么时候使用
  • 组长按项目检查任务和等待人工事项
  • 研发查看自己的席位任务与本机执行情况
  • 管理员批量维护标签及普通平台任务归属

从哪里进入

侧栏工单入口默认展示“工单管理”表格。顶部可接入 Jira 工单或新建平台任务；这两个入口含义不同。表格中点击标题或右侧操作打开快速查看抽屉，关闭后保留当前列表。完整详情继续提供派单、正式决策与执行管理。

筛选与快捷视图

项目、负责人、席位和关键词直接显示；更多筛选包含工单状态、执行状态、优先级及周期执行任务开关。默认不展示周期执行产生的内部任务。关键词匹配已加载工单元数据中的平台编号、Jira 编号和标题，不搜索完整会话正文。

“全部工单、待处理、执行中、等待人工、已阻塞、执行异常、已完成”沿用当前筛选范围。待处理是待办与待排期工单，不等于已授权的调度队列；没有执行证据不会被当成运行或等待。工单元数据分批核对，加载未完成时数量带 ≥ 并显示说明，不能将其当作全量统计。数据读取失败会明确提示。

条件保存于 URL，刷新或分享链接可以恢复；数据权限仍由当前登录账号决定。条件标签支持单独移除或清除全部。默认按最近更新排序，也可以按创建时间或标题排序；管理表格支持每页 25、50、100 条。列表 / 看板入口保留原有分组和筛选能力。

两种状态分别表示什么

  • 工单状态：平台记录的任务生命周期，例如待处理、处理中、阻塞、已完成。
  • 执行状态：席位心跳和活动运行提供的证据。在线席位确认当前任务忙碌时显示运行中，上报等待决策时显示等待人工；离线不推断本机进程已退出。
  • 状态待核验：没有充分证据，不能当作 Agent 空闲或没有启动。
  • 结束状态待核对：工单已结束但仍存在活动运行或在线席位上报，需要人工查看记录核对，不会自动停止或重启。
  • 已登记待核验、等待调度：仍需查看派单授权与门禁，不能仅凭登记状态认定已获准执行。

“已完成”不是“已验证交付”。正式交付仍需核对 Harness、Jira 与交付证据。

快速查看与会话

右侧抽屉展示标题、项目和工单状态，按原有权限提供恢复提示；展开后读取工单说明、受管会话和 Harness 阶段。正文和会话不会为每条列表工单预先请求。缺少采集证据时不推算阶段百分比，正式决策按任务中指定的渠道处理。

列设置与个人视图

默认展示项目、负责人 / 席位、工单状态、执行状态和最近更新；优先级可按需打开，其余列可以隐藏。列设置和命名视图仅保存于当前浏览器，按登录账号及组织隔离，不在电脑之间同步，最多保存 20 个。浏览器拒绝存储时会提示，当前页面仍可操作。

批量管理

组织管理员可勾选当前页工单，添加标签、调整普通平台任务的项目或负责人。先预览目标和数量，再确认执行；结果逐项说明成功、跳过或失败。切换筛选或翻页会清空选择，避免操作隐藏工单。

添加标签前读取现有标签并追加保留。已绑定席位、Harness 或执行记录的任务，不在列表中批量修改项目或负责人，需要到详情核对绑定。调整负责人不会派单或启动 Claude；不提供批量启动、停止或恢复。

推荐操作

  1. 在“接入 Jira 工单”页面选择项目，在“接入 Jira 主需求”填写主需求编号。

编码与代码评审为什么没有两个执行按钮？

研发 Harness 已在编码流程中发现和核验关联的代码评审单，完成审查、修复与交付。再派发一个代码评审 Agent 会重复执行。

代码评审仍保留自己的真实 Jira 单号、被审提交 SHA、范围、评审报告、交付记录、独立计时及 Tracker 回执。多个编码单和评审单并存时，由 Harness 核验实际关联，不能仅凭“同一个主需求”推断。编码完成或 Claude 退出都不能直接把评审标成通过。

本期总览提供工单关联和执行方式说明，尚未聚合读取所有评审报告与 Tracker 回执；请在对应 Jira / Harness / Tracker 查看原始证据。

如何理解状态与权限？

  • Jira 状态和人员是接入时快照；平台状态来自当前任务记录，两者分别展示。派单准备时会重新读取 Jira，经办人、状态和类型仍必须符合席位规则。
  • 重复接入返回已有主需求，不覆盖既有执行状态，也不自动同步新增子工单。
  • 研发负责人是业务协调角色，不自动获得管理员权限。管理员可统一派单，席位负责人沿用现有权限；不能因此修改其他人的席位配置。
  • 工单、成员和席位仍以当前平台组织为权限边界。已有 DSP、基础平台、ATS2.0 组织不会自动迁移；跨团队可在同一个交付管理组织中建立项目、成员与执行席位。
  • 当前没有全链路自动排程。设计评审、构建环境和测试准入等领域门禁仍由正式 Harness / Jira 流程核验，不能以平台运行结束替代验收。

席位与本机执行

会话、阶段进度与席位统计

查看本机受管 Claude 的可见对话、同步缺口、Harness 阶段和人员时间统计。

什么时候使用
  • 了解工单执行过程和为什么等待
  • 查看完整工具结果及子代理记录
  • 按日、周、月、季度或年查看席位工作量
  • 复盘交付后的 Jira 关联缺陷

在哪里查看

  • 工单详情顶部“本机会话与 Harness 进度”：选择执行会话，查看对话记录、终端补充及 Harness 阶段。对话可切换“全部记录”或“仅人机问答”，筛选仅针对已加载记录，可继续加载后续记录。当前状态和本轮累计耗时优先展示，同步诊断、质量明细和阶段原始证据按需展开。工具和子代理记录带来源标签，长正文按需继续加载；预览不替代已保存正文。
  • 席位管理 → 统计分析 → “席位工单与时间统计”：选择日、周、月、季度、年及日期；查看席位／负责人、在手工单、开始／交付、执行／人工等待／在线空闲、工作时段在线和质量覆盖。
  • 席位的“设备与诊断”会说明客户端是否具备采集能力。需要配套发布并更新客户端后，新启动的已登记任务才提供记录；仅拉取 Harness 仓库不能替换已安装接入桥。

最大范围采集的含义

默认采集受管任务的可见研发输入、Claude 回复、工具参数与结果、子代理、上下文压缩信息和终端补充。会话由平台任务、运行和设备绑定，不扫描其他 Claude 会话，也不补录接入前历史；隐藏推理不采集。Token 继续使用原有用量账本，不根据重复消息再次计费。

凭据、私钥和配置路径按本机规则排除或遮蔽，服务端再检查。仅支持 UTF-8 文本附件；图片、PDF 等二进制或内嵌附件在缺少安全脱敏适配器时只保留元数据及不可用原因。单条正文／文本附件最多 100 MiB，本地待传队列默认 1 GiB、平台每会话正文分块最多 2 GiB。达到上限会显示暂停／缺口，不宣称完整。

同步状态与来源覆盖分开看

网络断开后先存在本机 SQLite 队列，重新连接按已确认位置补传。运行结束后保留 7 天补传窗口。同步结束只说明已经传到观察到的结束位置，不能证明来源没有截断、文件消失或不支持格式。请同时看缺口事件和同步健康。首次绑定平台失败且运行已结束的记录可能只保留在本机，需诊断处理，不会伪装采集成功。

“暂停上传”仍在本机记录，恢复后补传；“暂停采集”跳过暂停区间，恢复后不补采，留下明确缺口。平台不能删除 Claude 自身保存在本机的原生历史。

阶段和时间的依据

Harness state 和 effort 只证明观察到了阶段变化。只有受版本管理的完整门禁契约执行通过，才显示“门禁通过”。现有技能尚未配置契约时不会自动显示通过或推算完成百分比。

执行状态来自 Claude Hook、领域等待和短时观测窗口。网页批准后显示“已批准，等待本机恢复”，收到实际执行证据才恢复计时。无输出、失联和证据过期都不能算在线空闲；在线空闲需要席位心跳证明无活动任务。时间按 Asia/Shanghai 计算，周一开周，人员多电脑并行取时间并集。席位统计的“工作与等待”展示未知时长和时间覆盖率，用于辨别缺少证据的时间。“工作时段在线”仅累计工作时段内、由心跳证明的连接时长，执行、人工等待、空闲及暂停接单时的连接均可计入；心跳有效期为 90 秒。未覆盖的工作时段显示“统计不完整”，可展开查看缺失区间，不推算为离线，也不代表人员工时。管理员可在统计区展开“工作时段设置”，配置本组织每周工作日及最多四个不重叠的时间段；默认周一至周五 09:00–12:00、13:00–18:00。修改后历史查询也按新口径计算；当前不自动处理法定节假日、调休或请假。当前周期只累计已过去的工作时段，席位创建之前不计入，非工作时间不抵扣工作时段的缺口。

工单与质量口径

开始、交付、取消使用首次业务事件，负责人变更不重归历史；模拟任务排除。平台在手取期末附近 90 秒内快照；Jira 在手取已配置经办人、项目和类型范围内未完成总数，快照须在 15 分钟内，缺少数据显示“暂无快照”。

缺陷只认 Jira 显式关联且类型为 Bug／缺陷等的工单，不把 Agent 失败当作缺陷。观察窗口为首次交付后 14 天，完整观察过窗口的样本才进入缺陷发生率分母。暂无快照或样本未成熟会明确提示，不显示虚假的零缺陷。

权限和保留

正文仅执行时负责人及组织管理员可查看，其他成员即使能看工单也不能读取该正文。负责人变更不会把前任正文转交给新负责人。会话正文不进入通用运行日志、搜索、第一方遥测或错误上报。

在会话的“采集控制与数据管理”中可暂停采集／上传或确认删除平台正文。删除会清理正文分块和消息投影，并留下墓碑防止重传复活；客户端收到后清理对应采集队列，原生 Claude 文件仍由本机管理。正文默认 90 天保留，由新会话登记触发清理，每小时最多处理 100 个到期会话；当前尚无独立定时清理和组织自定义保留策略。元数据长期清理仍待补充。

支持与验收边界

采集器协议／解析器版本为 1，使用现有 macOS、Linux 和原生 Windows 桥接入口。当前代码完成静态检查和构建不等于真实 Claude／操作系统兼容验收；未知格式会标出缺口。当前每轮创建独立原生会话；同轮 Stop Hook 继续受支持，跨轮复用同一原生会话被拒绝。

研发接入

项目与共享仓库：配置一次，供多张工单使用

按业务仓库建立长期项目，每台电脑自行绑定本地路径。

什么时候使用
  • 多个工单属于同一仓库
  • 多人在不同目录开发同一产品

Project 有什么用

Project 把任务、仓库工作区、项目说明、状态概况、成员及预算归在一起。适用于同一个产品、源码仓库或长期研发目标。项目摘要可帮助负责人了解当前状态、下一步和待人工处理的事项，具体更新取决于摘要智能体是否启用。

共享配置建议

  1. 创建项目，填写清晰的项目名称和说明。
  2. 项目仓库为可选项：测试 Harness 可只使用套件内资产与目标环境，无须额外仓库。研发需要业务源码时，优先选择 Harness 的 settings.local.json 目录引用中、且在在线席位源码白名单内的已有仓库；需要补充时，在项目“配置 → 源代码库”点击 添加 GitLab / 其他 Git 仓库，填写 仓库 URL 和 基线分支或标签。支持 HTTP、HTTPS、SSH URL 和 git@host:group/project.git 格式；已有仓库点击“编辑”即可修改。仓库认证沿用执行电脑上的 Git 凭据。
  3. 共享工作区不要把某位研发电脑的本地 cwd 当成所有人的工作路径。
  4. 为各执行电脑登记席位。研发接入会复用 origin 与基线匹配的唯一白名单目录；多个候选或较深目录可显式配置工作区到仓库路径的映射。

本机绑定示例

以下 UUID 和路径是占位符，需换成自己的 Project、工作区和业务源码路径：

harness seat info
harness repo bind --project <Project-UUID>   --workspace <Workspace-UUID>   --path /Users/yourname/work/dsp7.1_git
harness repo list

绑定时会核对仓库根目录、本机路径白名单、Git origin 与共享 URL，以及本机是否存在基线引用；不会自动拉取或覆盖源码。绑定对象是业务仓库，不是 Harness 知识库目录。

工作树怎么生成

编码和 Bug 工单通常准备独立工作树，分支使用 harness/<Jira编号>，目录位于该席位自己的工作树根目录。设计工单通常使用本机登记的源仓库，不额外创建源码工作树。

具体路径以接入结果或 harness status 为准，不要凭其他电脑的目录推断自己的路径。改动共享 URL、基线或本机映射可能导致执行校验停止，应先核对已有工单，避免在执行期间随意更换配置。

通过项目页面把真实 Jira 子工单登记到所选电脑。

什么时候使用
  • 正式编码子工单开工
  • Bug 修复接入

接入前准备

  • Jira 已指定研发经办人，工单类型属于当前支持的编码、Bug 或设计工作流。
  • 真实工单尚未完成，当前 Jira 状态允许开工。
  • Project 已配置共享仓库 URL 和基线。
  • 所选执行席位已登记，本机已绑定该工作区的业务仓库，并已更新到支持席位规则接入的客户端。
  • 席位接单设置已保存 Jira PAT、经办人登录名、Jira 项目、平台项目仓库、允许状态和工单类型。手工接入可复用已保存但未启用自动执行的规则。

网页操作步骤

  1. 进入目标项目详情页，在“Jira 工单执行”中点击“接入 Jira 工单”或“接入其他工单”。
  2. 输入 Jira 子工单号，例如 ATSES-XXXXX。
  3. 选择项目的共享工作区。
  4. 选择实际执行的电脑／席位。
  5. 查看自动展示的席位接单规则，无需再次选择状态。点击 核验工单与席位规则，查看 Jira 当前状态、类型及核验结果；提交时也会重新核验。
  6. 点击 派单并执行。网页创建引用席位规则的接入申请，所选本地桥在线时再次核验并准备工作目录。项目、仓库、经办人、类型或状态不匹配时会说明原因，请在席位接单设置中修正，不再逐单填写状态。
  7. 查看等待上线、排队、准备、执行、等待决策等状态。本机自动打开可见 Claude 终端，无需输入启动命令。

提交申请时网页会留下真实创建者的授权评论。不要手工编辑申请中的隐藏标记来换工单、换项目或换席位；它们与中央归属校验关联。

各种结果如何处理

显示结果含义下一步
等待接入桥处理申请已保存，所选桥尚未完成核验确认选对席位，检查该电脑的桥是否运行
接入已完成已登记并准备目录，但尚未开工在所选电脑打开终端启动
接入未完成／已阻塞Jira、仓库、账号或本机条件不满足按错误说明修复，在同一任务重试
已由另一任务或席位登记同一 Jira 的中央归属冲突找到已有任务并核对，不能重复抢占

平台派单会授权真实执行；不会自动完成 Jira。已完成的 Jira 工单不能通过此入口重新开发；模拟演练使用独立流程。

规则变化与旧申请

新申请复用席位当前规则，本机准备目录和每次启动前重新核验 Jira 当前状态；变更规则不会自动授权开工。旧申请保留原先明确填写的允许状态，不修改已有授权标记。遇到已有申请时打开原任务处理，不重复创建。客户端版本较旧时页面提示先更新，不会静默提交无法处理的新申请。

两种操作与已有登记

  • 派单并执行（默认）：明确授权目标席位自动准备、排队和启动。必须开启席位的平台派单执行开关，并更新客户端到支持平台派单的版本。离线派单仍持久保存，恢复上线后处理。
  • 仅登记（高级选项）：准备后等待本人启动，不产生自动执行授权。
  • 已有版本 3 的登记申请，可在当前任务卡片点击“执行 DSP-xx”（显示实际任务编号），不修改原始隐藏标记、不重新建任务。旧版本申请需按提示处理，不能擅自改写授权标记。
  • 尚未领取执行权时可以“取消自动执行”；已领取或运行中的任务在任务页面处理，取消不会强行杀死 Claude。
  • 自动执行授权由平台单独保存并审计，修改普通任务描述或 Jira 指派不会产生授权。
  • 席位电脑需要已登录图形桌面，并允许接入桥打开系统终端。终端显示实际任务指令、工具调用和可见输出，不包含模型内部不可见推理。

关闭终端与恢复执行

关闭本机终端后，网页会显示“终端已断开，等待重连”。一般保留 60 秒重连时间，可在本机终端执行 harness attach ATSES-XXXXX（替换为实际工单号）；等待审批的会话按审批等待期限保留。超时或会话异常结束后，任务会标为阻塞，并显示“执行已中断”，不会自动再跑。

在原任务详情页或项目派单面板点击 恢复 DSP-xx（显示实际任务编号）。系统需要在线客户端确认旧进程已退出，且不存在活动运行；再生成新的执行授权，重新核验 Jira、仓库和执行锁并打开终端。保留原工单和 Harness 阶段，不保证复用已退出的 Claude 上下文。其他领域阻塞不能用此按钮跳过。离线或旧进程状态未知时不允许恢复。

Jira 变更与网页派单

任务详情与接入申请卡片显示 Jira 当前状态、经办人和最近同步时间。页面打开期间每 30 秒刷新，也可点击“同步 Jira 状态”。同步失败会明确提示，不能依据旧结果派单。Jira 来源状态与平台执行状态分开展示；变更经办人不会自动启动席位。

在原任务页点击“派单并执行”，平台会重新读取 Jira 并核验当前席位规则。在线空闲席位领取后准备源码并打开本机 Claude；准备失败会回写具体原因，修正后在同一任务点击“修复后重新派单”，无需新建接入申请。活动执行不能重复派单。

第一期：自动关联已登记席位

适用于已经在本机配置 Claude 和 Harness，希望网页直接复用本机执行者的研发人员。

  1. 管理员先为这台电脑绑定独立 Agent、SSH 环境、机器身份和授权用户，安装本席位的 0600 Agent 凭证。登记不能替代初始通道授权。
  2. 在自己的 Harness 目录执行登记，例如：
harness seat register --claude /usr/local/bin/claude --settings /Users/leo/work/fingard/base-harness-infrastructure-dsp7/.claude/settings.local.json
harness seat info

以上路径是当前 Leo Mac 的示例，其他电脑换成自己的路径。默认自动查找 Claude，并使用上次登记的配置或 Harness 的 settings.local.json；用 --use-default-settings 显式选择 Claude 默认配置。

  1. 新建 Claude 的连接步骤上方选择 关联已登记的本机席位。页面会展示执行环境、Claude 版本与路径、设置文件、Harness 根目录和最近检查时间。
  2. 点击 使用此席位，打开已有智能体。网页重新核对登记并打开原 Agent；这条入口不会为同一电脑再创建一个执行者。Project 接入 Jira 工单时也选择同一个席位。
  3. 本机执行 harness seat check 可核验并刷新；配置、路径或 Claude 版本变更后执行 harness seat register 重新登记，再点网页 刷新席位。

登记检查有效期为 24 小时，并不表示电脑当前在线。网页核对服务端登记；本机启动和交互包装器在调用 Claude 前再次检查机器、文件摘要、版本、环境和登记版本。登记不验证密钥或模型可用性。文件内容和 API 密钥不会上传。

已登记的包装器使用登记的 Claude 路径，通过 --settings 读取本机设置；原有同会话审批续传继续保留。管理员改变执行通道或参数后，需要重新核对登记。存在活动任务时不得更新执行配置。

网页派单与恢复的启动进度

已完成本机登记、在线且空闲的席位，在网页授权派单或恢复时会同步生成持久启动指令。更新后的客户端通过独立的主动连接领取，最多每秒检查一次新指令，不再等待两轮 20 秒轮询。会话补传、Jira 统计和通知不占用指令接收通道。未准备仓库、离线或忙碌的任务仍按正常队列等待。

任务和接入结果中可查看启动进度及各阶段累计耗时：网页授权 → 指令生成 → 本机收到 → 环境核验 → Jira／仓库核验 → 请求真实运行 → 本机终端连接。终端连接后 Claude 仍可能初始化或等待模型响应；收到指令不代表模型已开始工作。

新通道需要更新席位客户端；旧客户端继续使用心跳领取。网络中断会自动重连，持久指令和本地打开记录防止重复打开终端；仍会核验原进程停止、平台授权、Jira、仓库和执行锁。运行中的席位请等待任务结束后再更新客户端。

批量选择允许执行的 Jira 状态

接单设置的“① 工单状态：什么时候允许执行？”支持“全选状态”。搜索关键词后，操作变为“全选搜索结果”，只选择当前匹配项，保留搜索范围外的已选状态；再次点击取消当前范围的选择。“清空状态”移除全部已选项。支持部分选择提示，并可继续逐项调整。最多保存 1000 个状态，选择后点击“保存 Jira 自动执行规则”才生效；全选不会自行派单或开工，已完成工单仍不可执行。

席位与执行智能体有什么关系

个人电脑席位关联一个执行智能体身份。席位管理电脑在线状态、负责人、接单规则、仓库与通知；智能体记录执行配置、技能、用量与运行历史。旧 SSH 席位和主动连接席位均使用席位派单流程。

个人席位智能体详情提供“派发 Jira 工单”和“查看关联席位”。派发入口预选当前席位，并优先显示该席位规则绑定的项目；进入表单后核对项目、仓库和目标席位，仍需明确提交才派单。指定席位不存在、无权限、已暂停或未启用 Jira 接入时提示处理，不自动改派其他电脑。席位详情链接直接定位目标席位。

已绑定席位的智能体不在详情页提供通用分配任务、立即运行、跟踪运行、暂停、终止、复制或重置会话入口。接单控制与设备配置统一到席位管理，避免把平台原生运行误认为 Harness 工单派发。平台现有接口授权及正式执行门禁继续生效。

独立服务器智能体继续保留原生任务分配、立即运行与管理操作，由其执行环境决定运行位置。新建平台任务并指派独立服务器 Agent，属于平台原生任务流程；正式 Jira / Harness 研发任务使用“派发 Jira 工单”。

上级智能体与人类负责人

“上级智能体”是 Agent 之间的汇报层级，不是席位负责人。个人席位隐藏此字段，人类负责人由管理员在席位管理指定；独立服务器 Agent 可按多智能体协作需要选择，单独工作可留空。历史上级关系不会因隐藏字段被删除。

部分账号没有配置读取权限，接口会省略智能体配置。新版页面会使用当前账号可访问的席位登记表补充识别；核对未完成或失败时不展示通用运行操作，可重试。若发布后仍看到 Assign Task / Run now 或 Choose manager，请先保存编辑并完整刷新页面；仅在左侧菜单切换不会更新已经打开的网页代码。

harness status
harness attach ATSES-XXXXX

终端意外断开时，先查看状态，再尝试 attach。已有活动运行时不要反复 start，否则可能产生冲突或无效唤醒。

  • 接单设置：推荐一次配置 平台派单执行。只有一个项目仓库时自动选择；多个时自行选定；没有仓库时先配置项目。手工模式放在高级区。

  • 通知：设置阻塞提醒与超时升级，按姓名选人。选择管理员登记的企业机器人，接收人需来自同企业的有效通讯录。

  • 设备与诊断：检查本机配置或更新登记，失败与警告直接展开，通过项收起。

  • 已有席位时接入向导默认隐藏，需要新电脑时点击“接入新电脑”。切换标签与刷新心跳不会覆盖未保存的表单；切换到其他席位前请保存配置。

  • HTTP IP 地址通常不支持浏览器系统通知，页面会显示不可用原因；钉钉与网页内提醒仍可使用。

推荐：智研平台派单后自动执行

场景：组长统一在本平台发起任务，本机可见执行，遇到决策通知负责人。

  1. 在接单设置保存 Jira 地址、PAT、经办人登录名、项目仓库、允许状态与工单类型，勾选“允许此电脑自动执行智研平台明确派发的工单”。
  2. 在通知页配置发送机器人及负责人，保持电脑桌面登录、接入服务在线。
  3. 进入项目页“派单”，填写 Jira 工单号，选择仓库和席位。状态复用席位配置。
  4. 点击“派单并执行”，系统记录持久授权；离线等待上线，忙碌保留队列，空闲后准备并启动本机可见 Claude 终端。
  5. 在网页查看进度、会话、用量和待决策事项，在本机观察实时上下文输出。需要决策时按正式领域门禁处理。
  6. 如需暂不执行，在高级选项选择“仅登记”；该操作不会生成自动执行授权。

Jira 的指派只作为经办人校验，不再扫描 Jira 自动建单或开工。 平台派单是唯一新增自动任务的入口。完成后的自动会话按既有完成门禁退出、核验后释放席位。

改派、暂停和异常

  • 暂停接单：在运行概览点击暂停接单，只阻止新工单发现、准备与启动，已经运行的工单继续执行、决策续传与通知。恢复接单后继续平台队列调度，不需要逐单重配。暂停状态保存在服务器，离线也可以设置；旧版桥以服务器启动门禁为准，升级桥后本机也会在发现和准备阶段等待。

  • 停用规则与暂停不同：停用会撤销自动工单授权，影响当前自动任务；界面保存前会再次说明。

  • 停用自动执行规则、经办人变化、需求或附件变化、工单移出允许状态时，当前自动任务停止并保留领域状态与证据，通知原负责人处理。

  • 忙碌时保留队列，不把等待标为接入失败；网络失败会保留执行状态，避免因不确定结果重复启动。

  • 旧版登记或其他席位已取得该 Jira 执行权时，不自动抢占。跨席位改派后需管理员核对旧进程停止并处理交接，当前版本没有自动转移既有独占登记。

  • 本机在线还需 Claude 已完成登录、模型配置可用及操作系统允许打开终端。这些本机环境问题会回报检查或请求失败记录。

推荐：接入研发电脑（管理员）

场景：组织研发人员希望连接自己的电脑，沿用本机 Claude 和 Harness 配置，不配置 SSH、不输入智能体或项目 UUID。

  1. 使用本人网站账号登录，进入 席位 → 接入新电脑 → 接入研发电脑（管理员）。
  2. 填写席位名称，点击 生成接入命令，复制到这台电脑的终端执行。命令中的一次性接入码有效期 15 分钟，请勿转发。
  3. 安装器检测本机 Claude、Harness 工程和 Jira 配置。检查目录后输入 yes。多个候选目录会让你选择；没有配置时会提示准备，安装器不会代替你安装 Claude 或克隆业务仓库。
  4. 从列表选择组织项目及本机 Git 仓库。安装器核对 origin 和基线分支，不需要输入 UUID。回车可以暂时跳过，之后执行 harness repo connect。
  5. 返回席位页面确认电脑在线。默认保持人工启动策略。后续在 Project 的“接入工单”登记 Jira 子工单，然后在本机运行 harness start ATSES-XXXXX --confirm-no-other-executor；macOS 也可以通过网页请求启动，由本机 Terminal 确认。

准备与权限

  • macOS / Linux，Python 3.9+、Git、可运行的 Claude Code、当前版本 Harness 工程，以及本机可访问网站的网络。Linux 后台服务使用当前用户 systemd；没有用户 systemd 时使用 --no-service 并手动启动安装器输出的 watcher 命令。Windows 原生安装尚未提供，可在 WSL 使用 Linux 路径。
  • 账号需要 agents:create 权限。组织要求新智能体审批时，快捷接入会停止，并要求管理员按原审批流程处理；它不会自动批准智能体。
  • 模型密钥和 Jira 凭证保留在电脑上。网站只登记配置来源、摘要及路径等信息。本机 Agent 使用其已经配置好的模型服务，包括第三方中转站。
  • 一台电脑在同一组织只保留一个席位。已经安装的电脑复用原席位，不会自动把旧 SSH 席位改成主动连接。
  • 项目共有仓库 URL 和基线分支；每台电脑分别选择自己的源码目录。Harness 根目录不是业务源码映射。

位置运行内容

断线、取消和重新接入

本机监督器定期检查租约。网站取消运行或连接长期失败时停止对应 Claude；网络请求超时会延长实际停止时间。服务器重启后不会恢复派发旧执行包，本机收到旧租约失效后停止。网页运行结束不等于电脑进程已确认停止，重新启动前仍需核对本机状态。不要因为等待而在另一台电脑同时执行同一工单。

安装过程中已写入本机配置但尚未完成登记时，可以重跑安装命令，复用配置并完成后续登记。已有配置不完整或后台服务指向其他版本时，请按提示核对。不要删除凭证后重复创建新席位。

高级接入与日常管理

使用场景

  • 研发负责人确认电脑是否在线、Claude 配置是否发生变化。
  • 从网页请求本机启动，研发人员在可见终端核对后执行。
  • 新电脑安装接入桥、获得独立凭证，并登记自己的本机路径。
  • 为指定工单开启主动推进，发现阻塞并按间隔提醒、超时升级。

席位管理

侧栏打开 席位管理。本机接入桥约每 20 秒向服务器发送心跳，90 秒无心跳显示离线。显示状态包括在线空闲、正在执行、等待人工决策、等待本机确认、配置异常。

在线仅证明接入桥通信正常。 网页不会根据 Agent 的 idle 状态猜测电脑在线。模型密钥可用性和 SSH 启动能力以实际运行为准。

点击 检查本机配置，接入桥检查 Claude 可执行文件、版本、JSON 配置、Harness 和服务端登记。网页“操作记录”显示接收和结果，最近检查区域展示检查项。仅检查版本和文件，不调用模型，不上传密钥或文件内容。

配置变化后先核对，再点 更新设备登记。存在活动运行时，不允许更新执行配置。后台每分钟检查配置，每小时在配置一致时续期登记；出现变化时提醒，不自动接受新配置。

网页请求本机启动

  1. 从 Project 接入 Jira，或在本机登记模拟任务。工单需要出现在席位管理的“工单队列”中。
  2. 核对没有其他执行者，勾选确认，再点击 请求本机启动。
  3. 请求发送到服务器，接入桥通过出站轮询获取；不需要给研发电脑开放入站端口。
  4. 本机自动打开独立 Terminal 终端，输入 yes 同意；其他输入拒绝。也可执行 harness seat pending 查看请求，再运行 harness seat accept <请求UUID>。
  5. 同意后沿用原有 Harness 启动、Jira 校验和 智研协同平台 SSH 调度，连接真实 Claude 会话。网页记录运行 ID，终端显示执行过程。

请求等待有效期为 15 分钟。等待本机确认时网页可以取消；领取之后使用任务／运行页面处理，不把取消启动请求当作停止运行。重复请求不会启动第二个执行者。现阶段自动打开终端支持 macOS。

主动推进

在 接单设置 → 高级：手工登记工单的推进方式 中选择模式并填写明确的工单号，保存策略：

模式行为
手动启动仅处理人的启动请求
主动发现并请求确认在本机已登记且就绪的授权工单中发现待执行工作，主动打开终端请求确认
限时授权后自动执行在网站工单范围与本机有效授权同时满足时，自动打开可见终端并执行

自动执行需要在本机终端明确登记授权，例如：

harness seat allow-auto-start --jira ATSES-XXXXX --minutes 60 --confirm-no-other-executor
harness seat revoke-auto-start

授权最长 480 分钟，只覆盖明确登记的工单。本机授权过期、网站取消策略、Jira 状态不符、已有执行者或领域门禁不满足时不能自动启动。没有有效本机授权时改为终端人工确认。

只推进已经登记的工单，不自动创建 Jira 需求、不擅自领取其他研发的工单、不自动同意业务方案。一次主动请求不会在失败或结果不明确时无限重试，需要核对后手动恢复。

阻塞与多渠道提醒

待决策事项显示在席位管理；侧栏显示待处理数量。macOS 提交系统通知，按保存的间隔重复提醒，超过升级时间显示“超时升级”。通知是否实际弹出取决于系统通知权限和专注模式，窗口打开和网页提醒仍可查看。

浏览器支持系统通知且满足权限条件时，可点击 启用浏览器提醒；在普通 HTTP IP 地址上浏览器可能不提供该能力。网页内提醒始终可用。

钉钉使用网站保存的席位通知配置，旧 Harness 工单通知配置作为已授权的兼容路径。新接收人或群需要单独指定，系统不从席位登记中猜测收件人。真实工程确认仍通过 Jira；模拟确认只影响模拟 state。

新电脑接入向导

管理员点击 接入新电脑 → 高级 SSH 接入：先选择尚未绑定席位的独立 Agent 和已配置的 SSH 环境，填写那台电脑的 Harness、接入桥、Claude 与设置路径；可指定获授权的网站用户 ID，留空为当前管理员。

生成邀请并下载接入桥。邀请有效 15 分钟、只能使用一次，不会复制现有席位的凭证。新电脑准备 Harness、Claude 和 Jira 凭证，然后运行：

chmod 600 /绝对路径/paperclip-seat-invitation.json
/usr/bin/python3 onboard.py --invitation /绝对路径/paperclip-seat-invitation.json --jira-credential-file /绝对路径/jira-access.json --repository-root /本机业务源码根目录 --install-watcher

邀请中的桥安装位置必须与实际解压位置一致。成功后保存 0600 本机凭证，登记 Claude，配置 Harness 的桥路径并安装当前用户的后台监督进程。Jira 凭证不会从网站下发，需由研发电脑独立配置；本机仓库仍通过 harness repo bind 绑定。

同一组织内一台机器不能重复绑定两个执行 Agent。已有本机接入配置时安装器拒绝覆盖，应复用原席位或由管理员核对迁移。SSH 通道本身仍在“执行环境”中配置。

钉钉机器人通知

管理员在席位管理页展开“钉钉通知机器人”，添加企业内部应用机器人的名称、CorpId、AppKey、AppSecret 和 RobotCode。应用需启用机器人、开通单聊消息发送权限，并发布到负责人的可见范围。AppSecret 加密保存于平台服务器，不下发研发电脑。

席位负责人进入“通知”，先选择管理员登记的发送机器人，再打开接收人下拉框，输入姓名、部门、组织或钉钉 ID 关键词检索同企业人员。支持空格分隔多个关键词、上下键选择与回车确认；搜索无结果时检查关键词和人员联邦同步。设置提醒间隔和超时升级时间后，点击“保存通知设置”生效。由本机接入桥上报阻塞状态，平台服务器以机器人身份发送消息，本机无需登录个人 DWS。

“最近机器人投递”区分发送中、钉钉已受理、发送失败和结果未知。已受理不代表已读；未知结果不自动重发同一条消息，后续提醒周期会产生新的提醒。停用机器人会停止所有引用它的席位的钉钉提醒，网站和本机系统提醒仍可使用。旧个人账号配置不会自动转换，需要选择机器人并保存。

接单范围：工单状态与工单类型

工单状态决定什么时候允许接收及继续执行，例如“待编码”“编码中”；工单类型决定 Agent 接收哪类工作，例如“编码”“线上问题”“系统设计”。这两组条件与经办人、项目一起生效，必须全部满足。

  1. 先验证 Jira 连接，获取真实状态。
  2. 在“工单状态”中搜索关键词、勾选状态。列表可滚动，最多选择 1000 个；上方展示全部已选状态，点击 × 可移除。搜索不会清除已选项。Jira 状态可能来自其他项目流程，请按团队实际工作流选取。
  3. 在“工单类型”区域选择工作类别。状态和类型分别至少选择一项。
  4. 查看“当前接单范围”摘要，补齐条件后重新预览匹配工单，再保存规则。预览只查询、不执行。

例如经办人为 liw2386，类型为“编码”，状态为“待编码、编码中”：只接收该经办人的编码工单，且当前状态必须是待编码或编码中。工单未完成但不在所选状态内仍不会开工。高级手工填写状态名称与复选框同步，不用重复配置。仅保存配置不等于启用自动执行，还需勾选自动执行授权。

已有席位更新客户端

进入席位详情 → 设备与诊断 → 本机接入桥，查看本机最近心跳版本和网站当前版本。席位负责人或管理员点击“更新客户端”，选择实际操作系统，复制命令到原注册电脑、原操作系统用户的终端执行，无需创建新席位或生成新接入码。HTTP 网站可能无法自动复制，可选中命令后按 ⌘C / Ctrl+C。

更新器校验网站和席位身份，下载并校验 SHA256 安装包。有活动运行、待响应会话或本机启动请求时拒绝升级，处理完成后重新执行。升级保留原席位身份、Jira/PAT 引用、项目仓库映射及本机模型配置；先备份配置，再切换版本目录与当前用户后台服务。失败时恢复原配置，并提示服务恢复结果。不要关闭执行中的 Claude 来强行更新。

更新后等待席位重新上线，确认两边版本一致。新启动的已登记工单使用新版会话采集；更新前的独立会话和历史记录不会自动补采。离线时显示的是最后收到的版本，不能证明升级成功。旧 SSH 席位也使用同一更新命令：校验原席位凭证和机器指纹后，保留原席位、负责人、历史工单、仓库和本机模型配置，同步迁移为本机主动连接，不需要新接入码。切换期间服务端暂停派工，待本机配置和后台服务就绪后恢复。网络中断且结果无法确认时保留迁移记录及暂停状态，恢复网络后重试同一命令即可继续；不要删除配置或重复注册。旧 SSH 执行环境保留，其他席位不受影响。

Harness 框架仍通过原 Git 仓库更新，本操作只更新接入桥，不会自动拉取或修改 Harness 技能、模型密钥和业务代码。手工运行 watch 的电脑需先自行停止空闲 watch；使用 --no-service 的自定义配置须按更新器提示手工启动。

四个日常命令

命令场景
harness online启动接入服务并恢复本机接单
harness offline暂停新任务，现有运行和人工决策结束后安全下线
harness doctor检查服务、网络、Claude 和席位登记
harness upgrade获取网站最新安装器，保留原席位更新接入桥

三个系统使用相同命令。已有电脑首次须从网页“设备与诊断 → 更新客户端”复制完整命令更新一次。使用工程内 Harness 入口的电脑还需按团队流程更新框架。

安装器默认设置登录自动启动；主动 offline 的暂停标记会跨登录保留，执行 online 才恢复本机接单。网页原有暂停不会自动解除。有活动任务时显示“本机暂停／待下线”，不会中断 Claude；断网无法确认任务结束时保留服务重试。退出后超过 90 秒无心跳显示离线。

原开发环境诊断用 harness doctor --environment，原 --repo 参数保留。自定义配置升级用 harness upgrade --config <路径> --no-service，自定义配置服务仍需手动启动对应 watch。

钉钉超时升级为 DING

在席位的“通知”页选择企业机器人和接收人，配置普通提醒间隔与“DING 升级（等待分钟）”。默认普通提醒间隔为 10 分钟，持续等待人工处理达到 30 分钟时，升级发送一次应用内 DING；计时从本次待处理事项开始。

同一次等待只升级一次。处理完成后停止，新待处理事项重新计时。发送前重新核对任务归属和最新在线心跳；席位离线时不根据过期状态发送。DING 的已读或确认不代表业务决策已处理。

投递记录区分普通消息和 DING。机器人需有 DING 接口权限；缺少权限时显示失败，不改用个人账号或其他机器人。投递结果未知时不会盲目重发。不发送短信或电话 DING。

接收接口联调工单

在席位 → 接单设置 → 工单类型中勾选“接口联调”，保存后重新核验或派单。已有席位不会自动扩大接单范围。接口联调使用本机 Harness 的 dsp-integration-test 技能；已有电脑需在“设备与诊断 → 更新客户端”更新接入桥，Harness 工程也须包含该技能及 check_integration_execution_plan.py。

接口联调按独立 integration 工作流登记，领域资料位于 tickets/integration-工单号/，继续使用独占工作树。先按技能确认测试环境、账号、执行路径及范围，再执行联调；派单不代替这些确认。完成时核验联调上下文、报告、已批准范围门禁，以及原有 Tracker、Jira 和工作树证据；有限范围验收记为 partial，不表示全链路通过。

管理员跨席位派单

实例管理员及本组织管理员可以在平台向所选席位派单，无需把自己设为席位负责人，也无需改写原申请人。系统记录管理员派单授权，本机通过服务端核验后接入；原席位负责人继续接收阻塞通知。普通成员仍按席位授权范围操作。项目、仓库、Jira 状态与经办人、单执行器及联调环境等校验继续生效。已有客户端需更新接入桥，才能识别管理员的平台派单授权。

登录电脑后自动上线

“接入研发电脑”默认勾选“登录电脑后自动上线（推荐）”。执行接入命令时会安装当前用户的后台服务、启用登录启动并立即启动连接；安装完成后核验服务的启用状态及运行状态。Windows 使用当前用户的登录计划任务，macOS 使用 LaunchAgent，Linux 使用 systemd 用户服务。需要登录该电脑用户，才能打开可见 Claude 终端。

不勾选时，命令使用 --no-service（Windows 为 -NoService），不安装后台服务，也不会停用已有服务，需按终端提示手动运行接入桥。已有席位更新客户端后会补充核验；在“设备与诊断 → 登录后自动上线”查看最近一次上报结果。旧客户端未上报时显示未知，离线时显示最后一次检查，不能证明电脑当前状态。

执行 harness online 可修复并启动本用户后台服务；异常时用 harness doctor 查看原因。harness offline 的手动下线意图仍保留，需要再次 harness online 才恢复接单。自动上线不会跳过派单授权，也不会自动恢复已阻塞的任务。

删除旧席位（仅管理员）

在席位管理的运行工作台选择旧电脑，点击详情顶部“删除席位”。电脑需已下线或卸载客户端，并等待网页显示离线；有排队、执行中运行或未结束任务时，先结束运行并完成、取消或转派任务。只有本组织管理员、组织所有者或平台管理员可以删除，普通负责人不能删除。

确认框输入完整席位名称后删除。此操作永久删除席位对应的智能体、运行记录、所发评论和接入凭据，不会卸载电脑客户端。需要再次接入时，由管理员重新生成有效的接入命令。

同时通知钉钉群并 @ 席位负责人

  1. 管理员在目标群添加“自定义机器人”，启用加签，取得 Webhook 和 SEC 开头的加签密钥。负责人应已加入该群。
  2. 打开“席位管理 → 接入与管理 → 钉钉通知群”，填写群名称，选择群所属企业的已登记机器人，填写 Webhook 和加签密钥后保存。密钥加密保存；编辑时两项留空保留原值，更新时同时填写。群所属企业须与机器人一致。

Harness 登记与故障排查

选择本机 Harness 目录、查看套件详情，以及在无图形界面或登记失败时使用备用命令。

什么时候使用
  • 首次登记研发、需求分析或测试 Harness
  • 更换 Harness 目录或更新套件版本
  • 无图形桌面时手动指定路径
  • 登记失败或网页没有显示套件详情

日常登记：使用卡片按钮

  1. 打开“席位管理 → 对应席位 → 设备与诊断”，需要配置权限才能登记。
  2. 首次使用目录选择功能前，在“更新客户端”中完成一次客户端更新。
  3. 在对应 Harness 卡片右侧点击“登记／更新登记”，生成并复制命令。用途和席位已自动绑定。
  4. 在该席位电脑执行命令，在系统文件夹选择框中选择 Harness 的 Git 根目录，目录应包含 CLAUDE.md 和对应技能。
  5. 校验通过后自动保存，网页约 5 秒更新；也可点击“刷新能力登记”。展开“查看套件详情”核对路径、仓库、技能和版本。

取消选择不会修改登记。登记不会自动派单；测试登记本身不授予执行权；需在条目自动交付流程选定该席位并授权启动，客户端也需更新。运行或等待人工决策期间不能更换登记。

备用方式：手动指定目录

适用于无图形桌面的 Linux 或需要明确填写路径的场景。在对应席位电脑执行，将示例路径替换为真实 Harness Git 根目录；路径含空格时保留引号。Windows 使用带引号的本机绝对路径。

需求分析 Harness（DSP）：

harness capability register --kind analysis --profile dsp --path "/本机路径/分析Harness"

研发 Harness：

harness capability register --kind development --path "/本机路径/研发Harness"

测试 Harness：

harness capability register --kind qa --path "/本机路径/测试Harness"

这些命令使用当前电脑的席位配置。优先使用卡片生成的带 --seat-id 命令，避免在错误席位登记。同一席位可登记多类套件，无需划分席位职责类型。

查看登记与重新检查

查看登记：

harness capability list

重新检查本机文件：

harness capability check

套件文件或版本变化后，在席位空闲时重新登记。默认研发目录的详情来自设备登记；完成能力登记后才会显示已上报的仓库、技能、Git 版本及文件摘要。

常见问题

  • 找不到 harness 命令或不支持 --choose：先按客户端更新指引更新，再打开新终端重试。
  • 没有弹出文件夹选择框：确认在该席位电脑的图形桌面执行；无图形桌面时使用上面的 --path 方式。
  • 席位不匹配：在目标席位生成命令，并在它对应的电脑执行，不要删除 --seat-id 来绕过检查。
  • 目录或文件校验失败：检查是否选择了 Git 根目录，以及 CLAUDE.md、领域技能和套件配置是否完整，按终端提示修正。
  • 任务正在运行或等待决策：先处理现有任务，席位空闲后再更换登记。
  • 网页没有更新：确认终端提示登记成功，再点击“刷新能力登记”；显示刷新失败时，恢复平台连接后重试。

什么时候使用
  • 研发过程需要透明化

进入运行记录

建议查看顺序

  1. 确认关联任务和智能体，避免把其他工单的运行当成当前执行。
  2. 看开始时间、结束时间、耗时和结果。

Token 和费用有什么限制

当前交互式 Claude 接入可从 Claude 持久化记录中提取可用的用量，并按消息编号去重。没有来源时应该显示未知，而不是当作零。

停止和取消是执行控制操作，不是常规审批按钮。先查看任务和本地会话状态；服务端运行结束不总能证明本地进程已经消失。重试前确认旧执行者停止，并采用现有工单的正规续传入口。不要通过新建同一 Jira 的任务来规避锁。

费用页面怎么读

预算怎么用

预算用于限制智能体、项目或组织的支出。触发硬上限时可能暂停执行。管理员应核对用量和业务优先级，再决定提高预算、调整范围或保持暂停。

  • 负责人比较同类任务的 Token 消耗和执行耗时，寻找 Harness 知识不足或重复尝试。
  • 管理员为试点设置费用上限，出现预算事件后先复核，再恢复执行。

  • 概览和运行：查看任务、活动运行及历史结果。

正式任务复用 Harness 原生启动环境（2026-10-24）

新版接入桥从席位登记的 Harness 根目录启动正式 Claude 会话，目标等同于 cd <Harness 根目录> && claude 后输入“完成 ATSES-XXXXX 工单”。Claude 原生读取 CLAUDE.md、.claude/skills/ 和 user / project / local 配置来源。.claude/settings.json、.claude/settings.local.json、.mcp.json 按存在情况加载。认证与 MCP 凭据保留本机，不上传配置内容。外部显式 settings 仍按 Claude 合并优先级生效。

启动提示要求查询 Jira 真实类型，按 Harness 路由选择技能，并遵守断点续传和领域门禁。平台补充派单身份、执行权、采集与回传信息。相同加载环境不保证模型每次选择和输出完全相同。

启动目录与源码目录分开：Claude 在 Harness 根目录启动；代码仍在本工单登记的源码目录 / 独占工作树修改，通过 --add-dir 提供访问。不会因切换启动目录创建或替换源码目录，也不免除独占校验。

启动前检查引导、技能目录、可选 JSON 配置与源码路径；缺失、格式错误或显式限制配置来源时明确阻塞，不自动换目录。诊断通过不代表 MCP 网络、认证或技能实际调用已验证。--strict-mcp-config 和限制 --setting-sources 的配置与此模式冲突时拒绝启动，需要核对配置。

已有席位如何使用：席位详情 → 设备与诊断 → 更新客户端，在原电脑、原注册用户下空闲时执行更新命令。保留席位身份、负责人、接单规则、仓库映射与历史；执行中、排队启动或等待决策时更新器拒绝更新。更新后核对“正式任务启动方式”，下一次正式会话生效；旧会话不改目录、不被接管。旧客户端保持原行为，模拟任务保留隔离目录。

需要回退时，由负责人在本机接入桥 config.json 设置 "claude_launch_mode": "legacy-source"，空闲后重启桥，仅影响随后新会话。删除该字段或设置 "harness-root-v1" 恢复默认；兼容模式会明确显示，不会静默降级。

哪些变化会生效

  • 智研协同平台 新增或启用技能：通常在下一次运行准备技能提示包时生效。当前会话不会自动热更新；技能或指令版本变化可能影响旧会话复用。
  • Harness 修改技能或知识：修改的是本机工程文件，按 Git 共享。下一次运行应使用更新后的工程；当前会话可能已有旧内容，不能假设会自动重新读取。
  • 两处内容不会自动同步：修改网页技能不会修改 Harness 仓库，修改 Harness 技能也不会自动更新网页技能库。
  • 发现不等于执行：进入技能清单只说明可用；任务还需要触发、路由或明确调用。已加载技能不等于通过领域验收。

智研协同平台 的自定义技能运行名可能带消歧后缀，例如 shared-skill-load-probe-20261006--8b6db90b1c。需要明确调用时，以当前会话技能清单中的实际名称为准，不要假设名称始终等于网页 slug。

例行任务适合周期性检查、汇总或复盘：设置执行者、指令和触发计划，观察实际生成的执行任务及运行记录。启用计划前应核对 Agent、权限和预算。

流水线和业务案例

流水线用于定义阶段和步骤；业务案例用于跟踪一类工作通过不同阶段的过程。适用于固定的评审、处理或运营工作。相关页面可能受实验开关控制。

与当前 Jira／Harness 的边界

这些平台功能不会天然同步 Jira 的需求拆分和状态，也不会自动调用本地 Harness 工单流程。把“接入 → 开发 → 评审 → 交付”设计成全自动流水线，还需要具体集成和验收。当前已交付的是网页定向登记和本地主动执行，不是全部自动调度。

  1. 打开登录页，输入企业邮箱与初始密码 12345；使用用户名时勾选“企业人员账号”。

初始化密码只属于 智研协同平台，与钉钉、企业微信和企业邮箱密码独立。角色默认是普通成员，席位创建等权限仍由管理员授权。

快速入门

Windows 新电脑首次接入与原席位更新

从环境准备、管理员生成接入命令，到本机安装、仓库绑定和在线验收；原电脑更新复用已有席位。

什么时候使用
  • 给一台 Windows 新电脑首次接入平台
  • 原电脑重新上线或更新接入桥
  • 排查接入成功但不能接单的问题

一、先区分首次接入和原电脑更新

  • 新电脑首次接入：管理员在网页为这台电脑生成一次性接入命令，选择实际负责人。每台电脑使用独立身份和凭证。
  • 原电脑重新上线或更新：打开原席位的“设备与诊断 → 本机接入桥 → 更新客户端”，复制 Windows 专用命令，在原 Windows 用户下执行。命令包含原席位的 AgentId，复用已有身份。
  • 不要把另一台电脑的配置或凭证复制到新电脑。更换 Windows 用户后，先确认是否仍能使用原用户的本机配置；全新环境走首次接入流程。

二、新电脑准备环境

准备 Windows 10 1809+ 或 Windows 11、Python 3.10+（含 pip）、Git for Windows（含 Git Bash）、已配置并可实际调用模型的 Claude Code，以及 Harness 和业务仓库。使用原生 PowerShell，无需 WSL。

在负责人的 Windows 登录用户下打开 PowerShell，执行：

py -3 --version
py -3 -m pip --version
git --version
claude --version
Test-NetConnection 10.60.43.53 -Port 3100

如果 Python 通过 python 安装而没有 py 启动器，可改用 python --version、python -m pip --version。版本应满足要求，端口检查应显示 TcpTestSucceeded : True；无法连接时先接入公司网络或可访问该服务器的 VPN。

在 Harness 目录中先确认 Claude 能正常启动和访问模型，再退出该测试会话。Harness 版本需要支持终端执行入口；缺少入口时先按团队方式更新 Harness 仓库。接入桥更新不会自动 Git 更新 Harness 框架。

支持原生 claude.exe；官方 npm 安装的 claude.cmd 会解析为 Node 与 CLI JS 入口，Node 版本遵循 Claude 自身要求。本机 Harness 的 .claude/settings.local.json 存在时沿用，否则使用 Claude 默认配置，无需在网站重新填写模型 Key。

三、管理员在网页生成本机专用命令

  1. 打开网站侧栏“席位管理”，点击“接入新电脑”。
  2. 在“接入研发电脑（管理员）”中选择实际负责人，例如为范天星的新电脑选择“范天星”。
  3. 选择 Windows（原生 PowerShell），填写能区分设备的名称，例如“范天星-Windows研发电脑”。
  4. 生成并复制完整接入命令，交给该电脑负责人执行。接入码有有效期且仅能消费一次，过期或已使用时重新生成。

帮助文档不提供固定共享接入码；请使用网页当次生成的完整命令。

四、负责人在新电脑执行

  1. 使用本人日常开发的 Windows 用户打开 PowerShell，进入本机 Harness 根目录。例如：
Set-Location 'C:\work\base-harness-infrastructure'

以上是示例路径，请替换为实际目录。

  1. 粘贴网页生成的完整 PowerShell 命令并执行。它会下载安装入口、检查 Python，并安装接入桥；缺少终端依赖时，通过 pip 安装 pywinpty>=2.0.15,<4 的预编译 wheel。企业网络需要允许所配置 pip 源，或提前准备批准的 wheel。
  2. 根据提示核对 Harness 根目录、Claude 可执行文件、设置文件和电脑名称，确认无误后按提示输入 yes。不要把业务仓库目录误选为 Harness 根目录。
  3. 按提示选择业务仓库与平台项目的对应关系。没有完成的绑定可在安装后执行 harness repo connect 补齐。
  4. 安装成功后关闭当前 PowerShell，重新打开，让用户 PATH 中的 %LOCALAPPDATA%\ZhiyanSeat\bin 生效。

五、验收：本机与网页都要检查

重新打开 PowerShell 后执行：

harness doctor
harness online

回到网站刷新“席位管理”，确认：

  • 负责人和电脑名称正确，心跳已更新，席位在线。
  • “设备与诊断”中的 Harness／Claude 路径正确，接入桥版本符合网站提示。
  • 项目与本机业务仓库映射正确，缺失时执行 harness repo connect。
  • “接单设置”中的项目范围、派单规则和接单开关符合预期。harness online 不会自动解除网页上的暂停接单。
  • “通知”中的负责人和钉钉通知配置符合预期。接入成功不等于已经验证钉钉投递。

先用团队授权的验证工单检查网页派单、本机终端启动和执行回报，再启用正式自动执行。

六、原电脑更新与日常使用

原电脑更新时先确认没有正在运行、等待人工决策或排队启动的任务，再使用原席位“更新客户端”给出的命令。不要为更新重复创建席位。

若仅 Claude 版本、路径或设置文件发生变化，在任务空闲时重新登记并检查：

后台运行与边界

安装器创建当前用户的 Zhiyan-Seat-Bridge-<用户SID> 计划任务，以交互登录身份、普通权限在登录时启动，并立即启动本次接入；不保存 Windows 密码，不安装 SYSTEM 服务。必须保持该 Windows 用户已登录，退出登录、休眠或断网会导致席位离线。

使用 -NoService 时不创建计划任务，按安装器输出的命令手动运行。本机日志位于 %USERPROFILE%\.config\paperclip-dsp7-bridge\watcher.log。Windows 气泡提醒受系统通知设置影响；网页和钉钉是独立通知通道。

harness start、attach、seat、repo、status 和 knowledge 通过桥执行，其他子命令委托给登记的 Harness CLI。安装不修改 Harness 源码；业务技能使用的 Shell、Maven、MCP 等仍需在本机准备好。Windows 原生流程仍需按上述步骤做实机验收。

分析完成后自动保存轻舟

绑定轻舟条目的分析完成后自动保存正文，单独展示回写结果并支持重试。

什么时候使用
  • 希望把席位分析结果自动更新到轻舟
  • 轻舟保存失败，需要核对账号或补齐业务字段
  • 分辨内容保存与正式业务评审

自动保存的条件

管理员在“需求分析”创建任务并填写已纳管的轻舟条目号，核对轻舟分析保存参数后派发。当前版本通过 P0–P4 和真人质量评审后，平台自动把 analysis.md 正文保存到轻舟，回读内容一致才显示“已保存并回读核验”。未绑定条目不触发回写。

每个席位在“席位管理 → 具体席位 → 接单设置 → 轻舟账号”独立配置账号和密码，由席位负责人或管理员维护。密码加密保存，不回显、不交给模型。可检查已保存账号的登录状态，登录成功不代表具备所有条目权限。分析回写使用执行席位账号，须具备该条目分析负责人的保存权限。未配置、账号不匹配或失效时保留本地成果并提示修复后重试，不会借用项目来源账号，也不会擅自变更条目负责人。项目来源账号仍用于项目数据同步。

业务字段

保存优先使用明确填写的参数，其余沿用轻舟已有值。缺少业务共性时默认共性业务，缺少工时默认 1 小时，缺少日期取本次运行的上海时区起止日期。默认工时是保存参数，不是实测工时。创建时可修改，失败后也可在重试表单补齐。轻舟可能按业务共性重新分配评审人，请核对。

失败如何处理

在分析任务详情的“轻舟分析内容回写”查看错误。管理员可修改参数后点击“重试保存轻舟分析”；只处理已冻结交付，不重启模型。响应丢失时先回读，已保存的一致版本不重复写入；来源内容已被修改时停止覆盖，请核对后建立新修订。未纳管条目需先在当前项目同步。

本地成果会保留，保存失败不显示为成功。正文超过 120 KB 或疑似包含凭据时需要先整理、脱敏并重新核验。升级服务端和页面后，还需更新席位客户端才能上传分析正文；旧客户端已有成果需补传完全匹配的版本，或建立新修订重新分析。

内容保存与正式发布

自动保存仅上传分析正文，其余原始材料留在本机。自动保存不自动申请评审、不代替轻舟业务审签，也不表示交接包已正式发布。正式发布仍先按正式流程核对材料，再在网页登记来源链接与版本。
