# 席位并发执行

在“席位管理 → 运行工作台 → 选择席位 → 接单设置 → 并发执行”设置最大并发工单数。每个席位独立，默认 1，支持 1–50 的整数。席位负责人和管理员可修改。

启用多个并发前，先升级本机主动连接客户端并等待新心跳。旧客户端和 SSH 接入继续串行；配置接口会拒绝在这些客户端上启用多个并发。能力降级时有效上限回到 1。

工单获得派单授权后进入队列。超过并发上限时等待，空出名额后由后台继续调度。未领取的启动请求不会因排队超过 15 分钟自动过期；进入本机确认和启动阶段后沿用 15 分钟超时保护。可在操作记录取消排队请求。运行请求仍须通过原有工单准入、负责人、暂停、预算、审批和仓库核验。

执行中、等待人工决策及已领取待启动的工单都占用名额；已结束但进程退出尚未核验的任务也不释放名额。调低上限时已有运行继续，在占用量低于新上限后才启动新工单。同一工单不能建立两个执行者。

页面展示全部活动运行，单独打开各工单可处理其决策或停止该运行。暂停接单保留已有运行。并发运行仍使用原有 Harness 仓库与工单隔离规则；共享工作区的串行策略可能进一步限制实际同时执行数。

实现复用现有 JSON 配置，无数据库迁移。服务端与客户端必须一同升级；无需手动修改本机配置文件。
