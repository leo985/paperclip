# 席位并发执行

在“席位管理 → 运行工作台 → 选择席位 → 接单设置 → 并发执行”设置最大并发工单数。每个席位独立，默认 1，支持 1–50 的整数。席位负责人和管理员可修改。

启用多个并发前，先升级本机主动连接客户端并等待新心跳。旧客户端和 SSH 接入继续串行；配置接口会拒绝在这些客户端上启用多个并发。能力降级时有效上限回到 1。

工单获得派单授权后进入队列。超过并发上限时等待，空出名额后由后台继续调度。未领取的启动请求不会因排队超过 15 分钟自动过期；进入本机确认和启动阶段后沿用 15 分钟超时保护。可在操作记录取消排队请求。运行请求仍须通过原有工单准入、负责人、暂停、预算、审批和仓库核验。

执行中、等待人工决策及已领取待启动的工单都占用名额；已结束但进程退出尚未核验的任务也不释放名额。调低上限时已有运行继续，在占用量低于新上限后才启动新工单。同一工单不能建立两个执行者。

页面展示全部活动运行，单独打开各工单可处理其决策或停止该运行。暂停接单保留已有运行。并发运行仍使用原有 Harness 仓库与工单隔离规则；共享工作区的串行策略可能进一步限制实际同时执行数。

实现复用现有 JSON 配置，无数据库迁移。服务端与客户端必须一同升级；无需手动修改本机配置文件。

## 分析任务取消后的恢复（2026-11-12）

取消后不会自动重启分析。管理员再次显式派发时，服务端可使用已认证的完整进程树停止、进程退出和许可撤销回执完成旧运行停止核验；仍有活动进程、未清理租约、机器身份变化或其他恢复拦截时继续拒绝。旧操作结果未知的记录保持不变。

派发被跳过或失败且没有实际运行或持久排队请求时，页面显示中断原因，不再持续显示排队；相同请求编号复用已有运行。若本机 Harness 文件或版本变化，须在对应席位空闲时通过 `harness capability register` 重新核验登记，然后显式恢复；重启席位不会代替能力登记。


### Harness 空闲自动登记

支持自动登记的客户端每 60 秒在空闲时核验已登记 Harness；同一仓库、目录、profile、协议和能力角色内的文件摘要或版本变化自动登记，服务端沿用席位锁、机器认证、登记修订及无活动运行检查，并记录新旧版本摘要。正在运行或等待人工响应时暂缓；不自动启动或重放任务。更新与派发竞争时仍可拒绝本次启动，待登记完成后显式恢复。自动登记是内容身份检查，不保证任意更新的业务语义兼容，也不是运行目录快照。


### 分析轻舟原件采集

网页配置的席位轻舟账号可由当前授权分析运行的本机只读辅助程序使用。平台只核验并提供认证引导；登录、正文与附件下载和原生证据归档都在客户端进行，不将附件流量放到服务端。不得将账号响应写入任务材料或把账号、密码、Token 作为模型输入；冻结交付后不再接受新的采集认证申请。
