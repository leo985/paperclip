# P1 独立需求分析闭环实现与验收

日期：2026-10-25。范围：智研协同平台、本机接入桥、已登记的 DSP 分析 Harness。已于 2026-10-26 发布生产，核验记录见 [生产发布记录](2026-10-26-p1-analysis-production-release.md)。

## 使用流程

交付工作台／条目交付 → 独立需求分析 → 选择项目 → 创建分析记录 → 管理员明确授权派发 → 在线席位领取真实运行 → 本机可见 Claude 加载分析技能 → 网页答复与当前版本质量评审 → 原生交付核验及产物索引 → 人工登记正式发布。

创建分析记录不启动模型，不要求虚构 Jira 编号。分析 Harness 在本机通过 `harness capability register --kind analysis --profile dsp --path <目录>` 登记；同领域多个套件必须选择路由。老客户端需更新，协议能力为 `analysis-execution-v1`。原有研发根目录、席位身份与已登记 Jira 任务不迁移。

本机 Claude 从登记的分析 Harness 根目录运行，加载 `dsp-requirements-analysis`（通用 profile 为 `requirements-analysis`）；恢复加载 `analysis-resume`。原生任务 ID 为 `pc-<平台任务UUID>-r<修订>`，文件位于该分析套件的 `工单/analysis-<原生ID>`，恢复不得重新 init。

## 运行与权限

- 使用原生 issue、heartbeat run、真实出站领取、执行许可、预算准入、进程树停止证明、用量账本及受管会话；不增加第二套模型调度器。
- 创建和派发由组织管理员授权，席位负责人可查看本席位分析及回答问题、停止运行。组织间数据隔离；历史负责人和所选席位固定。重新分派不自动接管本机材料。
- 授权绑定运行、派发编号、授权人、机器、能力 ID 和能力登记修订。权限、席位、执行环境、预算或路由失效时停止续租；未知停止状态不允许盲目替换旧执行器。
- 接入桥常驻心跳领取独立运行，不依赖 Jira pilot；桌面终端连接同一 PTY。没有可用终端时模型不会隐形启动。新增本机 `attach-run <运行UUID>` 仅连接已存在、存活的本机会话，不创建模型或授权。
- 模型工具权限仍由本机 Claude 配置管理；网页业务答复不代替工具权限。网页对话来自受管采集记录，保留原任务的正文权限及采集缺口说明。

## 决策与状态

- 网页显示原生 P0–P4、实际门禁错误，不根据文字输出推算百分比或完成状态。运行终止但未交付显示中断，可核验后恢复。
- Stop hook 收集原生 requirements.json 的开放阻塞问题；正常空闲不伪造业务决定。P3 产生当前输入指纹的质量评审问题。
- 答复绑定问题、运行、输入摘要与内容摘要，记录实际操作者和时间。同一 Claude 会话领取后继续，无须 `/exit`。已保存、已送达、已失效与领域门禁通过分别展示。
- 送达 ACK 幂等；本机答复回执可恢复网络中断。输入或问题变化后旧决定失效，不把上一版本批准复用于新材料。
- 网页“批准此输入版本”才写入对应 review.json 的评审人、时间和摘要；服务端收集交付时独立要求同一输入摘要的已送达批准记录，不能仅相信本机自填 review。
- 等待决定通过席位状态和告警上报；沿用本机通知及网页已配置的服务端钉钉机器人提醒策略。验收不发送钉钉消息。

## 产物与正式发布

七项索引：intake.md、evidence.json、requirements.json、analysis.md、review.json、handoff.md、state.json；每项记录 SHA-256，另存输入指纹和 handoff 指纹。采集前后重验原生门禁与文件指纹，交付冻结后不可覆盖。

原始客户材料仍在本机，索引不是共享交接包。正式发布需要负责人先按 Jira／轻舟正式流程发布交接材料并核对访问权限，管理员再登记来源链接、版本摘要和核验说明，明确标记 `manual-attestation`。只接受不带凭据或查询参数的正式 Jira／轻舟来源链接。登记不调用上游上传／发布 API，没有来源自动回读，不自动触发研发派单，也不代替轻舟正式业务审签。

已发布／已交付后变更必须新建修订和独立任务目录；旧产物、决定与正式记录保留。缺少经验证的轻舟写入和版本回读契约前，不宣称“自动正式发布”完成。
