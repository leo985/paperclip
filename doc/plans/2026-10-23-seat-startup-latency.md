## 实现

1. 已登记、在线、空闲、登记有效的席位，平台派单／恢复事务直接创建持久指令；授权 ID 作为幂等 commandId。复用原有创建校验、席位事务锁、任务独占登记与授权检查。未准备、忙碌、离线等情况保留授权队列。
2. 新增独立的出站长轮询线程：每次最多等待 18 秒，服务端每秒读取持久队列。身份与组织检查、连接上限、已知指令游标、断开清理、失败退避；不持有事务或数据库连接等待锁。多实例仍从数据库获取指令。
3. 线程独立 SQLite／API 对象；与心跳通过 delivery.lock 和 opened 标记串行交接。主循环优先心跳，补传及统计后置。独立通道不执行采集和通知；收到 auto-request 返回的指令立即交接。
4. 升级读者使用共享锁，安装器维持独占锁和空闲保护。Windows 使用 LockFileEx 字节范围共享／独占锁；监督进程退出时线程随进程退出，无额外后台子进程。
5. 回执增加运行环境核验、Jira／仓库核验、真实运行请求阶段。服务端按当前授权隔离历史轮次，网页展示累计耗时；连接终端不表示模型已响应。阶段回执为尽力上报，接受与启动门禁仍强校验。

## 发布与边界

- 不涉及数据库迁移，不启动演练任务，不终止现有 Claude。
- 仅发布本次涉及的两个后端路由、UI 构建及客户端包，不覆盖其他预存修改或迁移。
- 发布前确认平台无活动运行；客户端更新前确认本机无活动会话。忙碌时延后，避免普通服务重启触发运行排空。
- 新通道需要新版客户端；旧客户端兼容心跳领取。
- 编译、类型与 token 静态检查不等同于真实恢复性能验收；新轮次的页面耗时用于后续实测。Windows 共享锁需要 Windows 实机验收。
