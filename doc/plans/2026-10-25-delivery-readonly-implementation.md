# 条目只读纳管：首批实现与验收

日期：2026-10-25。范围：I1 的手工快照纳管与跨来源结构差异；不是 W00–W10 全部完成。

## 已实现

- 新增公司、项目隔离的 `delivery_snapshots` 关系表及生成迁移 `0288_keen_penance`；保存不可变版本、采集时间、标准化主子工单结构及来源内容摘要。
- `GET /api/companies/:companyId/delivery-intake` 按项目分页查看历史快照；`POST .../preview` 预览，`POST .../import` 核对指纹后纳管。组织管理员可导入，组织成员按原权限读取。禁止 Agent 凭证使用这些接口。
- 只接受明确标记的 `manual_snapshot`，来源为轻舟已知地址。没有发起外部网络请求，不保存浏览器 Cookie、Token、原始正文或附件；没有 Jira/轻舟写操作，也没有执行任务、派单或费用活动。
- 无损解析原始 JSON 长整数；区分业务 urid 与排期 issueUrid；核对真实父子关系。失败响应、截断分页、重复 Jira 身份、多月份排期矛盾均拒绝保存。
- 多月份相同排期步骤去重；展示 Jira 有而排期无、排期有而 Jira 未返回、作废/取消差异。不会据此自动判定替代关系或正式验收通过。
- 新增“条目交付”页面，入口在管理中心和 Jira 工单执行页面。支持项目选择、预览、保存、历史版本查看、分页及错误反馈。`/delivery-help.html` 提供在线格式与使用场景说明。
- 既有但尚未发布后端的 Jira 主需求导入组件由 `VITE_JIRA_REQUIREMENT_INTAKE=true` 显式构建开关控制；此次不开放其执行入口。既有单工单接入及席位流程继续沿用线上实现。

## 验证

- 18 个定向测试通过（来源归一化、路由鉴权/隔离/幂等/审计、原 Jira 主子单规划回归）。
- Shared / DB 构建、Server TypeScript 编译、UI 类型检查与生产构建通过；token gates 通过。
- 本机隔离 PostgreSQL 完整初始化并成功应用迁移，没有使用或覆盖本机业务数据库。
- Ego Browser 任务空间 79：真实上传 ATS3-00156、预览、保存、重复保存、刷新后从历史版本恢复；确认 3 主单、20 子单、18 去重排期、4 项差异和 23 行工单记录。
- 同一浏览器验证无效文件明确报错且保存按钮禁用；管理中心入口可进入新页面。
- 窗口最小化导致截图未能生成；上述功能验证使用真实 DOM、页面操作及持久化结果，不将其声称为截图视觉验收。

## 本批未实现

轻舟长期服务认证与在线定时同步；独立分析任务与多 Harness 能力登记；独立代码评审、QA 执行；版本化证据准入、范围授权与自动编排；新路径统一预算和远程停止治理。它们继续按[开发拆分](2026-10-25-unfinished-delivery-implementation-design.md)推进，当前界面明确标注未开放，不自动执行历史工单。

当前纳管对象是只读来源视图，尚未关联或创建平台 `issues` 执行实体。手工快照采集时间由上传者声明；不能用于实时调度准入。

## 发布方式

后台仅新增服务/路由、表及迁移，并对运行版本的路由挂载与 schema 导出做增量补丁；未将本机其他未提交后台改动打包。前端生产构建包含页面与导航。客户端桥安装包、清单和席位配置不变。

发布程序在服务器加锁、比对全部文件基线、确认无活动运行、备份文件及数据库，再应用唯一新增迁移并重启 `paperclip.service`。失败时回滚代码和静态资源；已成功应用的新增表及迁移记录保留，避免破坏新增数据。其他用户服务 PID 必须保持不变。
