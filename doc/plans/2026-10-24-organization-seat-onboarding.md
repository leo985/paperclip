# 组织创建与研发席位接入调整

日期：2026-10-24

## 目标与流程

创建组织只填写名称和可选说明，不再将组织建立与通用智能体、模型密钥、示例项目和示例工单绑定。保存后进入当前组织的 `/setup` 初始化清单：人员 → 项目仓库 → 研发席位及负责人 → Jira 接单规则 → 推荐通知。

初始化可分次完成。工作台和管理中心保留入口，旧组织 onboarding 链接转入清单；创建前可取消，创建后可离开再继续。无可见组织时按实例权限展示创建或联系管理员的提示。

## 对象和权限

组织是权限和数据边界，席位是研发电脑的执行入口，接入席位时登记执行智能体。独立通用智能体保留为高级入口。新组织不复制旧组织成员、席位和凭据；已有组织、智能体、席位及任务保持原状。

创建组织沿用后端实例管理员限制，初始化清单面向组织管理员，人员联邦入口仅实例管理员可见。新智能体审批策略保持生效，不因初始化自动关闭。

## 检查语义

复用组织范围的成员、项目和席位接口。只在清单页读取数据，短期复用缓存并提供手动刷新；不向工作台添加轮询。配置状态不代表真实执行验收，接口失败显示未知。PAT 配置状态不返回密钥；通知配置不代表发送成功。

项目仓库需要 URL 和基线分支；席位需要负责人、设备信息；接单还需可用席位、启用规则、PAT、经办人、状态、类型及对应项目仓库。完成统计是接入指引，不是替代执行授权的门禁。本机仓库绑定、在线空闲、单执行器和领域门禁仍由原流程校验。

## 发布及验证

仅构建并替换静态资源，无 API、数据库或服务配置变化，无需后端重启。保留旧哈希资源，发布前校验基线和备份，HTML 最后发布，发布后核对文件校验和、健康接口和服务 PID。在线帮助增加组织与席位关系及操作步骤。

执行 UI 类型检查、生产构建、设计 token 检查和差异空白检查。未创建真实组织或派发工单；未执行完整登录浏览器回归。发布结果见同日期 `organization-seat-onboarding-release.json`。
