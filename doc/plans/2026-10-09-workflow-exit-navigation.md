# 创建与配置流程退出交互

## 问题与设计

创建组织是覆盖当前 URL 的全屏 OnboardingWizard。此前移除了可见关闭按钮，并用普通 div 替代 DialogContent；首步 FooterNav 也没有取消入口。全局 dialog 状态未在浏览器历史导航时关闭，因此浏览器后退仍可能被旧向导覆盖。

统一规则：上一步只用于步骤回退；取消 / 返回用于退出整个流程；退出后回到进入向导时的页面及组织。未保存的输入退出前明确提示，已创建资源保留，不自动删除。不使用 navigate(-1) 作为唯一返回路径，直接打开页面也有确定的出口。

## 修改

- 组织向导：顶部常驻“返回并退出向导”，首步“取消并返回”；恢复 Radix Content 的焦点约束及 Escape 行为。
- 退出确认：未保存输入将丢弃，已创建组织、智能体、任务保留；可继续配置或退出。
- 保存中不重复退出 / 发起创建；离开向导后的异步结果不再绑定到已关闭的界面。
- 对话框打开时记录 returnTo；退出还原原组织，通过 route_sync 避免最近访问页面覆盖返回目标。
- 浏览器 Back / Forward 关闭全局创建对话框，不让旧向导覆盖目标页面。其他页面导航也关闭任务、项目、目标、智能体创建弹窗。
- 路由式 onboarding 关闭后可返回组织列表；没有任何组织时保留初始组织入口。
- 智能体创建页，以及组织导入、导出页，增加独立于加载、失败与完成正文的返回栏。
