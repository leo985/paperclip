# 交付链工作流操作闭环（2026-11-17）

交付链模板定义项目固有流程；启动授权创建实例，固定来源、模板版本、节点图和执行人。节点由人或 Agent 完成，前置不满足时只展示进度，不产生可处理人工待办。

## 本次实现

- 条目阶段及子工单列表统一导航至交付计划或已有节点，不再从这些列表独立派单。已有独立任务保留查看入口。
- 提供公司隔离的 `delivery-workflows/pending-actions?scope=mine|company` 投影。个人范围按实际操作负责人过滤；组织范围仅管理员可读。未激活、等待前置、已完成、已复用、已关闭及被退回的旧版本不生成办理待办。分析节点继续使用现有分析发布/提问待办。
- 人工工作、人工评审、Agent 交付核验、业务问题、启动确认、管理员恢复及正式验收分别投影，工作台优先使用实例待办，抑制普通任务状态产生的重复或虚假待办。
- `delivery-workflows/for-task/:taskId` 返回经授权的实例与节点上下文。任务页展示关联与当前操作入口，交付链页面定位到准确节点。
- 人工工作节点激活时任务状态为处理中，人工评审为待评审；实例保留已有兼容状态协议，界面区分待人工办理与待人工评审。
- 普通任务 PATCH 不能改写实例节点的状态或执行人；未授权节点不能通过普通 checkout 抢先执行。节点不能通过普通任务删除或释放，生命周期操作走实例接口。成果文件、对话等普通协作继续允许。
- 原有提交、评审、答复与确认接口仍执行人员权限、来源与交付版本校验；处理后待办随实例状态消失，后续节点由现有调度器激活。最终验收及恢复仍沿用现有管理员治理边界。
- 计划预览可以展示缺少评审的已知节点，实际启动严格拒绝缺少模板要求的评审，不再把席位延迟绑定选项作为放宽结构的开关。

## 边界

不改变项目模板，不自动接管已有独立活动任务，不启动真实 Jira 交付，不迁移数据库。已有纯人工交付、Agent 回执、并行汇合、版本核验和返工协议复用。席位通知规则保持现状；面向无席位人员的通知催办、授权转交和流程耗时统计为下一阶段能力，本次不声称已提供。
