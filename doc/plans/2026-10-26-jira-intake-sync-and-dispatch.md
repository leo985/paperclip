客户端补丁以静态包原子替换发布，不再重启网站。旧任务工作树需核验索引完整性；不得因目录存在直接覆盖其中人工工作。

真实验收继续发现：交互启动在产生模型运行前需分配执行身份，旧通用 PATCH 同样受到运行归属保护限制。新增 `dsp7-jira-intake/start-assignment`，只允许本机对已准备完成、有独占登记、原申请未变化且无活动运行的自身任务分配自身身份，写入审计；不修改领域状态、不生成运行，后续 wakeup、网页派单授权、预算和独占运行门禁仍独立执行。

网页新增“启动失败”和“重试启动”。重试复用原任务；服务端只对已结束的启动指令重新授权，仍拒绝已领取或活动运行，避免失败后无操作入口。

## Windows ConPTY 身份核验

实机 Claude 2.1.251 经 pywinpty 启动后，Windows `CommandLine` 以空格开头，`CommandLineToArgvW` 的 argv[0] 为空，原先只比较命令行的规则因此误报“未找到唯一的当前 Claude 进程”。进程快照增加系统返回的 `ExecutablePath`，仅在真实可执行文件与登记文件一致时补齐空 argv[0]，仍核验完整 JS 入口和精确 session-id；未能读取实际映像路径时拒绝这种匹配。其他进程不会因同名或提示词中含工单号被认领。

ConPTY 输出经有界 socket 背压转接后交给 Windows select，避免将非 socket 句柄传入 select。启动执行权检查失败前的输出保留在本机，并脱敏写入运行错误，便于诊断。增加 socket 输出/EOF、空 argv[0] 的真实映像核验与错误 JS 入口拒绝测试，共 3 项通过。
