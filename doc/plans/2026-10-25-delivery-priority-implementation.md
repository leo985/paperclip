## 本批已实现

### P0：预算准入、暂停与用量账本基础

- 原生公司、席位 Agent、项目预算准入检查全部有效硬策略，不再仅选择第一条；金额为零及仅预警策略维持原有语义。
- 已知项目缺失或跨组织时拒绝准入；席位指令生成、接受及 checkout 接入同一预算服务。控制、心跳和停止回执不被预算门禁关闭。
- 预算恢复前重新核验同一 scope 的全部有效硬策略；提高月度限额不会绕过仍然超限的累计限额。
- 公司、项目、席位已有人工暂停不会被预算暂停覆盖；预算解除不能清除人工暂停。
- 预算取消本机出站运行前，持久化停止意图及审计；意图不代表本机已经退出。已有单执行器及停止核验机制继续有效。
- `cost_events.idempotency_key` 及唯一索引按公司、Agent 和来源事件键去重。相同事件重传复用原账本行；同一键的业务内容、Token、费用或发生时间不同则拒绝。旧生产者不提供键时保持兼容。
- 费用的运行、工单、项目、目标归属均校验组织边界；运行还校验 Agent 身份。
- 原生运行结束汇总通过 `accountFinalRunUsage` 将账本回执与 Agent 累计 Token/费用同事务提交。并发重试不会重复累计；提交后远程预算停止失败可重试，不重复收费。汇总键由服务端保留，普通费用 API 不允许占用。
- 本地 Claude 运行失败时，仍保留实际获得的模型 Token 汇总；中转/订阅计费仍标 unknown/unpriced，不把 CLI 模型估价当真实账单。
- Schema 生成迁移：`0289_bitter_arclight.sql`，未在生产应用。

这部分是观测费用治理基础，不能宣称已经具备严格零超支、所有新领域的许可续验或流式费用结算。

### P0：同席位多个 Harness 的登记基础

- 新增 `harness capability register/list/check`，分别登记分析、研发和 QA 仓库、本机根目录、profile、HEAD、技能角色和文件摘要。
- Git origin 的认证信息不上传；不读取/上传 Claude settings、MCP 或 API Key。分析默认 profile 解析为实际活动 profile，并核对其路由技能。
- 服务端校验标准席位凭据、组织、机器身份和修订；事务锁与乐观修订防止覆盖并发登记。执行、排队或在线等待决策时不能更换能力；相同能力允许刷新检查时间。
- 席位详情的“设备与诊断”显示“本机 Harness 能力”、路径、版本、检查时间及操作说明；加载失败可重试。
- 登记不改变旧 `harness_root`、负责人、仓库映射或历史任务。`executionReady=false` 明确表示执行适配待验收，不因技能文件存在就开放自动派发。
- 安装器显式清单包含新增模块，已重建本地客户端包；没有更新用户已安装客户端。

### P1：轻舟在线来源客户端基础

- 参照 `qingzhou-ops` 的 `token_manager.py` 及只读方法实现统一登录表单，使用配置账号换取 Token；Token 仅内存缓存。
- 并发登录合并；401/403 最多重新登录并重试一次。失败分类为待认证、连接不可用、来源拒绝、格式错误或结果不完整，不以空数据掩盖错误。
- 仅允许固定轻舟来源的四种只读查询：条目、分析详情、月度计划、排期树；不提供任意 URL、任意 UC 或写入操作。
- 条目筛选用 form；排期的 manageId、number、type 及组织/月参数按原接口放在 URL query；19 位编号无损解析。拒绝跳转，限制超时和响应大小，错误不包含账号、密码、Token 或原始上游异常。
- **真实认证仍未通过**：技能配置存在，本机调用原有 get-token 返回 ConnectionError，尚未取得有效 Token；没有复制个人浏览器 Cookie，也没有将账号复制到生产。
- 已补齐项目级网页来源配置、加密密钥库及手动在线读取/同步，详见下方续批记录；持续定时同步与真实内网认证仍待完成。

## 续批实施：执行许可与网页在线来源

本节为上述基础后的实际增量，代码、迁移和客户端包均未发布到生产，也没有升级任何真实席位。

### 执行许可、停止及用量补传

- 新客户端领取原生出站任务时声明 `permitProtocol=1`；服务端签发与公司、席位、机器、运行、任务及一次性 lease 绑定的 60 秒执行许可。续验重新核对任务归属、取消/暂停、原生预算及持久化停止意图。过期或撤销的许可不能复活。
- 客户端在启动前续验，使用单调时钟和请求发出时间计算保守截止时间。独立看门狗在 HTTP 阻塞时仍要求停止受管进程；临时停止错误持续重试。恢复网络不会重新启动旧进程。
- 同一运行不重新签发许可；旧许可未收到监督器退出回执时阻止新许可。退出回执仅证明监督器观察到子进程退出，**不等于完整进程树停止核验，不清除已有执行阻塞**。
- 暂停或终止席位仍可上传停止/用量回执，不能领取新工作。服务端以持久化许可判断是否需要续验，不允许通过省略客户端协议标记绕过。
- 已获取的真实 Claude 最终 Token 汇总和退出回执先进入本机 outbox；网络失败、运行尚未结算、响应无明确 `received=true` 时保留文件，后续重试。最终汇总复用原生账本幂等键，正常结算与延迟补传不会重复累计。
- 第三方中转/订阅费用仍为 unknown/unpriced，不按 CLI 估价入账。没有最终模型汇总的强制中断仍可能缺少用量，**尚无逐消息流式结算，也不具备严格零超支保证**。
- 旧客户端不声明新协议时继续原有传输，不将其标为已受新许可控制。生成迁移 `0290_lyrical_nighthawk.sql`，尚未应用生产。

### 项目级在线来源接入

- “条目交付”新增管理员在线来源区域：选择当前项目已配置 Jira 连接的席位，填写轻舟组织数字编号、账号和密码。轻舟凭据由原生 `secretService` 加密保存，账号/密码和密钥 ID 不回显；留空保留原凭据。
- “读取并核对”不保存；“同步只读版本”保存带 `online_readonly` 标识的版本，相同内容复用历史版本。不创建或派发执行任务，不修改轻舟/Jira。成员可查看已有快照；配置、读取和同步限定组织管理员。
- 从条目及分析清单读取真实主单；按全部指定月份读取匹配组织的计划/排期树，再完整分页读取 Jira 主子单。组织不匹配、页数/总数不一致、数据截断、非法来源均拒绝，不能保存部分结果。
- 外部网络读取不持有数据库事务；提交前复核项目、连接修订、Jira 席位连接和两类密钥版本。读取期间配置或凭据变化拒绝提交。连接保存、核验成功/失败及新版本同步均有安全审计，不记载凭据。
- 网页可显示待认证、连接不可达、来源拒绝和数据不完整等状态；帮助页已补充在线配置、月份及两个读取按钮的场景。手工快照保持兼容。
