# 明确停止与一次真实本机重试

日期：2026-10-23

已定位：通用 transient_failure_retry 没有本机启动意图，出站适配器却将其返回为成功，随后触发空的交接运行。原始异常退出码不能证明用户希望停止整个任务。

实现：

- 网页停止与 `harness stop <Jira 工单号>` 先持久记录意图，再取消／发信号；本机离线意图随停止证明心跳同步。审计记录独立于适配器结果，防止结束回写竞态覆盖意图。
- 新版本本机启动才设置自动重试协议标记。旧运行不会因升级被自动启动。
- 停止证明必须对应本任务最新本机运行，心跳有效且席位空闲。公司、负责人、有效平台授权、环境释放及其他执行保护必须通过。持有席位／任务／运行锁后原子授予一次新的派单授权；并发心跳不重复授权。
- 新授权沿用现有客户端持久调度、可见终端、启动意图、Jira 校验与独占锁流程。每次显式派单／恢复最多一次；自动重试再次失败保留阻塞。晚到停止记录阻止待启动的自动授权。
- 禁用个人出站席位的通用空重试。缺少本机启动意图的通用唤醒返回失败，不再产生成功空跑。页面新增准备自动重试状态及取消入口。

验证：

- 独立、一次性 PostgreSQL 测试库：21 项回归通过；库在测试结束后删除，未操作真实工单。覆盖并发去重、次数上限、退出码 2、历史运行、明确停止及回写竞态、停止证明、较新运行、Jira 授权撤销、暂停、活动运行、环境租约与其他保护、禁止通用重试和空跑失败。
- Python：15 项通过，含停止指令先落盘、断网同步、唯一运行校验、新授权清除旧错误并调用本机真实启动入口，以及既有原生等待提醒。
- 服务端 TypeScript 编译、UI TypeScript 检查与 UI 构建通过；UI token gates 通过。未运行全仓库检查；本次为定向变更验证，未创建 PR。
- 实际 Claude 启动使用模拟入口验证，未启动模型或重启用户故意中断的历史工单。

发布以同目录 release JSON 为准。后端／UI／安装包定向覆盖并校验摘要，发布前备份数据库和文件并确认没有活动运行。本机更新只在席位空闲时进行。无数据库迁移。
