# 2026-11-05 可配置交付流程

默认模板：设计 → 设计席位负责人审核 → 前后端编码并行（同席位排队）→ 全部编码汇合 → 用例编写 → 功能测试 → 人工验收。

复用 delivery-workflows 引擎、正式交付回执及原生 Harness，不另建执行通道。组织配置作为默认，项目可覆盖或恢复继承；已启动实例保存模板快照。配置仅影响新建流程，启动动作仍需明确绑定真实工单和席位。

已实施：模板版本持久化和乐观锁、组织/项目权限验证、阶段开关和默认席位、自动/确认启动、指定审核人、编码并行/串行依赖、逐阶段恢复、等待通知、设置入口及默认模板自动接入。

验证：实际数据库回归覆盖版本固定、并发发布、审核门禁、无分析上下文、并行运行、同席位排队及失败分支阻止汇合；页面测试覆盖组织发布、项目继承和错误反馈。全仓检查结果在交付说明中如实报告。

范围：不自动收编旧运行、不提供拖拽引擎、不自动完成业务验收；钉钉沿用席位等待通知策略。生产发布需独立核对当前未发布的交付模块依赖，不将本地实现描述为已上线。
