# 项目独立 Jira 来源连接

## 用户流程

组织来源配置不再选择执行席位。管理员为当前项目填写 Jira 服务地址、PAT、轻舟凭据及排期组织，保存后进入组织月度条目列表。PAT 加密保存且不回显；编辑时留空复用，改变地址必须重新填写 PAT。来源连接只用于工单读取、来源核对与同步，执行席位仍在派单时选择。

当前配置入口为“需求条目 → 组织来源配置”，按平台项目隔离，每个项目保存一份来源连接。项目来源凭据不会替换席位自身的 Jira 派单凭据；席位的经办人、允许状态、执行权限等仍沿用原有配置。

## 数据与兼容

迁移 `0297_loose_paladin.sql` 为 `delivery_connections` 添加 `jira_base_url`、`jira_secret_id`，并将旧 `jira_agent_id` 改为可空；不删除、重写既有连接。

新配置将 PAT 保存到项目独立的公司加密 secret，并将旧席位引用置空。旧配置在保存前仍沿用原席位连接；管理员保存后，在同一事务内复制旧 PAT 为项目独立凭据，不修改旧席位或其 secret。已有旧配置若已失效，可填写地址和新 PAT 修复。保留旧 API 的显式 `jiraAgentId` 输入兼容旧客户端，新 UI 不再发送它；服务端拒绝同时提交两种连接模式。

月度排期查询只依赖轻舟项目凭据，不再因 Jira 席位变动而失败。完整来源核对与同步使用项目 Jira 凭据，继续检查来源修订、secret 版本和项目组织边界。Jira 地址沿用服务端允许来源列表；禁止用户信息、非根路径、查询参数及未获准的来源。

## 验证

- 13 个针对性接口与组件测试通过，包括无席位接入、旧配置复制与脱离、删除旧席位后读取、凭据保留与不回显、非法地址、冲突参数、并发凭据轮换及原来源回归。
- shared/db 构建、服务端直接 TypeScript 检查和编译、UI 类型检查和构建、设计 token 检查通过。
- 服务端完整 typecheck 脚本的 runner 原生构建前置步骤因 shell PATH 中缺少 cargo 未通过；直接运行同一服务端 TypeScript 检查及编译均通过。
- ego-browser 使用隔离上游响应、真实本机 API 与数据库验证项目地址/PAT 保存、无席位选择、自动进入组织月度条目、PAT 不回显、留空编辑保留凭据。

## 发布与回退

发布前检查无活动运行、迁移状态无分叉，保留模块备份及完整数据库备份；只应用 0297 增量迁移并重启平台自身服务。席位客户端不变，核对其他用户服务 PID。发布记录见 `2026-10-26-project-jira-source-release.json`。

失败时恢复旧应用模块和 UI，保留已应用的增量迁移文件及可空新字段；不自动删除 secret 或破坏新增项目连接。需要数据库回退时由运维根据私有备份单独评估。
