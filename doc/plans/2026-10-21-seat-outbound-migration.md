# 旧 SSH 席位原位迁移

## 使用方式

席位详情 → 设备与诊断 → 迁移并更新客户端，复制原更新命令到原电脑、原操作系统用户执行。继续沿用 `--upgrade --agent-id <原席位 ID>`，无需新接入码。普通首次接入流程不自动迁移。

## 身份和数据保留

使用原独立 Agent 凭证，校验公司、Agent ID、管理员已绑定的 machineId 和机器指纹。迁移不能创建 Agent、接管其他电脑、重分配负责人。保留 Agent ID、机器身份、负责人和 intakeUserIds、通知及 Jira 调度配置、原工单和独占登记、项目本机仓库映射、本机 Claude 路径及配置文件。

服务端只切换此 Agent 的 transport 和控制环境，更新其运行登记及摘要，并关闭旧周期心跳（保持按需唤醒、单并发）。原 SSH 环境不删除、不修改，不影响使用同一环境的其他席位。模型密钥和 Jira PAT 不上传到迁移接口。

## 协调切换

1. 本机取得 upgrade/operator/config 锁，检查活动运行、Claude 会话、启动意图和服务归属，备份配置、服务和 CLI（保留符号链接）。
2. 停止空闲 watcher 并持有 watch 锁，重新检查本机无运行。生成迁移编号，先写入持久恢复记录。
3. 服务端事务锁定席位，核验原机器与无 queued/running/scheduled_retry 任务及无近期待决策状态；要求席位 idle。切换 outbound，关联可用 local 控制环境，更新登记版本，同时置为 paused。
4. 本机同步新的执行环境、登记版本和接入桥版本目录，安装 CLI 与后台服务。恢复 watcher 后因升级锁/记录存在，暂不执行任务。
5. 服务端确认对应迁移与配置版本后恢复 idle。最后清理升级记录，watcher 才开始正常工作。

服务端操作按 migrationId 幂等，审计 prepared/completed/rolled_back/restored。接口返回字段白名单，不返回备份配置和凭证。登记接口明确返回 executionTransport；本机刷新登记不再根据缺失的通用 Agent 字段默认写成 ssh。

## 异常恢复

失败时先确认服务端迁移结果；prepared 可回退执行配置但保持 paused，恢复本机备份和旧服务后再恢复服务器 idle。无法确认远端结果时不盲目还原或重启旧执行链，保留本机恢复记录，原命令可继续 prepared 迁移或完成回退。若服务端已 completed 但客户端响应丢失，则确认完成，不反向覆盖。

未知服务归属、身份不匹配、活动任务、缺少旧运行登记、缺少本地控制环境均拒绝迁移并显示原因。恢复时核对备份路径与当前配置；不会删除配置重建席位。

## 交付边界

不补采历史独立会话、不自动拉取 Harness Git、不改业务代码、不强制停止 Claude。不自动替使用者执行本机迁移；发布后原升级命令才执行实际切换。
