# 席位钉钉机器人通知

## 使用方式

组织负责人、组织管理员及实例管理员可在席位管理页展开“钉钉通知机器人”，添加或编辑企业内部应用机器人。填写名称、CorpId、AppKey、RobotCode 与 AppSecret。编辑时 AppSecret 留空保留原值，更换 AppKey 时必须提供新密钥；关闭启用即可停用。

席位负责人在通知标签选择机器人及同企业的通讯录接收人，保存提醒间隔和升级时间。旧个人发送账号不会猜测转换为机器人，需重新选择保存。管理员提供凭据后才能开展真实消息验收。

## 运行边界

- 本机桥仅上报领域阻塞、待决策和超时状态。
- 服务端使用钉钉开放平台企业内部应用机器人单聊 API，获取应用 accessToken，再发送 sampleText。
- 密钥由现有 local_encrypted vault 保存，不进入普通配置、审计明文、响应或本机。
- 机器人按组织隔离；管理员才能编辑，席位负责人可选择。
- 接收人必须来自同 CorpId 的有效钉钉人员联邦源；应用还需发布、启用机器人及具备发送权限和接收人可见范围。
- 配置采用现有 activity_log 中按机器人 ID 保存的版本记录；凭据仅保存 secretId 引用，无新增数据库迁移。
- 仅处理本席位负责的未结束 Harness 任务，并核验手工授权工单范围或 Jira 自动接单授权。
- 发送前用数据库 advisory lock 原子保留通知键：席位、机器人、接收人、确认、等级、时间段。每次心跳最多发送一条，避免重入重复；HTTP 调用各限制 10 秒。
- 投递状态：发送中、已受理（不表示已读）、失败、结果未知。结果不明不重复发送同一通知键，后续时间段是新提醒。无读回执保证。
- 使用机器人时心跳响应隐藏 dingtalk 发送配置，旧桥不会尝试以个人 DWS 发送；本机和网页提醒保持。
- 通知错误不阻断席位心跳。机器人停用后不再向钉钉发送。

## 验证边界

前端 TypeScript 检查、后端 TypeScript 编译及 UI 构建通过。没有新增或运行测试套件。未配置实际机器人凭据，因此不能宣称钉钉已送达。发布需独立记录备份、资源一致性、服务健康及鉴权边界；实际配置保存、权限错误及消息送达仍需带真实凭据验收。

## 接收人关键词检索

席位通知复用 SearchableSelect：先选机器人，再在接收人下拉框内输入姓名、部门、组织或钉钉 ID，支持不区分大小写、多关键词及键盘选择。仅显示机器人企业的有效通讯录人员，空结果有同步检查提示。当前人员联邦没有独立工号字段，因此没有提供工号检索。选择结果在搜索时保留，点击保存通知设置后生效。本次仅更新前端及帮助，无需服务重启。
