# 统一任务详情（2026-11-11）

## 范围与原则

分析、研发、测试及人工任务统一使用 `/issues/:issueId`，默认展示任务概况、待处理事项与执行操作、执行进度与门禁、交付成果、会话与执行记录。统一布局不重写各领域的生命周期、许可、预算、决策、交付或正式审批。

原任务详情保留在同一 URL 的 `detailView=collaboration` 视图，包含对话、文件、属性、关联任务和高级操作。已有评论／文件等深链接继续打开原视图。独立 Agent Chat 继续使用既有 `TaskDetailSurface`，不切换成业务任务详情。

分析列表保留创建、筛选和分页；选择分析、创建成功及旧 `analysis-executions?executionId=...` 链接进入统一详情，返回时保留项目、来源条目及页码。新修订通过原分析的只读详情预填创建表单，仍由原创建接口检查项目与修订关系，不覆盖旧分析。

## 类型识别与权限

新增只读 `GET /api/companies/:companyId/analysis-executions/by-task/:executionId`。仅不存在分析记录时返回 `{analysis:null}`；存在但非负责人／管理员时仍返回 404，跨组织／Agent 请求按原访问规则拒绝，读取故障仍返回错误。UI 仅在明确为 null 时使用通用工单模块，拒绝或故障不降级成通用派单面板。返回结构使用 shared 的 `AnalysisTaskDetail` 类型，旧分析详情端点沿用相同读取函数和权限规则。执行进度和会话记录联动选择同一次运行，读取共用原查询缓存；原组合会话视图仍可独立使用。无数据库迁移，无后台写入或自动派发。

## 流程演进边界

本次统一展示结构及入口，不扩展客户端分析协议。分析原生协议仍使用当前 P0–P4；受管会话的流程视图仍按真实上报事件及流程版本分组。未来完整跟随原生流程变更，需要另行引入版本化流程定义与兼容验证；不能仅给阶段代码加中文名称后宣称协议已动态化。
