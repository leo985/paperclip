# 分析完成后自动保存轻舟分析内容

## 行为

绑定轻舟条目号的独立分析（含交付链创建的分析）通过当前版本 P0–P4 和真人质量评审后，接入桥传送 `analysis.md` 正文及原有七项文件指纹。平台校验 UTF-8 正文与已冻结 `analysis.md` SHA-256 一致，先保存本地交付，再自动调用轻舟保存分析接口。未绑定条目的分析继续只采集索引，其余原始材料不上传。

接口参考：`ai-asset-hub/skills/qingzhou-ai/scenarios/demand-analysis.md`、`scripts/scenarios/save_demand_analysis.py`。使用 `UC_PROJ2_DEMAND_SPLIT_ANALYZE`、multipart 和 `demandAnalysisDto.*` 点号字段；本地 `avatar-proj` 的 `DemandServiceImpl.splitAnalyze` 和 `DemandAnalysisServiceImpl.saveInfo` 用于核对身份权限、必填字段及副作用。

使用当前组织中执行席位独立配置、加密保存的轻舟账号；凭据不下发席位或模型。未配置席位账号时阻止回写，不借用项目来源账号（2026-11-11 调整，见 `2026-11-11-seat-qingzhou-accounts.md`）。账号必须满足轻舟的条目分析负责人校验，平台不会代换负责人或绕过上游权限。目标条目必须已在同项目同步纳管，且当前上游编号与已纳管来源 ID 一致。

保存保留来源的标题、功能包、关联功能、跨子产品、方案属性、预估工时和已有分析业务字段；显式设置的回写参数优先。缺失业务共性默认共性业务，缺失工时默认 1 小时，缺失日期使用本次运行的上海时区起止日期。这是可修改的保存默认值，不是实测工时。创建时可修改，失败后可在重试表单补齐。轻舟接口会按业务共性重新分配评审人，界面明确说明。

分析 Markdown 转为完整转义的 `<pre>` HTML，保留正文和换行，避免嵌入脚本、远程图片或隐藏请求。正文上限 120 KB；正文疑似包含凭据时不接收。Jira 分析字段保留纯文本，不调用 Jira 写接口。正文回读一致后才记为已保存；自动保存不自动申请评审、不代替轻舟业务审签，也不将分析任务变成 `published`。正式发布登记及后续准入保持原语义。

## 失败与重试

`analysis_executions.qingzhou_writeback` 保存参数、状态、目标 ID、凭据来源、执行席位与账号修订、输入与内容摘要、上次来源摘要和核验时间。活动日志记录成功或失败及版本，不记录正文或凭据。

席位账号变化与同条目各分析修订的回写使用事务锁串行处理。未纳管、归档、来源身份不匹配、已结束条目及已有更新分析交付时，拒绝覆盖。网络超时或错误不盲目重发；管理员“重试保存轻舟分析”先回读，正文已经一致则只补记成功。若失败后源内容已变，停止覆盖并要求核对后新建修订。上游接口不提供原子比较写入，平台锁不能防止外部用户在读取与保存间修改轻舟。

失败不丢弃本地交付；页面明确展示失败和重试入口，不继续占用模型等待网络。重试只处理已冻结交付，不重启分析。失败后的重试由管理员手动发起，无无限后台重试。客户端丢失完成回执时，可重复发送同一交付，避免再次提交已冻结的观察状态。旧客户端没有正文时明确提示更新；可补传与旧清单完全匹配的正文，其他冻结字段不能修改。

## 发布与验证

需要部署服务端、迁移、前端和更新后的接入桥；仅刷新网页不能给旧客户端增加正文采集能力。已有分析的授权和真人质量评审仍生效。

测试覆盖 multipart 合同、精确版本正文、Windows 换行、大小限制、源字段保留与默认值、回读确认、响应丢失后恢复、重试冲突、并发去重、组织/项目隔离、权限和页面反馈。真实轻舟保存须使用具备对应分析权限的账号和指定条目验证；本次开发不选择任意业务条目进行试写。

### 本地验证结果（2026-11-10）

- 全工作区 `pnpm -r typecheck`、`pnpm build`、Storybook 构建及 `pnpm check:token-gates` 通过；Rust 检查使用本机已有的 Cargo 路径。
- 相关单元与组件测试 18 项通过，接入桥分析测试 16 项通过；新增 API 的生成合同同步检查和合同生成器测试通过。
- 相关数据库集成测试 10 项跳过：当前执行环境的 `uv_os_get_passwd` 返回 `ENOENT`，内嵌 PostgreSQL 无法启动。并发、响应丢失恢复和权限生命周期等数据库场景已编写用例，但本次未实际跑通，不能据此宣称完整集成验证通过。
- `pnpm test:run` 的首个服务端组结果为 528 个文件通过、40 个失败、163 个跳过；测试项 8757 通过、12 失败、4887 跳过。大量套件因相同的 PostgreSQL 启动问题失败；另有沙箱回调桥的 `nohup` 控制台错误、SSH 密钥生成失败，以及条目详情测试返回 500（其查询桩未提供后续交付链查询结果）。脚本在首组失败后退出，后续组未执行。另行运行的 OpenAPI 完整路由覆盖检查也因 `delivery-templates.ts`、`dsp7-seat-upgrades.ts` 未登记而失败；本次新增接口的合同同步检查通过。未修改这些范围外业务或测试基础设施。
- 本地验证阶段尚未部署，也未对真实轻舟条目进行写入验证。
