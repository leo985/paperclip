# 席位负责人由管理员统一指定

## 权限和操作

- 组织 owner/admin 和平台管理员管理组织内席位，候选负责人限同组织已激活的 owner/admin/operator/member，排除观察成员。
- 一个席位一位负责人。负责人可配置名称、Jira 接单、PAT、通知、检查和设备登记；不能修改负责人或其他席位。
- 新电脑由管理员选择负责人后生成接入命令，研发在自己电脑安装。不再将命令签发人自动当作席位负责人。
- 兼容旧席位：尚无显式 ownerUserId 时取 intakeUserIds 首位；管理员保存后收口为单人授权。负责人字段不允许通过通用智能体配置 API 绕过修改。

## 负责人变更

- 事务锁定席位并验证组织和候选人，保留 machineId、指纹、执行路径和登记版本。
- 有活动运行、本机处理请求或待决策任务时阻止转交。取消未领取的旧网页请求。
- 原负责人失去席位管理权限；新负责人获得权限。同步席位安装器签发的 Agent key 的 responsibleUserId，客户端令牌无需重新安装。
- 变更时停用 Jira 自动接单并移除旧 PAT 引用；新负责人填写自己的 PAT。手工推进、钉钉通知恢复默认，避免继续以原负责人身份执行或通知旧接收人。
- 不转交历史工单、历史运行身份或个人凭据。旧 Secret 保留历史记录，不将其明文返回新负责人。
- 每次管理员确认或变更写入 dsp7.seat.owner.assigned 审计事件。

## 发布范围

后端席位授权、邀请、负责人接口、通用配置保护；前端负责人选择与配置权限；帮助中心。无数据库结构变更，无 Harness 客户端源代码变更。
