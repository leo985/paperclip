# 2026-10-22 中断执行停止核验修复

## 根因

DSP-11 / ATSES-491887 的真实运行 `1b1502f8-c2ae-4e03-900b-82c09d89d244` 已在服务端结束。本机记录的 Claude PID 17831 和出站监督器 PID 17804 均已退出，但异常退出未写 `summary.json`。原逻辑要求摘要存在才上报 `stoppedRunId`，因此永久等待。另一个问题是第一次中断会禁用 pilot，后续仅处理启用任务，无法修正已展示的核验提示。

本机登记差异只有 `settingsDigest`，Claude 版本、可执行路径、配置路径、Harness 根目录和执行环境均未变。通过原有 `seat register` 接口显式刷新，保留原身份和配置内容。

## 修复

1. 仅对服务端真实执行已 failed/cancelled/timed_out 的任务核验，活动运行禁止通过。
2. 从会话元数据及本机 worker 启动事件取得 PID，检查对应 Claude 会话及所有记录的相关进程。无本机启动证据或进程检查失败时保持保护。
3. 存在正常摘要时按实际进程检查确认停止；无摘要时须两次无进程观察、间隔至少 15 秒。心跳重复执行该检查。
4. 写入独立停止核验证据 `stop-verification.json` 和事件。不制造结束摘要，不推算实际退出时刻，不把未知用量或费用写为零。
5. 纠正崩溃留下的 session running 元数据，记录退出观察时刻，保留原会话内容、领域状态和采集文件。
6. 已禁用且显示当前运行“执行已中断”的任务继续同步核验结果；不覆盖其他运行或业务阻塞，不重复写同一消息。
7. 新会话登记 wrapper/supervisor PID。确认停止后仅允许网页明确恢复，不自动运行。
