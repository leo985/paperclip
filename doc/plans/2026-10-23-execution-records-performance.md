# 执行记录页面性能优化

## 定位依据

- 浏览器访问线上 `/DSP/runs`，当前浏览器未登录，显示登录入口。两者共用同一个主入口脚本；该次主脚本传输约 6.14 MB、耗时 12.5 秒，DOMContentLoaded 约 12.85 秒。这是单次观测，不是受控网络下的完整登录后页面基准。
- 使用本机已登记席位的正常身份只读访问运行摘要列表：组织范围 40 条约 1.195 秒；本席位 39 条约 0.260 秒。没有修改身份、借用网页会话或读取日志正文进行测量。
- 原执行记录页每次进入即查询列表，点击最近运行还调用完整运行详情接口；该详情包含执行投影、身份历史、重试与静默状态等本页并未使用的信息。日志随后才发起读取，首次最多 64 KB。
- App 静态导入多数详情、配置和实验页面，两个 Layout 常驻创建表单，根节点常驻组织初始化向导。即使不打开表单，也会把相关编辑器依赖带入初始加载。

## 实现

### 按路由加载

App 采用稳定的模块级 lazy 路由声明，每个页面使用局部 Suspense，普通页面切换保留外层布局。登录、找不到页面和首次改密保留直接加载。运行日志权限、组织边界、入口及实验开关不变。

将 Agent 列表筛选常量提取为独立模块并保留原文件 re-export，避免只为了常量加载整个 Agent 页面。

### 按首次使用加载表单

两个布局共用 DeferredBoardDialogs，创建任务、项目、目标及 Agent 的表单在首次打开时加载。首次打开有可取消的加载提示；加载后保留原组件挂载，维持原有草稿与清理行为。组织初始化向导同样在首次打开时才加载。

### 执行记录请求

- 列表缓存新鲜期 15 秒，与列表刷新周期一致，短时返回不必等待重复请求。
- 最近列表已有的记录直接读取日志，不再补查完整详情；列表外历史链接仍先查详情确认所属组织。
- 首次日志读取开头最多 16 KB。点击查看更多逐级扩大前缀预览至最多 256 KB，不拼接独立解码的字节切片，避免 UTF-8 跨切片产生乱码。
- 日志不自动轮询，也不在窗口焦点切换或重连时自动重读大段正文；提供明确的刷新与失败重试操作。
- 切换记录时保留 URL 中的席位筛选，选中行有可见反馈。
- 请求接入 AbortSignal，离开页面或切换查询时取消不再需要的请求。

## 构建结果

最终主入口脚本约 0.73 MB，较原 6.14 MB 减少约 88%；HTML 初始引用的 JavaScript 合计约 3.11 MB。主入口变小不代表全部代码消失，其他页面按需下载；首次打开尚未缓存的表单会有加载过程。

没有后端、数据库、客户端、运行协议或权限变更。原有后台“状态容量扩展”待空闲发布任务继续保留，且仅更新后台，不覆盖本轮静态资源。
