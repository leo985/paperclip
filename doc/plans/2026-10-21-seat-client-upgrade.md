# 已有席位接入桥升级

## 交付内容

- 席位“设备与诊断”增加本机接入桥版本、网站当前版本、更新步骤和 macOS/Linux/Windows 命令。
- 负责人和管理员可查看命令，无新接入码；命令绑定 agent UUID，安装器还校验原网站。
- Python 安装器 `--upgrade`，Windows PowerShell 入口 `-Upgrade -AgentId`，无需 `-Code`。
- SHA256 校验与不可变版本目录；不覆盖正在运行的旧版代码。
- 保留身份、凭据、Jira 配置、仓库映射和 Claude 设置，仅切换桥路径和本用户后台服务。
- 升级锁、终端操作锁、配置锁与维护标记；检查服务端活动运行、本地会话和近期未消费启动意图。新版 watcher 调度和出站启动遵守维护锁。
- 备份原配置、Harness 本机路径登记、命令入口及服务文件。失败恢复原配置，尝试恢复旧服务，失败明确提示。
- 不自动结束 Claude，不修改业务源码，不运行 Harness Git pull。旧 SSH 席位拒绝直接升级。

## 使用

已有电脑：席位详情 → 设备与诊断 → 更新客户端 → 选择电脑系统 → 在原注册用户终端执行。任务执行中拒绝更新，完成后重试。更新后等待新心跳，确认版本一致后启动新任务。

首次接入：管理员“接入新电脑”，指定负责人，复制一次性命令给对应电脑；登记本机 Harness、Claude、项目仓库后配置接单和通知。

## 边界

- 当前用户后台服务可以切换；手工 watch 需用户先在空闲时停止。
- 不保证网络断开、系统断电、强制终止升级器后的自动恢复；维护记录和私有备份用于人工恢复。
- 旧版 watcher 不识别新版维护锁；升级时重复检查服务器和本机活动状态。既有终端启动使用同一 operator.lock，升级期间禁止新本机终端启动。首次从旧版升级应确保电脑空闲。
- 本地 Python 编译、UI/服务端类型检查、UI 构建和样式门禁作为静态检查；未运行真实席位升级或 Windows/Linux 实机验收。
- 已于 2026-10-21 发布服务器；没有自动升级任何已有席位。
