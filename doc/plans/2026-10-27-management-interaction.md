# 管理视角交互优化

日期：2026-10-27

## 目标与实现范围

管理者能够从当前组织的首页发现异常，看到处理责任与下一步，再进入原有工单、审批、恢复或设备诊断流程。

1. 共享执行状态和管理结论：工单生命周期、席位实时状态、执行停止证据分别保留；首页、工单管理及席位队列不再把 `in_progress` 直接解释为实际执行。
2. 待处理中心按任务聚合提醒，展示负责人、证据时间、下一步；保留正式审批和通知入口。归档和已读不表示问题解决。
3. 月度排期增加计划已过待核实、本周到期、责任人缺失、准入待核验筛选及风险排序。时间采用上海时区，不从计划日期推断正式延期或完成。
4. 首页管理员默认组织概览，记住账号/组织范围；卡片跳转保留项目、范围与状态。
5. 席位展示接单准备缺项、任务队列；运行记录显示关联任务和失败摘要。
6. 在现有条目材料、项目配置和交付报表中补充可定位的缺项及核验入口，保持未知费用、采集缺口与正式验收边界。

## 边界

本轮改进管理界面和只读投影，所有派单、恢复、审批、任务指派仍走现有服务端权限与门禁。不得通过页面认领改变席位负责人，不创建未经授权的执行，不将席位提醒伪装为可由平台审批解决的正式需求决策。跨设备视图同步、独立事件认领/转交/提醒状态需要后续明确的持久化资源契约，本轮不以浏览器本地状态冒充团队协作记录。

## 验证

执行证据优先级、陈旧停止记录、离线和读取失败、提醒去重、项目与个人范围、上海时区周界与计划日期、筛选/排序及跳转的针对性测试；UI 类型检查、token gate、构建和浏览器管理流程验证。验证记录在完成后补充。


## 本轮完成与验证记录

已完成共享管理结论、组织/个人视图、按任务合并的待处理卡片、月度风险筛选与排序、席位准备缺项、运行记录上下文、项目接入准备、阶段材料索引及报表数据质量提醒。工单列表补充展示范围选择；窄屏的材料与排期表保留可读列宽，在表格容器内横向滚动。

验证结果：

- 9 个相关测试文件、65 项断言通过，覆盖新管理逻辑/页面交互及既有阶段、批量同步、停止控制、执行状态、仓库配置回归。
- `pnpm --filter @paperclipai/ui typecheck`、`pnpm check:token-gates`、UI Vite 生产构建通过。Storybook 构建通过，生产构建存在既有大包提示。
- ego-browser 使用独立 Storybook 数据验证：首页互斥分组、提醒去重、范围切换、项目筛选及带条件跳转；25 条月度排期筛选出第 25 条责任人缺失条目，详情链接保留风险/排序/项目/月度；材料索引与项目准备状态可读。390 像素宽屏首页、材料页、月度排期页均无页面横向溢出，长表仅在容器内滚动。未对线上业务数据执行派单或修改。
- 全量 UI Vitest：643 个文件中 333 个通过、310 个失败；6626 项测试中 4676 通过、1950 失败，另有 107 个错误。失败包含已有英文断言与当前中文界面不一致、缺少测试 Provider 或 mock 导出。例如未修改的 TrustPresetSection 三项英文文本断言可单独复现。此次不能认定整仓回归通过。
