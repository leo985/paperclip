# 席位功能 P1–P3 实施与验收

日期：2026-10-07

## 范围

用户授权：按优先级实现全部功能、发布上线，并用当前 Mac 与服务器完成实际场景验证。

P1：心跳、网页检查、管理页。P2：一次性邀请与安装向导、配置变更提醒、网页启动／本机确认。P3：明确范围的主动推进、限时自动执行、阻塞重复提醒与升级。

## 实现结构

- `server/src/routes/dsp7-seat-control.ts`：公司与席位授权、心跳、策略、请求／回执、邀请。
- `server/src/routes/dsp7-seats.ts`：原席位登记和工单归属门禁，挂载控制路由，清单增加 presence/online/policy。
- `ui/src/pages/Seats.tsx`、`SeatAttentionNav.tsx`：管理、提醒与导航。
- 本机桥 `seat_control.py`：发送心跳、检查配置、处理请求、提示与限时执行。
- `onboard.py`：管理员预授权邀请的本机消费、独立凭证与安装。
- `interactive.py`：可见终端交接、启动回执。`pilot.py`：监督循环接入。

复用 Agent 的运行配置档案；心跳只记录运行状态。命令与回执使用已有 activity_log 的独立 `dsp7_seat_command` 事件记录，交易锁串行化同席位领取；不修改 Jira 独占登记事件。请求具备 UUID 幂等、15 分钟有效期、状态迁移、排队取消和不可盲重试。仅席位标准独立凭证可上报和领取。

初始邀请由实例管理员创建，只能绑定既定 Agent/环境/机器，15 分钟且一次性；凭证哈希留服务端，明文只在响应与本机 0600 文件。不会新增复制机器执行者。登记、心跳、策略和命令均保持公司边界。

网站模式与本机授权取交集，默认手动；自动模式必须有确切工单清单和 1–480 分钟有效的本机授权。所有启动沿用 Jira 状态、工作树、独占登记、租约、审批与领域完成检查。

## 使用说明

## 使用场景

- 研发负责人确认电脑是否在线、Claude 配置是否发生变化。
- 从网页请求本机启动，研发人员在可见终端核对后执行。
- 新电脑安装接入桥、获得独立凭证，并登记自己的本机路径。
- 为指定工单开启主动推进，发现阻塞并按间隔提醒、超时升级。

## 席位管理

侧栏打开 **席位管理**。本机接入桥约每 20 秒向服务器发送心跳，90 秒无心跳显示离线。显示状态包括在线空闲、正在执行、等待人工决策、等待本机确认、配置异常。

**在线仅证明接入桥通信正常。** 网页不会根据 Agent 的 idle 状态猜测电脑在线。模型密钥可用性和 SSH 启动能力以实际运行为准。

点击 **检查本机配置**，接入桥检查 Claude 可执行文件、版本、JSON 配置、Harness 和服务端登记。网页“请求记录”显示接收和结果，最近检查区域展示检查项。仅检查版本和文件，不调用模型，不上传密钥或文件内容。

配置变化后先核对，再点 **确认配置变更并刷新登记**。存在活动运行时，不允许更新执行配置。后台每分钟检查配置，每小时在配置一致时续期登记；出现变化时提醒，不自动接受新配置。

## 网页请求本机启动

1. 从 Project 接入 Jira，或在本机登记模拟任务。工单需要出现在席位管理的“本机已登记工单”中。
2. 核对没有其他执行者，勾选确认，再点击 **请求本机启动**。
3. 请求发送到服务器，接入桥通过出站轮询获取；不需要给研发电脑开放入站端口。
4. 本机自动打开独立 Terminal 终端，输入 `yes` 同意；其他输入拒绝。也可执行 `harness seat pending` 查看请求，再运行 `harness seat accept <请求UUID>`。
5. 同意后沿用原有 Harness 启动、Jira 校验和 Paperclip SSH 调度，连接真实 Claude 会话。网页记录运行 ID，终端显示执行过程。

请求等待有效期为 15 分钟。等待本机确认时网页可以取消；领取之后使用任务／运行页面处理，不把取消启动请求当作停止运行。重复请求不会启动第二个执行者。现阶段自动打开终端支持 macOS。

## 主动推进

在席位管理选择模式并填写明确的工单号，保存策略：

| 模式 | 行为 |
| --- | --- |
| 手动启动 | 仅处理人的启动请求 |
| 主动发现并请求确认 | 在本机已登记且就绪的授权工单中发现待执行工作，主动打开终端请求确认 |
| 限时授权后自动执行 | 在网站工单范围与本机有效授权同时满足时，自动打开可见终端并执行 |

自动执行需要在本机终端明确登记授权，例如：

```sh
harness seat allow-auto-start --jira ATSES-XXXXX --minutes 60 --confirm-no-other-executor
harness seat revoke-auto-start
```

授权最长 480 分钟，只覆盖明确登记的工单。本机授权过期、网站取消策略、Jira 状态不符、已有执行者或领域门禁不满足时不能自动启动。没有有效本机授权时改为终端人工确认。

只推进已经登记的工单，不自动创建 Jira 需求、不擅自领取其他研发的工单、不自动同意业务方案。一次主动请求不会在失败或结果不明确时无限重试，需要核对后手动恢复。

## 阻塞与多渠道提醒

待决策事项显示在席位管理；侧栏显示待处理数量。macOS 提交系统通知，按保存的间隔重复提醒，超过升级时间显示“超时升级”。通知是否实际弹出取决于系统通知权限和专注模式，窗口打开和网页提醒仍可查看。

浏览器支持系统通知且满足权限条件时，可点击 **启用浏览器提醒**；在普通 HTTP IP 地址上浏览器可能不提供该能力。网页内提醒始终可用。

钉钉继续使用 Harness 现有通知配置，并要求该工单已有明确通知授权。新接收人或群需要单独指定，系统不从席位登记中猜测收件人。真实工程确认仍通过 Jira；模拟确认只影响模拟 state。

## 新电脑接入向导

管理员点击 **新电脑接入向导**：先选择尚未绑定席位的独立 Agent 和已配置的 SSH 环境，填写那台电脑的 Harness、接入桥、Claude 与设置路径；可指定获授权的网站用户 ID，留空为当前管理员。

生成邀请并下载接入桥。邀请有效 15 分钟、只能使用一次，不会复制现有席位的凭证。新电脑准备 Harness、Claude 和 Jira 凭证，然后运行：

```sh
chmod 600 /绝对路径/paperclip-seat-invitation.json
/usr/bin/python3 onboard.py --invitation /绝对路径/paperclip-seat-invitation.json --jira-credential-file /绝对路径/jira-access.json --repository-root /本机业务源码根目录 --install-watcher
```

邀请中的桥安装位置必须与实际解压位置一致。成功后保存 0600 本机凭证，登记 Claude，配置 Harness 的桥路径并安装当前用户的后台监督进程。Jira 凭证不会从网站下发，需由研发电脑独立配置；本机仓库仍通过 `harness repo bind` 绑定。

同一组织内一台机器不能重复绑定两个执行 Agent。已有本机接入配置时安装器拒绝覆盖，应复用原席位或由管理员核对迁移。SSH 通道本身仍在“执行环境”中配置。


## 验收计划

1. 类型、构建、命令状态／心跳时间单测、本机许可范围与配置摘要测试。
2. 真实浏览器查看席位和提交检查，服务器接收、本机执行、网页展示回执。
3. 配置变更、登记版本不符、机器不符、重复请求和取消保护。
4. 停止／恢复本机监督进程，观察离线与恢复；保持 Tracker 可用。
5. 已授权 ATSES-493499 的新模拟轮次使用真实 Mac Claude 和 Paperclip 运行，网页请求、本机同意、待决策提醒、网页同意、同会话续传及完成。
6. 指定模拟工单验证主动推进与限时执行，验收后恢复手动策略、撤销许可。
7. 正式业务开发与钉钉收件人依赖用户提供未完成的工单及通知目标。已完成工单仅作模拟验收，不改真实 Jira/tracker/业务源码。

## 定向钉钉提醒实现

策略可配置接收人 userId 和固定 DWS profile，只对指定 Jira 工单发送阻塞与超时提醒。接收人从精确通讯录查询取得，DWS 登录凭据保留本机。发送前写去重标记；固定 argv 调用、固定 profile、幂等键、结构化结果核验，不盲重试未知投递。记录平台受理与失败，不能视作已读。
