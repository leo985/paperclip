# 终端断开与执行中断恢复

终端断开后通过席位心跳展示重连提示；普通执行保留 60 秒重连，审批等待按原期限保留。运行已失败、取消或超时，且本机结束报告存在、对应进程已退出，才报告 stoppedRunId 并将执行中的任务标为阻塞，显示“执行已中断”。不自动重试。

任务详情和项目派单面板增加“恢复执行此任务”。负责人或管理员明确点击后，事务内核验原派单授权、授权评论、最新失败运行、本机停止证明、在线心跳和无活动运行，再创建新的审计授权、将任务恢复为 backlog。本机重新核验 Jira、仓库和独占锁后启动。保留原任务、对话和 Harness 阶段，不保证复用已退出的 Claude 上下文。其他领域阻塞不能由此跳过。

客户端新增 execution-recovery-v1 能力。停止进程组遇到权限错误时仅回退到对应子进程，并写入退出结果。平台派单接口新增 resume 操作，状态 API 新增 reconnecting/interrupted。在线帮助同步更新。

检查采用 Python 语法检查、TypeScript 编译、UI 构建；不运行自动化测试，不创建验收模型会话。发布前核对无活动执行，备份替换文件，保留其他服务和原失败记录。

编译与构建已完成：server TypeScript、UI TypeScript、UI production build、Python AST 与后端 Node 语法检查通过。构建输出仍有既存 Node 引擎版本和大包提示，未运行测试。

补充：恢复核验仅针对带交互启动意图的真实执行，忽略后续不调用模型的消息处理运行。即使通用运行处理已将任务置为 blocked，若无领域阻塞且旧执行已结束，仍补齐中断说明和停止证明。恢复时同时收敛旧命令，避免旧 running 请求阻挡下一次启动。
