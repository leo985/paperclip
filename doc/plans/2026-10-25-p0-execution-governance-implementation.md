日期：2026-10-25。状态：代码与本机定向验证完成，尚未发布；不将此记录视作 Windows 真机、真实 Claude 费用或生产验收证明。

关联：[按优先级实施记录](2026-10-25-delivery-priority-implementation.md)、[预算设计](2026-10-25-delivery-budget-governance.md)。本批只补 P0 基础，不启用 P1 分析任务或 P2 QA 任务的业务自动执行。

## 1. 受管进程树停止

新版客户端声明 `supervisionProtocol=2`，服务端将“必须有树级停止证明”固化到运行许可。只回报 wrapper/Claude 主进程退出，不足以签发替代许可；许可到期、网络恢复也不会重新启动旧运行。

- macOS/Linux 监督器记录 launcher session，以及交互 PTY 在 exec 之前登记的独立 session 锚点；停止和核验覆盖这些 session 内仍存活的后代进程，包含 launcher 已经退出的情形。发信号前再检查 session 归属，不按命令关键字批量杀进程。
- Windows 使用监督器的非 breakaway Job Object。查询所有成员，只终止该 Job 中的进程；确认 Job 中仅剩监督器后才能给出空树证明。监督器退出时沿用 kill-on-close。此分支已经编码，当前 Mac 上未完成 Windows 真机验收。
- 双次空树观测间隔至少 250ms，并将机器凭据、一次性 lease、公司、Agent 和 run 绑定到停止回执。进程检查失败、仍有存活成员时为 unknown/pending，不伪造停止成功。
- 启动前配置/版本失败也持久化未启动证明；一旦写入 spawn 尝试标记，外层失败处理禁止假报未启动。
- 停止证明只验证本平台监督器管理的 session/Job 边界，不是通用系统沙箱，也不保证能追溯平台之外或故意逃逸受管会话的进程。不清除独立的人工暂停、业务阻塞或原生环境清理保护；恢复仍走现有授权入口。

兼容性：旧客户端不支持新树级证明时保留既有协议，不补造全程受控标记。旧许可的退出规则保留；绑定新领域路由的许可要求新版监督协议，不能通过降级客户端绕过。真实客户端只在空闲后升级。

## 2. 累计用量、差额入账和对账

每 5 秒从本次精确 session UUID 的 Claude JSONL 采集已落盘用量，按 message ID 去重，并纳入该 session 的 subagents。相同消息多块更新取各计数字段的高水位，不读取其他会话。

1. 新累计观测以单调序号写入本机不可变 checkpoint outbox，不覆盖旧文件；来源短暂缺失、损坏或总量下降时不将先前用量归零。
2. `/usage-checkpoint` 校验席位凭据、机器、许可 lease、run、观测时间及累计单调性。即使席位被预算暂停/运行已取消，计量上报仍可继续。
3. `run_usage_checkpoints` 保存高水位与首次许可冻结的工单/项目归属；`run_usage_observations` 保存每个序号的不可变摘要及账本回执，旧序号内容改变同样拒绝。
4. 与最终汇总使用同一运行锁。统一 `cost_events` 只写新增 Token 差额，Agent 累计数同事务更新；重复、并发、正常 final 与延迟 final 不双记。
5. 最终汇总少于已知观测时拒绝，保留对账缺口；没有最终汇总时保留 partial_observation，不把部分记录包装成完整结算。账本事件发生时间保留观测时间，晚到补报不改到当前月。
6. outbox 只有收到明确 ACK 才删除。单轮补传有时间预算和短网络超时，避免积压回执长期阻塞许可续验；看门狗独立于网络线程继续停止受管进程。

本地中转/订阅真实价格不可得时仍是 unknown/unpriced。Token 采集不是实际账单；不启用虚构的费用预留，不承诺零超支。原生费用门禁仍检查所有适用策略；未来分析/QA 的新领域许可会额外拒绝“存在有效费用硬预算但无可靠价格”的自动执行。

## 3. 多 Harness 路由与启动核验

席位负责人或管理员可在“设备与诊断 → 本机 Harness 能力”选择分析、研发、测试各自的路由。同领域仅一个候选自动选中；多个时必须明确选择。接口拒绝其他负责人、跨组织、过期修订、错误领域及执行/等待决策期间改路由，并记录审计。

服务端从已登记能力生成 `HarnessExecutionRoute`，绑定公司、Agent、机器、任务、run、注册修订、capability ID、仓库/profile/commit/文件摘要。许可保存此快照，续验时重核，变化则撤销。

客户端启动前及实际 spawn 边界两次重验服务端快照、本机登记回执以及真实文件/版本。未知领域、错误机器、缺少能力或版本变化时拒绝，不回落到任意目录或“完成工单”的通用提示词。任务描述不能提供任意 shell 或本机路径来改路由。

现有研发启动已接入新路由。旧任务原生状态、素材和模块仍绑定原 Harness，选择另一个研发根目录不能静默迁移旧任务，必须先完成对应接入。路由基础可供分析/QA 的原生执行适配调用；**分析网页任务、分析执行适配串联、QA 原生生命周期属于 P1/P2，尚未因本批路由配置而开放**。登记对象继续保持 executionReady=false，避免把能力发现误写成完整领域已验收。

## 4. 可见性和接口

“执行记录”选中运行后新增“执行治理与用量对账”，展示旧协议/观测模式、停止待核验/已回报树证明、未知/部分/最终用量、未计价以及本次固定路由。使用独立轻量查询，不扩大原运行列表的日志读取量；非席位运行不显示该卡片。

- GET `/api/companies/:companyId/seat-run-control/:runId`：组织隔离的治理摘要，不返回 lease、密钥或会话原文。
- PUT `/api/companies/:companyId/dsp7-seats/:agentId/harness-routing`：负责人/管理员选择已有能力。
- POST `/api/agents/:agentId/dsp7-outbound-runs/:runId/usage-checkpoint`：累计 Token 观测，不授予执行权。
- POST 同 run 的 `/stopped`：兼容子进程退出回执；新版可附受管树证明。
