# 新电脑登录后自动上线

## 实现

- 接入研发电脑默认勾选“登录电脑后自动上线（推荐）”。保持勾选会安装当前用户后台服务、启用登录启动并立即启动；取消勾选生成 `--no-service` / PowerShell `-NoService`，不安装服务，也不停止已有服务。选项变化会清除旧命令，要求重新生成，避免命令与界面不一致。
- 新增只读 `service_status.py`，分别核验 macOS LaunchAgent 的 RunAtLoad、版本路径、disabled override 和运行状态，Windows 当前用户计划任务的启用、登录触发器、执行路径、用户身份和运行状态，以及 Linux systemd 用户服务的启用、版本路径和运行状态。
- 安装后核验结果，启用但暂未运行时最多重试十次，不把子进程返回零直接当成安装成功。升级安装的核验摘要会显示在终端。
- macOS 安装修复 disabled override，确保 RunAtLoad、enable 与 kickstart；kickstart 不使用 -k，不重启已运行的接入桥。Windows 同一登记路径的任务重新设置用户登录触发器和启用状态，不覆盖指向未知版本的任务。Linux 同版本服务可重新 enable --now。
- 利用现有 `checks` 心跳协议上报 `autostart` 诊断，无数据库或服务端协议变更。诊断为提示级，不因系统服务检查未知就误报领域执行配置失败。
- 席位设备与诊断增加专门展示，未上报显示未知；离线明确为最后一次结果，不能证明当前状态。
- 仍保留主动下线标记：`harness offline` 后需 `harness online` 恢复；自动上线不绕过派单权限，不自动恢复业务阻塞。

## 检查与限制

UI 类型检查、生产构建、Token 检查、Python AST 语法及改动空白检查通过。未添加或运行测试，未在三种系统上实际执行安装、注销或重启登录，也未更新本机席位。没有宣称已完成跨平台登录验收。

本次仅发布网页、帮助及客户端下载包，不重启服务器服务。新电脑重新生成命令后接入，已有电脑更新客户端，再到设备与诊断检查上报结果；安装依赖当前用户系统服务权限。详见 `2026-10-24-seat-login-autoonline-release.json`。
